2Initializer & attributes

See Lesson 02 — self and attributes · Lesson 03 — The initializer

Fill in starting state
class Book:
    def __init__(self, title, copies):
        self.title = title      # attribute on the object
        self.copies = copies

dune = Book("Dune", 3)
print(dune.title)               # Dune

3Methods

See Lesson 04 — Methods that do things · Lesson 12 — Instance, class, static

Instance · class · static
class Book:
    def __init__(self, title):
        self.title = title

    def borrow(self):                 # instance: needs self
        return f"Borrowed {self.title}"

    @classmethod
    def from_json(cls, data):         # class: needs cls
        return cls(data["title"])

    @staticmethod
    def is_valid_isbn(code):          # static: needs neither
        return len(code) == 13

4Inheritance (is-a)

See Lesson 07 — Inheritance (is-a)

Child extends parent, calls super()
class Customer:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        return f"I am {self.name}"

class BusinessCustomer(Customer):
    def __init__(self, name, company):
        super().__init__(name)        # run parent's init
        self.company = company

c = BusinessCustomer("Bilal", "ABC Bank")
print(c.introduce())                  # inherited
print(c.company)                      # own

5Composition (has-a)

See Lesson 10 — Composition (has-a)

An object holds another object
class Address:
    def __init__(self, city):
        self.city = city

class Customer:
    def __init__(self, name, address):
        self.name = name
        self.address = address       # has-a

c = Customer("Bilal", Address("Stockholm"))
print(c.address.city)                # Stockholm

6Dunder methods

See Lesson 11 — Dunder methods

Plug into built-in syntax
class Book:
    def __init__(self, title):
        self.title = title

    def __str__(self):                # print(obj)
        return f"Book: {self.title}"

    def __repr__(self):               # repr(obj), debugging
        return f"Book({self.title!r})"

    def __eq__(self, other):          # obj == other
        return self.title == other.title

7Property

See Lesson 06 — Properties

Attribute syntax, real logic underneath
class Account:
    def __init__(self, balance):
        self._balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("cannot be negative")
        self._balance = value

8Dataclass

See Lesson 13 — Dataclasses

Boilerplate-free data class
from dataclasses import dataclass

@dataclass
class Customer:
    name: str
    country: str
    risk_score: int

c = Customer("Bilal", "SE", 85)
print(c)                 # Customer(name='Bilal', ...)

9Abstract base class

See Lesson 09 — Abstraction

Force subclasses to implement
from abc import ABC, abstractmethod

class RiskModel(ABC):
    @abstractmethod
    def calculate(self, customer):
        ...

class KYCModel(RiskModel):
    def calculate(self, customer):
        return customer.risk_score * 1.2

10Choosing between them

See Lesson 14 — Designing a system

You want…Reach for
One thing with data and rulesA class with __init__ + methods
A class that is mostly data@dataclass
"X is a Y"Inheritance
"X has a Y"Composition
Same call, different behaviourPolymorphism (override the method)
Controlled access to a value@property
A guaranteed interfaceABC + @abstractmethod
An alternate constructor@classmethod
The one warning OOP is a tool, not a religion. Not every noun needs a class, and unnecessary abstraction is a real failure mode. If a plain dictionary or function does the job clearly, use it.
