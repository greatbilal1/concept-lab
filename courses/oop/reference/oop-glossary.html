OOP Glossary

The vocabulary of object-oriented Python, in one place. Every lesson in this workspace uses these exact terms — if a lesson uses a word, it is defined here.

Core Methods Relationships Tools

ACore concepts

Object
A bundle of state (data it remembers) and behaviour (operations it can perform). The fundamental unit of OOP. See Lesson 01
Class
The blueprint that describes what every object of a kind will have. Written with class Name:. One class can build many objects. See Lesson 01
Instance
Another word for an object built from a class. "Instance of Book" means "an object created by Book(...)". See Lesson 01
State
The data an object remembers — its attributes. A book's title, author, copies. See Lesson 02
Behaviour
The operations an object can perform — its methods. A book's borrow(), restock(). See Lesson 04
Attribute
A piece of data stored on an object, reached with dot syntax: book.title. Set inside methods as self.title = …. See Lesson 02
self
The particular object a method was called on. Always the first parameter of an instance method. It is how a method reaches its own data. See Lesson 02
Constructor / initializer
__init__ — runs automatically when an object is created, and fills in its starting state. It initializes an already-created object; it is not the creation mechanism itself. See Lesson 03

BKinds of method

Instance method
Receives self first. Works with one particular object's state. def borrow(self): See Lesson 04
Class method
Decorated @classmethod, receives the class as cls. Used for alternate constructors, e.g. Book.from_json(data). See Lesson 12
Static method
Decorated @staticmethod. Needs neither the object nor the class — a utility logically grouped with the class. See Lesson 12
Property
Decorated @property. Exposes method-backed logic as if it were a plain attribute, so you get clean syntax with validation underneath. See Lesson 06
Dunder method
A method with double underscores on both sides (__str__, __len__, __eq__). Lets your objects plug into Python's built-in syntax. See Lesson 11

CRelationships between classes

Inheritance
A child class gets everything the parent has, then adds or overrides its own parts. Models an is-a relationship: class BusinessCustomer(Customer): See Lesson 07
Composition
An object contains another object. Models a has-a relationship: a Customer has an Address. Often more flexible than inheritance. See Lesson 10
Polymorphism
One call, many behaviours — each object decides how it responds to the same message. for c in customers: c.risk_type() See Lesson 08
Encapsulation
Keeping state and the rules that change it together, so callers cannot bypass the rules. In Python this is a convention, not enforcement. See Lesson 05
Abstraction
Exposing a simple interface while hiding the messy details behind it. Callers depend on what it does, not how. See Lesson 09
Duck typing
Python often cares less about an object's class and more about whether it supports the operation you need. "If it walks like a duck…" See Lesson 08

DTools & conventions

super()
Calls behaviour from the parent class — most often super().__init__(…) inside a child's initializer. See Lesson 07
@dataclass
Writes the boring __init__, __repr__ and equality methods for a data-focused class, so you only declare the fields. See Lesson 13
ABC / @abstractmethod
Defines an interface that cannot be instantiated directly and forces subclasses to implement the marked methods. See Lesson 09
_name (single underscore)
A convention meaning "internal — do not touch from outside". Python does not enforce it. See Lesson 05
__name (double underscore)
Triggers name mangling: __balance becomes _ClassName__balance. Used to avoid accidental clashes in subclasses. See Lesson 05
