# Mission: Object-Oriented Programming in Python

## Why
I want to build a real Python project — an app, CLI, or library — and I want the
code to stay understandable as it grows. Right now I can write scripts, but as
soon as a program gets bigger than a few hundred lines it turns into a tangle
where changing one thing breaks three others. OOP is the tool that lets me draw
boundaries: each part of the system gets a clear job and a clear place to live.

## Success looks like
- I can look at a problem and name the objects, their data, and their
  responsibilities before writing any code.
- I can write a class with `__init__`, attributes, and methods without
  second-guessing where `self` goes.
- I can choose between inheritance and composition deliberately, and explain why.
- I can read a real Python library's source and follow what its classes are doing.
- I can ship a small project where the classes are clean enough that a teammate
  could add a feature without asking me how it works.

## Constraints
- Learning in short sessions; each lesson must be completable in one sitting.
- Prefer Python (the language I actually use), not a toy language.
- No build step, no accounts, no dependencies — everything runs offline from
  `file://` in the browser, matching the rest of this workspace.
- I want to *do* things, not just read. Every lesson should end with something
  I have built or run.

## Out of scope
- Advanced design patterns (GoF catalogue) — later, once the fundamentals are solid.
- Metaclasses, descriptors, and other deep-magic Python internals.
- Other languages' OOP (Java, C++) — Python only for now.
- Frameworks (Django, SQLAlchemy) — I want the language, not a framework tour.
