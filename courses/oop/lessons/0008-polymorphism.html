Polymorphism

Polymorphism means one call, many behaviours. You write item.describe() once, and each object answers in its own way. It is the payoff of inheritance — and the reason you can add new types without touching old code.

Time ~10 min Win Write code that works for types you have not written yet Mission link Extend without editing

1The if-chain that keeps growing

Without polymorphism you end up branching on type everywhere. 

def describe(item):
    if isinstance(item, Book):
        return f"{item.title} ({item.copies} copies)"
    elif isinstance(item, Ebook):
        return f"{item.title} ({item.size_mb} MB)"
    elif isinstance(item, Audiobook):
        return f"{item.title} ({item.minutes} min)"

Every new type means editing this function. And every other function that branches on type. That is a lot of places to remember.

The failure Type checks spread through the program. Adding a type means finding and editing every branch — and missing one is easy.

2Let each object answer

Give every class its own describe. Now the caller does not care what the object is. 

class Book:
    def describe(self):
        return f"{self.title} ({self.copies} copies)"

class Ebook(Book):
    def describe(self):
        return f"{self.title} ({self.size_mb} MB)"

for item in shelf:
    print(item.describe())     # one call, many behaviours
Key idea The caller writes one call. Each object decides how to answer. Adding a new type means adding a class — no existing code changes.

3Duck typing

Python does not check the type. It only checks that the object has the method you called. "If it walks like a duck and quacks like a duck…" 

class Podcast:                 # not a Book at all
    def describe(self):
        return f"{self.name} (podcast)"

for item in shelf:
    print(item.describe())     # Podcast works too
Why this is powerful Any object with a describe method works — no shared parent required. This is why Python code stays flexible as it grows.

✓ Your win for today

You can now replace type-checking if-chains with a single polymorphic call, and you know that Python's duck typing means any object with the right method will work. Your code can now grow without being edited.

5Do this next

  1. Give Book and Ebook each a describe method, then loop over a mixed list calling it.
  2. Add a Podcast class that is not a Book but has describe. Confirm it works in the same loop.
  3. Rewrite an isinstance if-chain in your own code as a polymorphic method call.
