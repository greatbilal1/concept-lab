Composition (has-a)

Composition means building objects out of other objects. A Library has books. It is usually the better choice than inheritance — more flexible, easier to change, and it matches how the real world is actually structured.

Time ~10 min Win Build complex objects from simple ones Mission link Systems assembled from parts

1Inheritance is not always the answer

You need a Library that holds books. The tempting move is to inherit from Book — but a library is not a book. 

class Library(Book):        # Library IS-A Book? No.
    ...

This gives Library a title and copies it has no business having. The is-a test fails, so inheritance is wrong here.

The failure Inheriting for the wrong reason drags in attributes and methods that do not belong. The class becomes confusing and hard to change.

2Hold the parts instead

A library has a list of books. Store them as an attribute and delegate the work. 

class Library:
    def __init__(self, name):
        self.name = name
        self.books = []            # HAS-A list of books

    def add(self, book):
        self.books.append(book)

    def available(self):
        return [b for b in self.books if b.copies > 0]
Key idea Composition says "has-a". The library owns its books and uses their behaviour — without pretending to be one.

3Delegation

The outer object does not reimplement the inner object's behaviour. It delegates — passes the call through. 

class Library:
    def borrow(self, title):
        for book in self.books:
            if book.title == title:
                return book.borrow()      # delegate to the book
        return False
Why this is better The rule about borrowing lives in Book, in one place. The library just routes the request. Change the rule once and every library obeys.

You can now tell has-a from is-a, build objects out of other objects, and delegate behaviour instead of duplicating it. Composition is the tool you will reach for most often in real designs.
