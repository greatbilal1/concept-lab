Lesson 06 · Protecting state

Properties

A property lets an attribute look like plain data while actually running code. You get the safety of a method with the clean syntax of book.copies.

Time ~10 min Win Add validation without changing the syntax Mission link Clean call sites, safe internals

1Methods are safe but noisy

In the last lesson we protected copies behind methods. Safe — but the call sites got uglier. 

book.get_copies()      # a method call
book.set_copies(5)     # another method call

A property gives you the same protection with the syntax you already wanted. 

book.copies            # reads like data
book.copies = 5        # writes like data
Key idea A property is a method wearing an attribute's clothes. The caller sees data; the class runs code.

2The @property decorator

Decorate a method with @property and it becomes readable as an attribute. Add a matching setter to make it writable. 

class Book:
    def __init__(self, title, copies):
        self.title = title
        self.copies = copies          # goes through the setter

    @property
    def copies(self):
        return self._copies

    @copies.setter
    def copies(self, value):
        if value < 0:
            raise ValueError("copies cannot be negative")
        self._copies = value
Why this is elegant The rule lives in one place, but callers write book.copies = 5 as if it were a plain attribute. You can add validation later without changing a single call site.

3Read-only and computed properties

A property with no setter is read-only. A property can also compute a value on the fly instead of storing it. 

class Book:
    @property
    def is_available(self):           # computed, read-only
        return self._copies > 0

book.is_available    # True — no parentheses, no stored field
Watch out A property should be cheap and side-effect free. If reading it does heavy work or changes state, make it a normal method instead — the name should tell the truth.
