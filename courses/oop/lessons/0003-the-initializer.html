The initializer

__init__ runs automatically the moment you build an object. It is where an object gets its starting state — and where you can refuse to build a broken one.

Time ~10 min Win Set up objects correctly every time Mission link Objects that start in a valid state

1It runs by itself

You never call __init__ directly. Python calls it for you when you write Book(...). 

class Book:
    def __init__(self, title, copies):
        print("building a book")
        self.title = title
        self.copies = copies

dune = Book("Dune", 3)   # prints: building a book

The arguments you pass to Book(...) are handed straight to __init__, after the automatic self.

Key idea __init__ is the setup step. Its job is to leave the object in a valid, ready-to-use state. If it finishes, the object exists.

2Default values

Not every argument has to be required. Give a parameter a default and callers can skip it. 

class Book:
    def __init__(self, title, copies=1):
        self.title = title
        self.copies = copies

a = Book("Dune")          # copies defaults to 1
b = Book("Dune", 5)       # copies is 5
The mutable default trap Never use a mutable default like tags=[]. That one list is created once and shared by every object. Use tags=None and create the list inside __init__ instead.

3Guarding the start

Because __init__ is the only way in, it is the perfect place to reject bad data before the object ever exists. 

class Book:
    def __init__(self, title, copies):
        if copies < 0:
            raise ValueError("copies cannot be negative")
        self.title = title
        self.copies = copies

Book("Dune", -1)   # ValueError — no broken object is ever made
Why this matters If an object can only be built through __init__, and __init__ checks its inputs, then every object in your program is guaranteed valid. That is a huge amount of safety for four lines.
