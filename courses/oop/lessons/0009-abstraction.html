Abstraction

Abstraction is deciding what a class promises and hiding how it keeps that promise. An abstract base class lets you write down the promise once, and forces every subclass to keep it.

Time ~10 min Win Define a contract subclasses must honour Mission link Interfaces that stay consistent

1The promise nobody wrote down

In the last lesson, polymorphism worked because every object had a describe method. But nothing enforced that. Forget it and you find out at runtime. 

class Podcast:
    def summary(self):        # oops — wrong name
        return "..."

for item in shelf:
    print(item.describe())    # AttributeError, deep in a loop
The failure The contract was only in your head. Nothing told you that every item needs describe until the program crashed.

2Write the contract down

An abstract base class declares the methods every subclass must provide. You cannot build the base itself — only its concrete children. 

from abc import ABC, abstractmethod

class ShelfItem(ABC):
    @abstractmethod
    def describe(self):
        """Return a one-line description."""
Key idea The abstract class is a contract. It says "any ShelfItem can describe itself" without saying how. Subclasses must supply the how.

3Fulfilling the contract

Subclass the abstract class and implement every abstract method. Miss one and Python refuses to build the object — at the earliest possible moment. 

class Book(ShelfItem):
    def __init__(self, title, copies):
        self.title = title
        self.copies = copies

    def describe(self):                 # fulfils the contract
        return f"{self.title} ({self.copies} copies)"

ShelfItem()      # TypeError — cannot build an abstract class
Book("Dune", 3)  # fine
Why this is better The error moves from "deep in a loop at runtime" to "the moment you try to build a broken class". That is the whole value of abstraction: fail early, fail clearly.
