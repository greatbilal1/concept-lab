Lesson 07 · Relationships

Inheritance (is-a)

Inheritance lets one class build on another. Use it when the relationship is genuinely is-a: an Ebook is a Book. Get that test wrong and inheritance becomes a trap.

Time ~10 min Win Share behaviour without copying code Mission link Reuse without duplication

1Copying code is the smell

You have a Book. Now you need an Ebook that is almost the same but has a file size. The tempting move is to copy the whole class. 

class Ebook:
    def __init__(self, title, copies, size_mb):
        self.title = title
        self.copies = copies
        self.size_mb = size_mb

    def borrow(self):        # copied from Book
        ...

Now every fix to Book.borrow has to be made twice. That is the problem inheritance solves.

The failure Duplicated behaviour drifts. Two copies of the same rule will eventually disagree, and you will not know which one is right.

2Inherit and extend

Put the shared class in parentheses. The child gets everything the parent has, and adds or overrides what it needs. 

class Book:
    def __init__(self, title, copies):
        self.title = title
        self.copies = copies

    def borrow(self):
        if self.copies == 0:
            return False
        self.copies -= 1
        return True


class Ebook(Book):                       # Ebook IS-A Book
    def __init__(self, title, copies, size_mb):
        super().__init__(title, copies)  # run the parent setup
        self.size_mb = size_mb
Key idea super() calls the parent's version. The child reuses the parent's setup and behaviour, then adds its own.

3The is-a test

Before you inherit, say the sentence out loud. If it sounds wrong, do not inherit.

SentenceVerdict
An Ebook is a Book✓ Inherit
A Library is a Book✗ A library has books — use composition
A Customer is a Book✗ Unrelated — do not inherit
Deep hierarchies are a trap Three or four levels of inheritance become hard to follow. Prefer shallow trees, and reach for composition (next lessons) when the relationship is "has-a".

4Check yourself

Answer from memory. Every option has the same number of words.

✓ Your win for today

You can now share behaviour between classes without copying it, call the parent setup with super(), and — most importantly — apply the is-a test before inheriting. That test will save you from most bad class designs.

5Do this next

  1. Create an Ebook(Book) that adds size_mb and calls super().__init__.
  2. Override borrow in Ebook so it also prints the file size, then call super().borrow() inside it.
  3. Write three candidate classes and apply the is-a test to each. Note which ones should use composition instead.
