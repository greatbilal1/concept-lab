Methods that do things

A method is a function that belongs to an object. The good ones do one clear thing, change state only when they should, and return something useful. This lesson is about writing methods you would be happy to read again.

Time ~10 min Win Write clear, single-purpose methods Mission link Behaviour that reads like intent

1Methods change state or answer questions

Most methods fall into two groups. Naming them well makes code read like a sentence.

KindDoes whatExample
CommandChanges stateborrow(), restock(n)
QueryReturns informationis_available(), describe()
class Book:
    def __init__(self, title, copies):
        self.title = title
        self.copies = copies

    def borrow(self):                 # command
        if self.copies == 0:
            return False
        self.copies -= 1
        return True

    def is_available(self):           # query
        return self.copies > 0
Key idea A command changes the object; a query reports on it. Keeping them separate makes behaviour predictable and easy to test.

2One method, one job

A method that does five things is five methods wearing a trench coat. Split it. 

# hard to read
def process(self):
    self.copies -= 1
    self.last_borrowed = today()
    send_email(self.owner)
    log(f"{self.title} borrowed")

# easier to read
def borrow(self):
    self.copies -= 1
    self.last_borrowed = today()

def notify_owner(self):
    send_email(self.owner)
Why this helps Short methods are easier to name, easier to test, and easier to reuse. When a method is hard to name, that is usually a sign it is doing too much.

3Returning useful values

A method should return something the caller can act on. Returning True/False lets callers branch without inspecting internals. 

if book.borrow():
    print("Enjoy your book")
else:
    print("Sorry, none left")
Avoid Methods that both change state and print. Printing is a side effect the caller cannot control. Return a value; let the caller decide what to do with it.

✓ Your win for today

You can now tell a command from a query, split a bloated method into clear pieces, and return values instead of printing. Your objects now have behaviour that reads like intent.
