# Mission established: build a real Python project

The user's reason for learning OOP is to **build a real Python project** (app, CLI,
or library) whose code stays readable as it grows — not to pass an exam or learn OOP
for its own sake. This grounds every lesson in *shipping maintainable code*, so
examples should move toward a real project's domain rather than staying on generic
`Customer`/`BankAccount` toys.

## Implications
- Lessons should end with something **built or run**, not just read.
- Prefer Python-only, offline, no-dependency examples (matches the workspace).
- Once the user names their actual project, switch lesson examples to that domain.
- Out of scope for now: design patterns, metaclasses, other languages, frameworks.

## Evidence
Stated directly by the user when asked about the mission at the start of the
workspace. The user also chose to **keep the existing course page** and start
**from the very beginning** (what an object is).
