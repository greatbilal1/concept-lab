Lesson 06 · CQRS & Event Sourcing

Event Sourcing and immutable logs

Don't store the current state; store the events that led to it. Discover Event Sourcing: how accounting ledgers, git commits, and append-only event logs provide complete auditability.

Time ~10 min Win Design Event-Sourced systems using append-only immutable event streams and snapshots Mission link The architectural pattern that provides perfect auditability and temporal queries

1The ledger of facts

In a traditional CRUD database, when a user changes their address, you run UPDATE users SET address = 'Paris'. The past is erased: you no longer know they lived in London, when they moved, or why.

Accountants never erase the past: they use double-entry ledgers. Event Sourcing applies this to software: you never update or delete state; you append immutable events to an event stream: UserRegistered → AddressChanged → PlanUpgraded. The current state is simply computed by replaying all historical events from the beginning of time!

Key idea Event Sourcing stores state as an append-only stream of immutable past events.
