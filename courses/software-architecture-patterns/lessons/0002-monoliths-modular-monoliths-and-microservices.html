Lesson 02 · Macro Architecture & Monoliths

Monoliths, modular monoliths, and microservices

Microservices aren't free: you trade code complexity for operational complexity. Compare traditional Monoliths, Modular Monoliths, and Microservices across real engineering trade-offs.

Time ~10 min Win Evaluate Monoliths, Modular Monoliths, and Microservices based on team size and operational scale Mission link The central macro-architectural debate in modern enterprise systems

1The distributed trade-off

A Monolith packages all features into a single deployment unit sharing a single database. It is easy to develop, easy to test, and deploys as one binary. But as teams grow to 100+ engineers, coordinating releases and scaling independent hot spots becomes challenging.

Microservices split features into independently deployable network services. This buys independent scaling and team autonomy, but you pay a massive tax: network latency, distributed data consistency, partial failure modes, and DevOps complexity. A Modular Monolith offers a sweet spot: strict internal module boundaries inside a single deployable artifact!

Key idea Microservices trade in-process code complexity for distributed operational complexity.
