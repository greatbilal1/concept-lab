Lesson 03 · Event-Driven Architecture

Event-driven architecture and message brokers

Stop chaining synchronous HTTP calls. Discover Event-Driven Architecture (EDA): domain events, asynchronous decoupling, and message brokers like Kafka and RabbitMQ.

Time ~10 min Win Design asynchronous event-driven architectures using domain events and message queues Mission link Eliminates cascading synchronous HTTP outages across distributed systems

1The synchronous HTTP chain of death

In a naive distributed system, a checkout request triggers a chain of synchronous HTTP calls: OrderService → HTTP → PaymentService → HTTP → InventoryService → HTTP → EmailService. What happens if the EmailService has a 5-second network timeout?

The entire checkout request hangs, times out, and fails! The availability of the chain is the product of the availability of every service: if each service is 99% reliable, a 5-service chain is only 95% reliable! Event-Driven Architecture (EDA) decouples this: OrderService publishes an OrderPlaced event to a message broker and responds in 5ms. Other services consume the event asynchronously at their own pace.

Key idea Asynchronous events decouple services in time: producers fire and forget; consumers process at their own pace.
