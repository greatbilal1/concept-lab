Repository Maps and Architecture Guides

Creating concise repository maps and architecture overviews that orient agents in seconds.

Time ~10 min Win You know how to create concise repository maps that orient AI agents immediately. Mission link Mastering repository maps and architecture guides across modern software engineering

1Core principles of Repository Maps and Architecture Guides

When an agent enters a 200,000-line repository, it is blind. It does not know that `apps/web` is the Next.js frontend, `packages/core` is the business logic, and `services/worker` is the Celery background queue. Without a map, it must guess.

Key idea Creating concise repository maps and architecture overviews that orient agents in seconds.

2The Power of a Repository Map

A Repository Map (often documented in `ARCHITECTURE.md` or embedded in instruction files) provides an immediate mental model:

3Dependency Direction Invariants

# ARCHITECTURE.md: Repository Map
## Directory Layout & Responsibilities
- `src/api/`        -> FastAPI HTTP endpoints and routing.
- `src/domain/`     -> Pure business entities and business rules (zero I/O!).
- `src/storage/`    -> Database models, migrations, and repository implementations.
- `src/workers/`    -> Celery tasks and event consumers.
- `tests/`          -> pytest test suite (mirrors `src/` layout).

## Dependency Invariants
- `domain/` must NEVER import from `api/` or `storage/`.
- `api/` calls `domain/` and `storage/` through dependency injection.

This 15-line map saves thousands of tokens of blind directory listing tool calls and stops the agent from violating architectural boundaries.

Boundary Defense: Explicitly stating dependency directions (e.g. 'Domain never imports Storage') keeps your architectural layers pure.
