Lesson 06 · Space & trade-offs

Space and trade-offs

Every lesson so far has counted time. But algorithms also consume memory, and the two costs are often linked: you can spend space to buy time, or spend time to save space. This lesson is about that bargain.

Time ~12 min Win Spot a time-for-space trade-off Mission link Cost has two axes, not one

1The cost you forgot to count

Big O applies to memory exactly as it applies to time. If an algorithm stores one extra value per input item, its space is $O(n)$. If it stores a fixed number of variables no matter how big the input is, its space is $O(1)$.

Here is the subtle part: a loop that scans a list uses $O(1)$ extra space, because it only needs a cursor and a running total. But a function that builds a new list of the same size uses $O(n)$ extra space. Same time class, very different space class.

2Buying time with space

The most common trade-off in all of computing: remember an answer instead of recomputing it. Storing results in a table so you can look them up later is called memoisation, and it is the classic space-for-time bargain.

The naive way to compute Fibonacci numbers recurses on both $n-1$ and $n-2$, which is exponential — $O(2^n)$. But the same computation repeats the same subproblems over and over. Store each answer once and the time collapses to $O(n)$, at the cost of an $O(n)$ table.

Key idea Space and time are two axes of the same cost. Memoisation trades memory for speed; streaming trades speed for memory. Neither is free.

3Watch the trade happen

Step through the two versions of Fibonacci below. The naive version recomputes the same values again and again; the memoised version computes each value once and reads it back. Watch the calls counter.

For $n = 5$, the naive version makes 15 calls and the memoised version makes 5. The gap widens fast: at $n = 30$ the naive version makes over a million calls while the memoised version makes 30. That is the exponential-to-linear collapse, bought with a table.

✓ Your win for today

You can look at an algorithm and state both its time and its space complexity, and you can name the trade-off when one is bought with the other. Cost is a pair, not a single number.

5Do this next

  1. Take a function that reverses a list. Write one version that builds a new list and one that swaps in place. State the space class of each.
  2. Explain in one sentence why a lookup table can turn an $O(n)$ search into an $O(1)$ lookup — and what it costs you.
  3. Think of a case where saving memory matters more than saving time (a huge file, a small device). This sets up Lesson 08.
