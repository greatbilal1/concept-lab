Lesson 08 · Putting it together

Choosing between two solutions

This is the lesson the whole course was building toward. You can now count work, read notation, drop constants, name classes, weigh space and separate the cases. Here is how to use all of it to actually pick a solution.

Time ~12 min Win Justify a choice with Big O Mission link The judgement the course exists to give you

1The question is never "which is faster?"

You are asked to pick between two solutions. The naive question is "which one is faster?" — and it is the wrong question, because the answer depends on the input size, the memory budget, and which case you care about.

The right question has three parts: how big does the input get, how much memory can I spend, and which case must I guarantee. Answer those three and the choice usually makes itself.

2A worked decision

Suppose you need to check whether a value appears in a collection, and you get to choose the data structure. Two candidates:

  • A list: linear search, $O(n)$ time, $O(1)$ extra space.
  • A hash set: membership test, $O(1)$ time, $O(n)$ extra space.

The hash set wins on time and loses on space. Which is right? It depends on the three questions. If you look up many times and memory is plentiful, the hash set pays for itself immediately. If you look up once and memory is tight, the list is the better answer.

Key idea There is no "best" solution in the abstract. There is only the best solution for a stated input size, memory budget and case. Big O is how you make that statement precise.

5Do this next

  1. Take two ways to find duplicates in a list — nested loops versus a hash set — and write one sentence justifying each for a different input size.
  2. Pick a real function in a project you have written and state its time and space complexity. Then decide whether it is the right choice.
  3. Write a short paragraph choosing between two solutions, naming the input size, the memory budget and the case you are guaranteeing. That paragraph is the deliverable of this whole course.
