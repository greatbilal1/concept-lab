Counting the work

You already know how to write a loop. This lesson is about a different question: when the input gets bigger, how much more work does the loop do? That question is the whole of Big O, and it starts with counting.

Time ~10 min Win Count the steps in a loop by hand Mission link The raw material every later lesson measures

1Two ways to find a name

Imagine a list of names on a piece of paper, and you want to know whether "Ada" is on it. You have two honest strategies.

Strategy A: start at the top and read every name until you find Ada or run out of paper. Strategy B: the list is sorted, so open it in the middle, decide whether Ada is above or below, and throw away half the list. Repeat.

Both strategies are correct. Both eventually give the same answer. So why does anyone care which one you pick? Because of what happens when the list grows.

2Count the steps, not the seconds

Here is the move that makes this whole subject work. Instead of timing a program, count the operations it performs as a function of the input size. Call the input size $n$ — the number of names on the paper.

Strategy A, written as a loop:

for name in names:        # runs once per name
    if name == "Ada":     # one comparison per name
        return True
return False

If there are $n$ names, the loop body runs at most $n$ times. So the work is proportional to $n$. Double the list, double the work. That is a straight line, and it has a name you will meet in Lesson 03: $O(n)$.

Key idea Big O is not about how fast your computer is. It is about how the work grows when the input grows. Counting steps is how you find out.

3Watch the count grow

Strategy B is harder to count, because it does not touch every name. Each step throws away half of what is left. Start with 8 names: after one step there are 4, then 2, then 1. Three steps, not eight.

Step through it below. Watch the remaining count fall while the steps count creeps up — and notice that the steps grow far more slowly than the list does.

For 8 names, Strategy A needs up to 8 comparisons and Strategy B needs 3. For 1,000 names, A needs up to 1,000 and B needs about 10. The gap is not a constant factor — it widens as the input grows. That is the difference Big O is built to describe.

✓ Your win for today

You can look at a simple loop and say what its work is proportional to. That is the skill the rest of this course sharpens: not "is this fast?", but "how does this grow?".

5Do this next

  1. Write a loop that prints every pair of names in a list of $n$ names. Count how many times the inner line runs. (You should get $n^2$.)
  2. Count the steps in a loop that runs from 1 to $n$ but only does work when the index is even. Is the count still proportional to $n$?
  3. Take the two name-search strategies and predict the counts for a list of 16 names before you check. Then check.
Primary source Read _Introduction to Algorithms_ by Cormen, Leiserson, Rivest & Stein, Chapter 2 ("Getting Started"). It introduces the counting discipline this lesson uses, and its insertion-sort analysis is the canonical first example.
