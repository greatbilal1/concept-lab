Lesson 06 · Observation Tools

Using breakpoints and inspectors

Stop littering print statements everywhere. Interactive debuggers allow you to pause execution, inspect variable scopes, and step through code instruction by instruction.

Time ~10 min Win Set breakpoints and evaluate variables interactively without editing source code Mission link Provides real-time visibility into internal program state

1The power of interactive inspection

Print statements have three major drawbacks: they require modifying code, they cannot be queried interactively, and they only reveal what you anticipated printing. A debugger pauses execution right before the critical moment.

Once paused at a breakpoint, you have an active REPL. You can inspect any variable in scope, call methods, evaluate expressions, and step through the logic line by line.

Key idea A breakpoint transforms a passive crash into an active, exploratory scientific laboratory.

2Debugger navigation controls

Master the four essential navigation primitives: step over (execute current line), step into (dive into function call), step out (finish current function), and continue (run until next breakpoint).

3Stepping through a calculation

Trace how a debugger moves step-by-step through a loop, letting you verify variables at each iteration.

4Practice

Review standard debugger navigation commands.

✓ Your win for today

You can navigate execution state using breakpoints and stepping commands without modifying a single line of production code.

5Do this next

  1. Set a breakpoint in your code using your IDE or built-in debugger.
  2. Step through 5 lines of execution while evaluating local variables in the debugger console.
  3. Use 'step into' and 'step out' to inspect a helper function.
