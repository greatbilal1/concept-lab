Lesson 08 · Root Cause & Prevention

Fixing the cause, not the symptom

A good fix solves the defect at its origin, adds a regression test to keep it solved forever, and asks what architectural flaw allowed it to exist.

Time ~10 min Win Implement durable root-cause fixes accompanied by automated regression tests Mission link Completes the debugging lifecycle with permanent prevention

1The difference between masking and fixing

When an index is out of bounds, wrapping the line in a try...except IndexError: pass block is not a fix — it is a mask. The program continues running, but in an invalid, infected state that will corrupt data downstream.

A genuine fix addresses the original calculation that generated the invalid index, and ensures that invalid inputs are rejected or handled cleanly at the system boundary.

Key idea Never catch an exception merely to silence it; cure the condition that originated the error.

2The prevention workflow

A complete bug fix follows four mandatory steps: write a failing regression test, apply the minimal root-cause fix, verify the test passes, and assess the codebase for identical patterns.

3A verified regression test

Observe how encoding the bug reproduction into an automated test ensures the bug can never return unnoticed.

4Practice

Confirm the steps of permanent defect remediation.

✓ Your win for today

You can resolve defects at their root cause and lock in the fix with permanent automated regression tests.

5Do this next

  1. Convert an old bug fix into a permanent automated regression test in your test suite.
  2. Search your codebase for catch blocks that silently swallow exceptions.
  3. Conduct a mini post-mortem on your most recent production issue.
