Scoping Tool Permissions: Read-Only Databases and Parameter Allow-Lists

Restricting tool capabilities: dedicated read-only database roles, row/column masking, and strict parameter allow-lists.

1Core principles of Scoping Tool Permissions: Read-Only Databases and Parameter Allow-Lists

Prompt instructions like: 'Please only query data and do not delete anything' are suggestions, not security controls. If an agent is hijacked via prompt injection, it will gladly run DROP TABLE customers;. Security must be enforced at the resource permission level.

Key idea Restricting tool capabilities: dedicated read-only database roles, row/column masking, and strict parameter allow-lists.

2Database Permission Hardening

Three Principles of Tool Permission Scoping:

3Column Masking via Views

  • 1. Dedicated Read-Only Database Accounts: Connect the agent using a PostgreSQL user with permissions restricted strictly to `SELECT`. Even if an attacker executes SQL injection inside the tool, Postgres blocks the mutation!
  • 2. Column & Table View Masking: Never let an agent query the raw `users` table directly. Create a dedicated SQL View (`v_support_customers`) that completely omits sensitive columns like `password_hash`, `ssn`, and `credit_card_token`!
  • 3. Parameter Allow-Lists & Enums: Do not allow an agent to pass arbitrary string table names. Restrict parameters to explicit enums: `Literal["public_faqs", "order_status"]`.
  • 4. Maximum Row Limits (LIMIT 50): Hardcode a strict `LIMIT 50` into the backend tool query to prevent prompt injections from dumping the entire database in one call.
# Creating an Agent-Safe Read-Only PostgreSQL User (SQL):
-- 1. Create dedicated agent user
CREATE USER ai_query_agent WITH PASSWORD 'strong_random_password';

-- 2. Grant CONNECT but ZERO write privileges
GRANT CONNECT ON DATABASE production TO ai_query_agent;
GRANT USAGE ON SCHEMA public TO ai_query_agent;

-- 3. Grant SELECT strictly on safe sanitized views (NO passwords or PII!)
GRANT SELECT ON v_sanitized_customer_orders TO ai_query_agent;
-- Attempts to execute DROP, INSERT, or UPDATE will fail with SQL error: Permission Denied!

The View Masking Rule: If an agent does not need to see a column to do its job, that column must not exist in its database view. Mask PII and secrets at the database engine.
