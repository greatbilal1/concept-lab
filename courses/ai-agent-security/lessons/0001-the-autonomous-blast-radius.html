1Core principles of The Autonomous Blast Radius: When Models Can Execute Actions

A hallucinating chatbot generates a false paragraph: the user is annoyed, but nothing in the real world changes. But when you give that same model access to an `execute_sql_query`, `send_email`, or `deploy_code` tool, a hallucination or prompt injection becomes a catastrophic real-world action.

3Limiting Blast Radius by Design

  • 1. Data Destruction & Mutation: An agent with write access to databases or files can delete production records (`DROP TABLE`), overwrite master branches, or corrupt financial balances.
  • 2. Financial & Resource Depletion: An agent with access to cloud provisioning tools (AWS, GCP) can spin up 100 expensive GPU instances, incurring tens of thousands of dollars in debt.
  • 3. Unauthorized Data Exfiltration: An agent reading confidential emails can use its web browsing or messaging tools to broadcast customer PII to external attacker servers.
  • 4. Legal & Reputational Liability: Sending unauthorized binding contracts or defamatory emails on behalf of the company.
# The Blast Radius Equation:
# Blast Radius = (Tool Capabilities) x (Data Access Scope) x (Autonomous Turn Count)
#
# Unconstrained Agent (Catastrophic Risk):
# - Tools: [bash_terminal, execute_sql, send_email, write_file]
# - Permissions: Admin / root
# - Result: One prompt injection wipes out the company database!
#
# Bounded Agent (Secure Architecture):
# - Tools: [read_file, run_tests]
# - Permissions: Non-root container, read-only database, no internet egress
# - Result: Zero real-world damage even if hijacked!

The Blast Radius Rule: Assume every agent will eventually be compromised by prompt injection. Limit its tools and permissions so that a complete compromise causes near-zero damage.
