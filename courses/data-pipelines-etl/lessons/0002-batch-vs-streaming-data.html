Batch vs Streaming: Latency & Boundaries

Not every pipeline needs to be real-time. Understand the latency, throughput, cost, and complexity trade-offs between batch and streaming.

Time ~10 min Win Choose appropriately between batch, micro-batch, and real-time streaming architectures Mission link Prevent over-engineering high-cost streaming solutions when batch meets business SLAs

1Bounded vs Unbounded data

All data pipelines process one of two fundamental data types:

  • Bounded Data (Batch): A finite dataset with an explicit beginning and end (e.g. all transactions from yesterday, a 10GB log file). Processed in chunks with high throughput.
  • Unbounded Data (Streaming): An infinite, continuously arriving stream of events with no end (e.g. sensor readings, credit card transactions). Processed event-by-event or in micro-batches with low latency.
Key idea Batch processes bounded chunks with high throughput; streaming processes unbounded events with low latency.

2The cost and complexity curve

Real-time streaming sounds attractive, but latency has an exponential cost curve. Moving from 24-hour batch to 1-hour micro-batch is relatively simple. Moving to sub-second real-time streaming introduces out-of-order events, late-arriving data, stateful watermarking, and complex distributed debugging.
