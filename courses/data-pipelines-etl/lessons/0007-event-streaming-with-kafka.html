Lesson 07 · Streaming, Quality & Idempotency

Event Streaming & Message Brokers with Kafka

Traditional databases struggle with millions of events per second. Apache Kafka uses distributed append-only commit logs to stream data at massive scale.

Time ~10 min Win Explain Kafka's partitioned commit log architecture, consumer offsets, and consumer groups Mission link Decouple microservices and process high-throughput event streams in real time

1The distributed commit log

Traditional message queues (RabbitMQ) delete messages once acknowledged by a consumer. This means you cannot replay history or add a new analytics consumer next month.

Apache Kafka is an append-only distributed commit log. Events are permanently written to disk in sequence and retained for days or years. Multiple independent consumers can read the log at their own pace, seeking backward or forward by tracking their offset.

Key idea Kafka stores events in an append-only commit log on disk; messages are not deleted when consumed.

2Topics, Partitions, and Consumer Groups

To achieve horizontal scalability, Kafka structures data cleanly:

  • Topic: A category or stream name (e.g. user-clicks).
  • Partition: A topic is divided into multiple ordered partitions distributed across cluster broker nodes. Partitions enable parallel throughput.
  • Message Key: Messages with the same key (e.g. user_id) are guaranteed to route to the same partition, preserving strict ordering.
  • Consumer Group: A group of cooperating worker instances. Each partition is assigned to exactly one consumer within the group.
