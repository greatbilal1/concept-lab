Lesson 01 · ETL Architecture & Ingestion Patterns

ETL vs ELT: Architecture & Ingestion Strategies

Cloud computing flipped the data pipeline paradigm. Discover how modern ELT replaced traditional ETL to unlock unlimited analytical speed.

Time ~10 min Win Contrast ETL and ELT architectures and select the optimal pattern based on compute and storage trade-offs Mission link Build cost-effective data pipelines that leverage modern cloud data warehouse compute

1Traditional ETL: The compute bottleneck

In the era of on-premise hardware, storage and data warehouse compute were scarce and expensive. To save warehouse disk space, data teams used ETL (Extract, Transform, Load):

  1. Extract: Pull data from transactional SQL databases or logs.
  2. Transform: A dedicated transformation server (like Informatica or custom scripts) cleaned, aggregated, and formatted the data in memory.
  3. Load: Only the final, summarized aggregate rows were written to the data warehouse.

The downside? If business requirements changed, raw un-aggregated data was gone forever and had to be extracted from source systems again.

Key idea ETL transforms data on a separate server before loading; ELT loads raw data first and transforms inside the cloud warehouse.

2Modern ELT: Load raw, transform declaratively

In ELT (Extract, Load, Transform), pipelines extract data and immediately dump the raw, untouched data into a cloud data lake or warehouse staging table. Transformations happen downstream using SQL transformation frameworks like dbt (data build tool).

Benefits: raw historical data is preserved forever, ingestion pipelines never break because of schema transformations, and multiple teams can transform the same raw data for different purposes.
