Lesson 01 · Anatomy of a Repository

Anatomy of a repository

A clean repository speaks to you before you read any code. Learn the universal layout conventions of professional software projects.

Time ~10 min Win Identify the standard files and directories in any production repository Mission link Provides structural orientation for all project navigation

1The standard project anatomy

Every professional software repository separates concerns into dedicated top-level directories: source code (src/ or app/), automated tests (tests/), documentation (docs/), and project configuration.

The root directory is reserved for metadata files that govern the project: README.md (how to run it), LICENSE (legal permissions), .gitignore (what not to commit), and the dependency manifest.

Key idea A project root contains metadata and configuration; source code and tests live in dedicated subdirectories.

2The four primary top-level folders

Understand the strict separation between code, tests, documentation, and tooling.

3Tracing root directory inspection

Trace how an engineer navigates a freshly cloned repository to understand its stack and instructions.

4Practice

Test your memory of canonical repository layout.

✓ Your win for today

You can survey any repository layout and immediately know where configuration, source code, and tests belong.

5Do this next

  1. Audit the root directory of a personal project and move clutter into proper subdirectories.
  2. Ensure your project has a clean README.md with explicit setup commands.
  3. Verify that test files are not mixed in the same directory as production source code.
