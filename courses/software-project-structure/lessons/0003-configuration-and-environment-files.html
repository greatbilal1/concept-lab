Lesson 03 · Configuration & Secrets

Configuration and environment files

Code is identical across environments; configuration varies. Master the Twelve-Factor principle of keeping secrets and runtime configs strictly in the environment.

Time ~10 min Win Separate runtime configuration and secrets from source code using environment variables Mission link Prevents catastrophic secret leaks and configuration drift

1The Twelve-Factor config rule

A litmus test for clean configuration: Could your entire codebase be made open source tomorrow without leaking a single secret or database credential?

If the answer is no, you have hardcoded configuration in your code. The Twelve-Factor App methodology mandates that all configuration that varies between deploys (staging, production, development) must be stored in environment variables.

Key idea Never commit credentials or environment-specific URLs into version control; inject them via the environment.

2The .env and .env.example pattern

Use a committed template (.env.example) to document required keys, paired with an untracked local file (.env) for real values.

3Tracing configuration loading

Trace how an application loads configuration from the environment with sensible fallback defaults.

4Practice

Test your memory of environment configuration principles.

✓ Your win for today

You can architect applications whose source code contains zero hardcoded credentials or environment assumptions.

5Do this next

  1. Audit your repo for hardcoded passwords or API keys using git grep.
  2. Add .env to your root .gitignore file immediately.
  3. Create a .env.example file listing all required configuration keys.
