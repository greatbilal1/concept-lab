Lesson 01 · Orientation & Entry Points

Code is read more than written

Studies show engineers spend 70% of their time reading and understanding code. Treat code reading as a primary professional discipline.

Time ~10 min Win Adopt an active inquiry strategy instead of passive reading Mission link Sets the mindset for professional codebase comprehension

1The reading imbalance

Most computer science curricula emphasize writing: syntax, loops, and fresh empty files. Yet on your first day at work, nobody hands you a blank editor. You are handed a repository with hundreds of thousands of lines of legacy code written by people who no longer work there.

Reading code requires different cognitive skills than writing. You cannot hold an entire repository in your head. You must learn to read selectively, asking specific questions rather than consuming files sequentially.

Key idea Professional developers read selectively with an explicit question in mind.

2Active versus passive reading

Passive reading treats code as static literature. Active reading treats code as a running machine: you ask questions, trace variables, execute tests, and form hypotheses.

3Tracking cognitive load

Notice how focusing only on function signatures reduces cognitive load compared to analyzing full implementation loops.

4Practice

Test your understanding of the principles of active code reading.

✓ Your win for today

You approach unfamiliar code with an active investigation mindset rather than passive linear reading.

5Do this next

  1. Open an open-source project and write down three specific questions about its behavior.
  2. Attempt to answer just one question without reading unrelated files.
  3. Time how long you can investigate without getting lost in trivial details.
Primary source Dr. Felienne Hermans, *The Programmer's Brain* (Chapter 1: 'Decoding and Reading Code').
