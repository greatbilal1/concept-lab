Lesson 08 · Conventions & Architecture

Building a system mental model

You don't understand code by memorizing lines; you understand it by building a working mental model of how components interact. Learn how to synthesize the big picture.

Time ~10 min Win Synthesize an unfamiliar codebase into a concise, accurate architecture diagram Mission link Transforms reading insights into enduring structural mastery

1From lines to models

Comprehension is complete when you can simulate the system in your mind: if input X changes, component Y will transform it and component Z will store it. You no longer need to check every file because you understand the contracts between components.

Document your mental model as you explore. Draw simple block-and-arrow diagrams on paper. The act of externalizing your mental model exposes gaps in your understanding and anchors your memory.

Key idea A reliable mental model allows you to reason about system behavior without re-reading the code.

2The three-layer mental model

Structure your internal model into three levels: External Boundaries, Core Workflows, and Data Persistence.

3Validating the model against a real bug

Trace how an engineer uses their mental model to deduce where a feature modification must take place.

4Practice

Confirm your understanding of building and verifying mental models.

✓ Your win for today

You can build and test accurate mental models that allow you to navigate, modify, and explain any codebase with confidence.

5Do this next

  1. Draw a one-page architecture diagram of your primary project from memory.
  2. Predict where an unfamiliar feature is implemented before searching for it.
  3. Walk a colleague through your mental model and update any misunderstandings.
Primary source Simon Brown, *Software Architecture for Developers* (The C4 Model for Visualising Software).
