Full-text search: tsvector and tsquery

LIKE '%search%' is slow and ignores language morphology. Master PostgreSQL's built-in full-text search engine: stemming, stop words, tsvector, and tsquery.

Time ~10 min Win Implement fast full-text search queries with stemming and relevance ranking in SQL Mission link Provides Google-like search capabilities directly inside your relational database

1The limitations of LIKE '%query%'

Searching text with LIKE '%jump%' has two major flaws: 1. It cannot use B-tree indexes, forcing slow sequential scans across all text, and 2. It has zero linguistic awareness: searching for 'jump' will never match 'jumping' or 'jumped'.

PostgreSQL includes a complete, enterprise-grade Full-Text Search Engine. It parses text into tsvector (a sorted array of stemmed word lexemes with positions) and matches them using tsquery (Boolean search expressions), enabling fast ranked search across gigabytes of text.

Key idea tsvector stems words and strips stop words; tsquery matches linguistic lexemes via GIN indexes.
