Lesson 05 · Security & Permissions

Roles, permissions, and security

Stop connecting your web application as the 'postgres' superuser. Master PostgreSQL role-based security: users, groups, GRANT, REVOKE, and the Principle of Least Privilege.

Time ~10 min Win Configure dedicated database application roles with least-privilege permissions Mission link Prevents accidental database drops and limits blast radius during application compromises

1The danger of the superuser

Connecting an application as the postgres superuser is an enormous security vulnerability. If an SQL injection flaw exists in your app, an attacker has full root access: they can read any table, drop the entire database, and even execute shell commands on the server via COPY PROGRAM!

Security mandates the Principle of Least Privilege: create dedicated application roles with permission to access only the specific tables they need, with zero superuser or schema alteration privileges.

Key idea Never run applications as superusers; grant only the minimum necessary privileges to dedicated roles.

Learn the standard sequence for configuring secure application roles.
