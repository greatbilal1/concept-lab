1Agent Specification Template

Four essential sections
## 1. Goal & Context
What we are building and why.
## 2. Requirements
Inputs, outputs, schemas, endpoints.
## 3. Constraints & Non-Goals
What NOT to touch or install.
## 4. Verification
Exact commands to verify: `pytest tests/test_feature.py`

See Lesson 02 — Anatomy of a Software Specification.

2Machine-Verifiable Acceptance Check

Binary objective criteria
# BAD: 'Make sure billing is reliable'
# GOOD:
- [ ] `pytest tests/test_billing.py` passes 10/10 tests
- [ ] `ruff check src/billing/` reports 0 errors
- [ ] POST /api/v1/charge returns HTTP 402 on card decline

See Lesson 04 — Acceptance Criteria Agents Can Actually Verify.

3Concrete JSON Example Pattern

Few-shot schema grounding
### Request Example:
{
  "sku": "ITEM-42",
  "qty": 2,
  "price_cents": 1999
}
### Response (201):
{
  "order_id": "ord_104",
  "total_cents": 3998
}

See Lesson 06 — Example-Driven Specifications.

4Spec Invariants Clause

Guarding non-negotiable rules
### Invariants (MUST NEVER BE VIOLATED):
1. Account balance cannot be negative.
2. Shipped orders cannot be cancelled.
3. Write test for each invariant before modifying code.

See Lesson 05 — Edge Cases, Invariants, and Non-Goals.
