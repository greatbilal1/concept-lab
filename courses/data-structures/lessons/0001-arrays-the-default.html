Lesson 01 · Contiguous data

Arrays: the default

A Python list is the tool everyone reaches for first. It is also an array — a block of memory laid out end to end. Understanding that layout explains why some list operations are instant and others crawl.

Time ~10 min Win Explain why indexing is instant but inserting is not Mission link Choosing a structure starts with knowing the default

1One block, end to end

An array stores its items in contiguous memory — one after another, with no gaps. If each item is the same size, the computer can jump straight to any of them: 

address = start + index * item_size

That single line is the whole trick. To read items[4], the computer does one multiplication and one addition. It does not walk the list. This is why indexing is O(1) — constant time, no matter how big the array is.

Key idea Contiguity is what makes indexing instant. The cost of every other array operation follows from having to preserve that contiguity.

2The price of staying contiguous

Reading is cheap. Changing the shape is not, because the block must stay unbroken. Insert an item at the front and every later item has to shift one slot to the right: 

items = ["a", "b", "c", "d"]
items.insert(0, "z")
# every item moved:  ["z", "a", "b", "c", "d"]

That shift touches every element, so inserting at the front is O(n). Appending at the end is different — nothing needs to move, so it is O(1) (amortised, because the block occasionally has to grow).

3What a list is good at

A Python list is an array with a few conveniences. Reach for it when you:

  • need fast access by position — items[i];
  • mostly append and read, rather than insert in the middle;
  • want to iterate in order, front to back.

Reach for something else when you insert and delete at the front constantly — that is the linked list, next lesson.

✓ Your win for today You can explain why items[1000] is instant but items.insert(0, x) is not — and it is the same reason.
