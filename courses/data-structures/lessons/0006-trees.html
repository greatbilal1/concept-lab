Lesson 06 · Hierarchy

Trees

A linked list is a chain: each node points to one next node. A tree relaxes that — each node can point to several children. The moment a structure branches, it can describe hierarchy: folders, families, and the shape that makes fast search possible.

Time ~10 min Win Name the parts of a tree and build one from nodes Mission link Branching is what unlocks hierarchy

1Nodes that branch

A tree is made of nodes connected by edges. One node sits at the top — the root. Every other node has exactly one parent and any number of children. A node with no children is a leaf.

The defining rule is that there are no cycles: you can never follow edges and arrive back where you started. That single constraint is what makes a tree a tree rather than a general graph.

Key idea A tree is a linked list that branches. Each node still holds a value and pointers — there are just more than one of them.

2Binary trees

The most common tree limits each node to at most two children, called left and right. This is a binary tree, and it is the shape behind almost every tree you will meet. 

class Node:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None

That is the whole structure. A node holds a value and two references, either of which may be None — meaning "no child on that side".

3Depth and balance

The depth of a node is how many edges separate it from the root. The depth of the tree is the longest such path. Depth matters because most tree operations cost time proportional to it — you walk down from the root.

A tree where every level is full is balanced, and its depth grows logarithmically with the number of nodes. A tree that leans to one side is degenerate — it has the depth of a linked list, and the speed of one too.

Watch out "Tree" says nothing about order. A binary tree can hold its values in any arrangement at all — the ordering rule comes next lesson, with the binary search tree.

4Where trees show up

  • File systems — folders contain files and more folders.
  • The DOM — every HTML element contains its children.
  • Organisation charts — one manager, several reports.
  • Parsing — an expression like 2 * (3 + 4) becomes a tree.

✓ Your win for today

You can name every part of a tree — root, parent, child, leaf, depth — and build a binary tree from a simple node class. You also know why depth is the number that decides how fast tree operations are.
