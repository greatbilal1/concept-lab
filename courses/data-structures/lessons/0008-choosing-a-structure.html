Lesson 08 · Putting it together

Choosing a structure

You now know seven structures. The skill that matters is not memorising them — it is looking at a problem and seeing which one fits. This lesson gives you the vocabulary to make that choice deliberately.

Time ~12 min Win Pick a structure from the shape of the problem Mission link The structure is the first decision

1Cost, in one idea

Big-O is a way of describing how an operation's cost grows as the data grows. It ignores constants and small inputs and asks the only question that matters at scale: when the data doubles, what happens to the work?

The structures in this course differ mainly in which operation is cheap. An array is O(1) to read by index but O(n) to insert at the front. A hash table is O(1) to look up by key but has no order. A BST is O(log n) to search and keeps its keys sorted.

Key idea There is no best structure — only a best structure for a given mix of operations. Name the operations first, then choose.

2Amortised cost

Some operations are occasionally expensive but cheap on average. Growing a hash table is O(n) when it happens, but it happens so rarely that the amortised cost of an insert stays O(1). Appending to a Python list works the same way.

Amortised cost is the honest way to describe a structure that does occasional big work to keep the common case fast. It is not a trick — it is the real average you experience over many operations.

3Trade-offs

Every structure buys one thing by giving up another. That exchange is a trade-off, and naming it is how you justify a choice.

  • Array — fast indexed reads, slow inserts in the middle.
  • Linked list — fast inserts anywhere, slow reads by position.
  • Stack / queue — perfect order discipline, no random access.
  • Hash table — fast keyed lookup, no ordering.
  • BST — ordered and searchable, but only fast while balanced.

4A decision guide

Read the shape of the problem, and the structure usually names itself:

  • Need the nth item fast? → array.
  • Inserting and removing at the ends? → stack or queue.
  • Looking things up by name? → hash table.
  • Need data kept in order and searchable? → BST.
  • Data that nests? → tree.

✓ Your win for today

You can describe any structure by which operation it makes cheap, explain amortised cost, and name the trade-off behind a choice. You have a decision guide that turns a problem's shape into a structure.
