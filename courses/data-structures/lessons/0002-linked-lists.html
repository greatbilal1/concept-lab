Lesson 02 · Contiguous data

Linked lists

An array's strength — contiguity — is also its weakness. A linked list gives that up on purpose. Instead of one block, it is a chain of separate nodes, each pointing to the next.

Time ~10 min Win Explain what a linked list makes cheap and expensive Mission link The same trade-off appears in every structure

1A chain of nodes

A linked list stores each item in its own node. A node holds a value and a pointer to the next node. The nodes can live anywhere in memory — they do not need to be neighbours: 

node = { value: "b", next: → node("c") }

The list itself only needs to remember the head — the first node. From there you follow the pointers to reach the rest.

Key idea No contiguity means no shifting. Inserting at the front is just a pointer swap — but reaching the nth item now means walking the chain.

2Cheap inserts, slow lookups

To insert at the front, you point the new node at the old head and move the head. Two pointer changes, no matter how long the list is — O(1): 

new.next = head
head = new

But there is no formula to jump to index i. The nodes are scattered, so you must start at the head and follow i pointers. Reading the nth item is O(n) — the exact opposite of an array.

3When to reach for one

In Python you rarely build a linked list by hand — collections.deque covers most needs. But the idea matters because it is the shape behind many other structures:

  • a stack is a linked list you only touch at one end;
  • a queue is a linked list you add to at one end and remove from the other;
  • a tree is a linked list that branches.
✓ Your win for today You can state the array/linked-list trade-off in one sentence: fast indexing versus fast inserts.
