Lesson 08 · Boundaries & Abstractions

Bounded contexts and vertical slice architecture

Moving beyond technical layers: explore Domain-Driven Design's Bounded Contexts and Vertical Slice Architecture to organize software by business capabilities.

Time ~10 min Win Design vertical slice architectures and define domain Bounded Context boundaries Mission link The modern architectural paradigm organizing large software teams around business capabilities

1From horizontal layers to vertical slices

In traditional horizontal architectures, adding a new feature requires editing five folders: controllers/, services/, repositories/, models/, and dtos/. Code that changes together is scattered far apart.

Vertical Slice Architecture groups code by Business Capability: everything needed to execute 'PlaceOrder' (the endpoint, command handler, validator, and query) lives inside a single cohesive folder: features/place_order/. Paired with Domain-Driven Design's Bounded Contexts, systems evolve rapidly with zero cross-feature contamination.

Key idea Vertical slices group code by business capability, keeping everything that changes together in one place.
