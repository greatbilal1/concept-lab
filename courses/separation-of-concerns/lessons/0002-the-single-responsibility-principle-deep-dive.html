Lesson 02 · Single Responsibility & Actors

The Single Responsibility Principle deep dive

A class should have only one reason to change. But what is a 'reason to change'? Master Robert C. Martin's definition of SRP: separating code by business actors.

Time ~10 min Win Apply the Single Responsibility Principle by aligning class boundaries with business actors Mission link Prevents merge conflicts and unintended regressions across different company departments

1A reason to change is an Actor

The Single Responsibility Principle (SRP) is often misquoted as 'a class should do only one thing'. Robert C. Martin clarified the true definition: A module should be responsible to one, and only one, actor.

An Actor is a person or department who requests a change: the CFO (Accounting), the COO (Operations), or the CTO (IT/DBA). If a single Employee class contains calculatePay() (governed by CFO) and reportHours() (governed by COO), changes made for Accounting risk breaking Operations!

Key idea A module should have only one reason to change, meaning it serves exactly one business actor.
