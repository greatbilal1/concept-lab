Complex Types & Memory Management

How do you pass a string or JSON object to Wasm when it only understands numbers? Master pointers, allocations, and deallocation.

Time ~10 min Win Pass strings and byte buffers across the JS-Wasm boundary using memory pointers and prevent memory leaks Mission link Master low-level data marshaling and manual memory lifecycle management

1The string challenge: Everything is a number

WebAssembly functions can only accept and return i32, i64, f32, and f64. It has no native concept of a string, array, or object. So how does greet("Alice") work?

A string in Wasm is represented as two numbers:

  1. A pointer (offset): The 32-bit memory address where the string's bytes begin in linear memory.
  2. A length: The number of UTF-8 bytes in the string.
Key idea Strings and buffers are passed to Wasm as a memory pointer (offset address) and a length.

2The allocation lifecycle: malloc and free

To pass data from JavaScript into Wasm without bindgen abstractions:

  1. Wasm exports an allocation helper: alloc(size) (which calls Rust/C malloc).
  2. JavaScript calls const ptr = instance.exports.alloc(byteLength).
  3. JavaScript writes the UTF-8 bytes into new Uint8Array(memory.buffer, ptr, byteLength).
  4. Wasm processes the data at ptr.
  5. JavaScript calls instance.exports.dealloc(ptr, byteLength) to prevent memory leaks.
