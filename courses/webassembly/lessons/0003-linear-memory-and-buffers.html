Lesson 03 · Linear Memory & Interoperability

Linear Memory & TypedArrays

WebAssembly cannot access JavaScript garbage-collected objects directly. Instead, both communicate through shared Linear Memory.

Time ~10 min Win Allocate, read, and write WebAssembly Linear Memory using JavaScript TypedArrays Mission link Exchange high-volume raw data (images, audio, geometries) between JS and Wasm with zero copying

1The Linear Memory model

WebAssembly modules do not have direct access to JavaScript variables or the DOM. Instead, Wasm programs interact with the outside world through Linear Memory: a single contiguous array of raw bytes represented as a WebAssembly.Memory object.

Memory is allocated in pages of 64KB (65,536 bytes). Memory can grow dynamically using memory.grow(pages). Both JavaScript and Wasm can read and write to this exact same memory buffer simultaneously.

Key idea Linear memory is a contiguous byte array (in 64KB pages) shared between JavaScript and WebAssembly.

2Viewing memory with TypedArrays

In JavaScript, a WebAssembly.Memory object wraps an ArrayBuffer. You inspect or modify memory by creating TypedArray views over its buffer:

  • new Uint8Array(memory.buffer): Byte-by-byte access (great for images and ASCII strings).
  • new Int32Array(memory.buffer): 4-byte signed integers.
  • new Float32Array(memory.buffer): 4-byte floating point numbers (great for 3D coordinates and audio waveforms).
