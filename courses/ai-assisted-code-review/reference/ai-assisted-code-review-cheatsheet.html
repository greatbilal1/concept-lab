1Skeptical Diff Review Checklist

Line-by-line audit guide
1. DELETIONS: Did the agent delete existing error checks or tests?
2. IMPORTS: Are all imports approved in package.json / pyproject.toml?
3. BOUNDARIES: Check off-by-one ranges and date/currency math.
4. TESTS: Verify test assertions were NOT weakened or deleted.

See Lesson 03 — Reviewing AI-Generated Diffs with Skepticism.

2Targeted Security Review Prompt

Hunting OWASP vulnerabilities
"Audit src/api/orders.py with threat model: Authenticated Malicious Tenant.
Check specifically for:
1. IDOR: Are queries filtered by user.tenant_id?
2. Injection: Are all SQL queries parameterized?
3. Race Conditions: Are concurrent updates locked with FOR UPDATE?"

See Lesson 04 — Prompting for Security Audits and Vulnerabilities.

3PR Size and Review Policy

Defeating review fatigue
# Team Code Review Rules:
- Max PR Size: 300 lines of diff.
- Split large features into sequential, reviewable milestones.
- Require CI green (linters, types, tests) BEFORE human review starts.

See Lesson 07 — Preventing Review Fatigue and Rubber-Stamping.

4Human Verification Gate Architecture

Safeguarding high-consequence paths
# Mandatory Human Sign-Off Required For:
1. Production database schema migrations
2. Financial pricing and refund logic
3. Authentication, password, and session handling
4. Production deployment promotion

See Lesson 08 — Establishing Human Verification Gates.
