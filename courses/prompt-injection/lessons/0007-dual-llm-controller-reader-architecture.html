Dual-LLM Architectures: Decoupled Controller and Reader

1Core principles of Dual-LLM Architectures: Decoupled Controller and Reader

Prompt injection exists because an untrusted piece of text has the power to instruct a model that possesses tools. Security researcher Simon Willison proposed the ultimate architectural solution: The Dual-LLM Pattern (Privileged Controller vs Unprivileged Reader).

Key idea Architectural isolation: the Privileged Controller and the Unprivileged Reader (Simon Willison's Dual-LLM pattern).

How the Dual-LLM Architecture works:

3Neutralizing the Attack

  • 1. The Privileged Controller (Has Tools, Sees Zero Untrusted Data): The Controller coordinates the workflow and has access to sensitive tools (send email, query database). It NEVER directly reads raw web pages, emails, or PDFs!
  • 2. The Unprivileged Reader (Reads Untrusted Data, Has Zero Tools): When a web page or PDF must be read, it is sent to the Reader model. The Reader has ZERO tools and ZERO execution permissions. It cannot call an API, access a database, or connect to the internet.
  • 3. Sanitized Structured Data Transfer: The Reader extracts strictly structured, typed data (e.g. JSON with title, date, key facts) and passes it back to the Controller. Even if the Reader is completely hijacked by prompt injection, it has no tools to execute the attack!
# The Dual-LLM Execution Flow:
[User Prompt] ──> [Privileged Controller (Has Tools: email, database)]
                         │
                         │ (Commands Reader to ingest document)
                         ▼
                  [Unprivileged Reader (NO TOOLS! Isolated Sandbox)]
                         │ (Ingests poisoned PDF containing prompt injection)
                         │ (Injection attempts to hijack... BUT READER HAS NO TOOLS!)
                         ▼
                  [Emits Clean JSON Summary: {"revenue": 100, "expenses": 40}]
                         │
                         ▼
[Privileged Controller receives pure data, executes safe tools, delivers to user!]

The Architectural Separation of Privilege: You cannot be hacked by an instruction if the model that reads it has no hands to touch the world.
