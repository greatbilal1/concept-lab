Lesson 03 · Stateful Session Systems

Session IDs and cookie lifecycle

How does the server remember that you logged in? Explore the stateful session model: generating high-entropy session IDs and managing cookie lifecycles.

Time ~10 min Win Design stateful session authentication workflows using random session tokens Mission link The classic, battle-tested architecture for web application state

1The stateful session architecture

In a stateful session architecture, the server generates a cryptographically secure random string called a Session ID upon successful login. The server saves this ID in its database alongside user metadata (user_id: 42, role: 'admin').

The server then issues a Set-Cookie: sid=a8f9c2... header to the browser. On every future request, the browser includes this cookie. The server looks up the session ID in its store to identify the user.

Key idea A session ID is an opaque pointer to server-side session state stored in a secure cookie.
