Lesson 11 · Data

From source to running

You write print("hi"). A moment later, something happens. This lesson fills in the gap — the pipeline that turns text you can read into instructions the CPU can execute.

Time ~12 min Win Trace a line through the pipeline Mission link Where your code actually goes

1The gap to close

The CPU executes machine code — numbers, from lesson seven. You write Python, JavaScript, C or Rust. Something has to translate. That something is either a compiler or an interpreter, and the difference matters.

Key idea A compiler translates the whole program ahead of time into machine code. An interpreter reads and executes the program as it goes. Both end up doing the same work; they differ in when.

2Two strategies

Compilation is a pipeline of stages, each one transforming the program into something closer to machine code: 

source text
   ↓  lexer      split into tokens
tokens
   ↓  parser     build a syntax tree
tree
   ↓  optimiser  simplify and speed up
tree
   ↓  codegen    emit machine instructions
machine code

Each stage is a program in its own right. The lexer does not know what the program means; the parser does not know what the CPU is. Each one just transforms its input into a more structured form.

3The hybrid: bytecode

Python and JavaScript take a middle path. They compile your source to bytecode — a compact instruction set for a virtual machine, not for real hardware — and then interpret that. 

source  →  bytecode  →  virtual machine  →  real CPU
  (you)     (compiler)     (interpreter)      (hardware)

This buys portability: the same bytecode runs anywhere the virtual machine runs. It costs speed, because the virtual machine is another layer of interpretation — which is why hot loops get compiled to real machine code at runtime.

The unifying view Every language is somewhere on a spectrum from "translated fully before running" to "translated line by line while running". The CPU at the bottom only ever sees machine code. Everything above is translation.

4Trace a line

Here is the win. Follow this single line all the way down: 

x = 2 + 3

The lexer splits it into x, =, 2, +, 3. The parser builds a tree: assign to x the result of adding 2 and 3. The optimiser may fold it to x = 5. Codegen emits a load, a load, an add, a store. The CPU then runs those four instructions — exactly the kind of program you decoded in lesson seven.

✓ Your win for today

You can now describe the full path from source text to a running instruction, explain the difference between compiling and interpreting, and place bytecode and virtual machines on that spectrum. The gap between "I wrote code" and "the CPU ran it" is now filled in.

  2. Explain why Python is slower than C for the same loop. Your answer should mention the virtual machine.
  3. Find out whether your favourite language compiles, interprets, or does both. Most modern ones do both.
