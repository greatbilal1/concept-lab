Lesson 07 · The machine

Instructions and programs

The CPU reads numbers and treats them as commands. This lesson is about that encoding — how a number becomes "add these two things", and how a list of those numbers becomes a program.

Time ~12 min Win Decode a four-instruction program Mission link How source text becomes commands

1An instruction is just a number

The CPU has no concept of "ADD". It has a table of operations, and each one is identified by a number — an opcode. The instruction is that number, plus the operands it needs. 

opcode  operation
0x01    LOAD   R, address
0x02    STORE  address, R
0x03    ADD    R1, R2
0x04    JUMP   address
0x05    HALT

That table is the instruction set. It is the contract between the hardware and every program that will ever run on it. Different CPU families have different tables — that is what "x86" and "ARM" mean.

Key idea A program is a list of numbers in memory. The CPU does not distinguish code from data — it just reads numbers and, if the PC points at them, treats them as commands.

2Machine code and assembly

The raw numbers are machine code. Nobody writes machine code by hand, so we invented assembly language — the same instructions, spelled with short readable names. An assembler translates one into the other, one line at a time.

This is a one-to-one mapping. One assembly line becomes one machine instruction. That is what makes assembly "low level": you are still thinking in the CPU's terms, just with better spelling.

3Decode a program

Here is a tiny program. Read it line by line and work out what it does before you look at the trace: 

0x00  LOAD  R1, 0x10     ; R1 = memory[0x10]
0x01  LOAD  R2, 0x11     ; R2 = memory[0x11]
0x02  ADD   R1, R2       ; R1 = R1 + R2
0x03  STORE 0x12, R1     ; memory[0x12] = R1
0x04  HALT

It loads two numbers, adds them, stores the result, and stops. That is a complete program — five instructions, and it does real work.

This is the whole idea Every program you have ever run — a browser, a game, a compiler — is a list like this, just enormously longer. The structure never changes: load, compute, store, branch, repeat.

4Decode it yourself

Here is the win. Given this program and starting state, work out the final value of R1: 

memory[0x10] = 9
memory[0x11] = 4

0x00  LOAD  R1, 0x10
0x01  LOAD  R2, 0x11
0x02  ADD   R1, R2
0x03  HALT

R1 becomes 9, then R2 becomes 4, then R1 becomes 9 + 4 = 13. Final answer: R1 = 13. You just executed a program by reading it.

5Check yourself

Answer from memory — do not scroll back up. Each option has the same number of words, so nothing gives the answer away.

✓ Your win for today

You can now read a small program in assembly, explain what an opcode is, and trace a program's effect on registers and memory. You have crossed from "the CPU runs instructions" to "I can read the instructions" — and that is the skill that makes everything below your code visible.

6Do this next

  1. Write a four-instruction program that computes memory[0x20] - memory[0x21] and stores it at 0x22. You will need a SUB opcode.
  2. Explain why the CPU cannot tell code from data. What does that imply about where a program's instructions live?
  3. Look up the assembly for a language you know. Find one line of your own code and see how many instructions it becomes.
