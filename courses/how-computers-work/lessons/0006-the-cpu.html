Lesson 06 · The machine

The CPU

You have gates, adders and memory. Now assemble them into a machine that runs a program. The CPU is smaller than you think: a handful of registers, an adder, and a loop that never stops.

Time ~12 min Win Hand-run one clock cycle Mission link The engine every program runs on

1The three-part loop

A CPU does one thing, over and over, billions of times a second: 

1. FETCH    read the next instruction from memory
2. DECODE   work out what that instruction means
3. EXECUTE  do it, and move to the next instruction

That is the whole design. Everything else — caches, pipelines, multiple cores — is an optimisation of this loop. If you understand fetch–decode–execute, you understand the CPU.

Key idea The CPU is not clever. It has no idea what your program means. It reads a number, looks it up in a table of operations, performs one, and moves on.

2The parts

Five components, and you already know what four of them are:

The program counter is the star of the show. It holds the address of the next instruction. After each instruction it increments — usually by 1, sometimes jumping somewhere else. A jump is what makes loops and conditionals possible.

3One cycle, step by step

Let us run a single instruction by hand. Suppose the program counter holds 0x10, and memory at that address contains the instruction "add register 1 to register 2".

Notice how much is happening. The PC was read, memory was accessed, the instruction was decoded, the ALU did arithmetic, a register was written, and the PC advanced. All of that in one tick of the clock.

Scale check A modern CPU runs this loop around 3 billion times per second, and often several instructions per tick. The loop you just traced by hand happens faster than you can blink — but it is the same loop.

4Run a cycle yourself

Here is the win. Given this tiny machine state, work out what happens on the next tick: 

PC      = 0x20
R1      = 5
R2      = 7
memory[0x20] = "ADD R1, R2"   (result goes into R1)

Fetch: read memory at 0x20. Decode: it is an ADD. Execute: the ALU computes 5 + 7 = 12 and writes it to R1. Then the PC becomes 0x21.

Final state: R1 = 12, R2 = 7, PC = 0x21. You just executed an instruction.

✓ Your win for today

You can now name the parts of a CPU, explain the fetch–decode–execute loop, and hand-run a single clock cycle. You have gone from "the CPU is a magic chip" to "the CPU is a loop over a table of operations" — which is the single biggest demystification in this course.

6Do this next

  1. Run another cycle by hand. Start with PC = 0x30, R1 = 100, and memory[0x30] = "SUB R1, 1". What are the final values?
  2. Explain why the program counter must exist. What would break if the CPU had no way to know which instruction came next?
  3. Work out how many instructions a 3 GHz CPU executes in one second, assuming one instruction per cycle. Then think about how much work that is.
