Lesson 09 · Data

Text and characters

The machine only stores numbers. So how does it store the word "hello"? The answer is a lookup table agreed on decades ago — and the story of how that table grew to cover every writing system on Earth.

Time ~10 min Win Encode a word in ASCII and hex Mission link Why text is just numbers

1An arbitrary agreement

There is nothing about the letter A that suggests the number 65. It is a convention — a table that says "when you see 65, draw an A". That table is ASCII, and it was standardised in 1963. 

65  =  A        97  =  a
66  =  B        98  =  b
67  =  C        99  =  c
...
48  =  '0'      32  =  space

Notice that uppercase and lowercase differ by exactly 32. That is not a coincidence — it is a single bit. Flipping bit 5 of a letter's code toggles its case, which is why case conversion is so cheap.

Key idea Text is not special. A string is a sequence of numbers, each one an index into a character table. The machine never sees letters.

2Seven bits was not enough

ASCII uses seven bits, giving 128 characters. That covers English comfortably and almost nothing else. French accents, Greek, Cyrillic, Arabic, Chinese — all outside the table.

For years, everyone invented their own extensions, and text broke constantly whenever it crossed a border. The fix was Unicode: one giant table assigning a number — a code point — to every character in every writing system.

But a code point is just an abstract number. You still need to store it as bytes. That is UTF-8.

3UTF-8: variable width, backwards compatible

UTF-8 encodes a code point in one to four bytes, depending on how large it is. Small values — the ASCII range — take one byte. Larger ones take more. 

0xxxxxxx                              → 1 byte   (ASCII, 0–127)
110xxxxx 10xxxxxx                     → 2 bytes
1110xxxx 10xxxxxx 10xxxxxx            → 3 bytes
11110xxx 10xxxxxx 10xxxxxx 10xxxxxx   → 4 bytes

The leading bits are a length marker. A byte starting with 0 is a complete one-byte character; a byte starting with 10 is a continuation. This is self-synchronising: you can jump into the middle of a stream and find the next character boundary.

The clever part Every ASCII file is already valid UTF-8, byte for byte. That backwards compatibility is why UTF-8 took over the world instead of a cleaner but incompatible design.

4Encode a word

Here is the win. Encode the word cat in ASCII, then in hex: 

c  =  99  =  0x63
a  =  97  =  0x61
t  = 116  =  0x74

"cat"  =  63 61 74

Three characters, three bytes, six hex digits. Now try Cat — the first byte becomes 0x43, because C is 67 and c is 99. One bit changed.

✓ Your win for today

You can now encode and decode text by hand, explain why ASCII was not enough, and describe how UTF-8 stays compatible with it. You have also learned the general lesson: every data type is a convention. The bytes are always just bytes; the meaning is an agreement.

6Do this next

  1. Encode your own first name in ASCII, then in hex. Check the byte count matches the character count.
  2. Work out the ASCII code for Z from the table. Then work out z without looking — remember the difference of 32.
  3. Explain why a file of English text is roughly one byte per character, but a file of Chinese text is roughly three. Which UTF-8 length is being used?
