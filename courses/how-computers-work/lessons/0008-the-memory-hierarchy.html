Lesson 08 · The machine

The memory hierarchy

Fast memory is tiny and expensive. Big memory is slow and cheap. The machine solves this by stacking them — and the resulting hierarchy explains more about real-world performance than any other single idea.

Time ~12 min Win Compare latencies by orders of magnitude Mission link Why fast code is often about memory

1The trade-off nobody escapes

A register can be read in under a nanosecond. A hard disk takes milliseconds. That is a factor of roughly a million. You cannot build a machine where everything is register-fast, because register-fast memory is physically enormous and expensive.

So the machine does not choose. It uses all of them, arranged in layers, and moves data between layers as needed.

Key idea The hierarchy is a bet: small, fast, expensive at the top; large, slow, cheap at the bottom. Each layer caches the one below it.

2The layers

Each layer is bigger and slower than the one above. The CPU tries the top first, and only descends when it misses. Because programs tend to reuse the same data over and over, the top layers hit most of the time.

3Latency, in human terms

Numbers in nanoseconds are hard to feel. So scale everything up by a factor of a billion — one nanosecond becomes one second: 

register   1 ns   →  1 second
L1 cache   1 ns   →  1 second
RAM       100 ns  →  1.5 minutes
SSD       100 µs  →  1.2 days
disk       10 ms  →  4 months

Now the hierarchy is visceral. If a register access is reaching for a book on your desk, a disk access is a four-month expedition. This is why caches exist, and why a cache miss can cost more than a thousand arithmetic operations.

Locality Caches work because programs are predictable. Temporal locality: you reuse the same variable soon. Spatial locality: you use the next element of an array. Both mean the cache usually already has what you need.

4Compare the layers

Here is the win. Rank these four operations from fastest to slowest, and note how many orders of magnitude separate them: 

A. read a value from a register
B. read a value from RAM
C. read a value from an SSD
D. read a value from a spinning disk

Answer: A, then B, then C, then D. Register to RAM is about 100×. RAM to SSD is about 1,000×. SSD to disk is about 100×. Stacked up, the top and bottom are roughly a million apart.

✓ Your win for today

You can now name the layers of memory, put them in order, and explain why the hierarchy exists. More importantly, you can now predict why some code is slow before you run it — because you know that touching memory is often the expensive part, not doing arithmetic.

6Do this next

  1. Write down the five layers from fastest to slowest, with a rough latency for each. Do it from memory, then check.
  2. Explain why a cache miss is expensive. What has to happen that does not happen on a cache hit?
  3. Think of a loop you have written that walks an array. Which kind of locality does it exploit, and why does that make it fast?
