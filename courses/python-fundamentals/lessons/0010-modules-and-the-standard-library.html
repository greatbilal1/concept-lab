Modules and the standard library

You do not write everything yourself. Python ships with a large standard library, and you can split your own code into modules too. This lesson shows you how to import, what a module really is, and the one idiom every Python file should know.

Time ~14 min Win Import and use a module Mission link Modules are how programs grow past one file

1A module is just a file

Any .py file is a module. Its top-level names become the module's attributes, and other files can import them. 

# math_utils.py
def double(n):
    return n * 2

PI = 3.14159

That file is now a module named math_utils. Nothing special is required — no declaration, no export list. The filename is the module name.

Key idea A module is a namespace: a named container of values and functions. Importing gives you access to that container.

2Three ways to import

You can import the whole module, import specific names, or rename on import. Each has a place. 

import math                    # math.sqrt(16)
from math import sqrt          # sqrt(16)
from math import sqrt as root  # root(16)

import math keeps the module name in front of everything, which makes it obvious where a name came from. That is usually the clearest choice in a large file.

3The standard library

Python ships with hundreds of modules, ready to import with no installation. A few you will use constantly: 

import math        # sqrt, pi, floor, ceil
import random      # random(), randint(), choice()
import datetime    # date, datetime, timedelta
import json        # loads(), dumps()
import os          # path, environ, getcwd()

Because they are part of Python, they work offline and need no package manager. Reaching for the standard library before writing your own code is a habit worth building.

4The __main__ idiom

When Python runs a file directly, it sets the special name __name__ to "__main__". When the file is imported, __name__ is the module's name instead. 

def main():
    print("running")

if __name__ == "__main__":
    main()

This guard means the code inside runs only when the file is executed directly, not when it is imported. It lets a file be both a script and a reusable module.

Common trap from math import * dumps every name into your file and can silently overwrite your own names. Prefer explicit imports.
