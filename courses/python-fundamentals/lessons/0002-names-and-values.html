Lesson 02 · Syntax & values

Names and values

A program that cannot remember anything is useless. Names are how Python remembers: you attach a label to a value, then use the label later. This lesson is about that one operation — assignment — and the mental model that makes it click.

Time ~12 min Win Bind, rebind, and read names confidently Mission link Every later lesson stores its data in names

1A name is a label, not a box

The most common wrong mental model is that a variable is a box that holds a value. In Python it is closer to a label stuck onto a value. The value lives somewhere in memory; the name is just a way to refer to it. 

score = 10
score = 25

The first line sticks the label score onto the value 10. The second line peels that label off and sticks it onto 25. The 10 is not changed — it is simply no longer reachable by that name.

Key idea name = value means "make this name refer to this value". It is not a claim about the value, and it is not a copy of it.

2Assignment is a statement

Assignment is a statement, not an expression. It does something; it does not produce a value. That is why x = (y = 3) is a syntax error in Python even though it is legal in C and JavaScript.

The right-hand side is evaluated first, then the name is bound to the result. So x = x + 1 is perfectly sensible: read the old value of x, add one, then rebind x to the new value. 

count = 0
count = count + 1     # read 0, add 1, rebind count to 1
count += 1            # same thing, shorter form

3Choosing good names

Python does not care what you call a name, but your future self does. The community convention is PEP 8: lowercase words joined by underscores, like total_price or user_name.

A name must start with a letter or underscore, and may contain letters, digits and underscores. It cannot start with a digit, and it cannot be one of Python's reserved words such as if, for or class. 

total_price = 19.99     # good
TotalPrice  = 19.99     # legal, but not Pythonic
2fast       = 19.99     # SyntaxError: starts with a digit
class       = 19.99     # SyntaxError: reserved word

4Reading a name that does not exist

If you use a name before binding it, Python raises NameError. This is a runtime error, not a syntax error — the file parses fine, it just fails when execution reaches that line. 

print(total)     # NameError: name 'total' is not defined
total = 5
print(total)     # 5
Common trap Typos produce NameError, not a helpful "did you mean" message. If you see one, check the spelling and check that the assignment ran before the line that reads it.

✓ Your win for today

You can bind a name, rebind it, and explain why the old value is not "changed". You also know the naming rules and what a NameError means.
