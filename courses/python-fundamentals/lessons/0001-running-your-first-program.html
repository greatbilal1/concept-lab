Lesson 01 · Syntax & values

Running your first program

Before types, loops or functions, there is one thing to get right: the loop between you and the machine. Write a line, run it, read what comes back. This lesson sets up that loop and shows you the two ways Python runs your code.

Time ~10 min Win Run a file and read its output Mission link The feedback loop every later lesson depends on

1Python is a program that runs your program

You do not talk to the hardware directly. You write a text file, and a program called the interpreter reads it and does what it says. That interpreter is python3, and it is already installed on macOS and most Linux systems.

The interpreter works top to bottom. It reads a line, works out what it means, does it, then moves to the next line. There is no compile step you have to run first, and no build folder to clean up.

Key idea A Python file is a script, not a blueprint. The interpreter executes it in order, one statement at a time, and stops at the first error it cannot handle.

2Two ways to run code

There are exactly two ways you will run Python in this course, and they serve different purposes.

The REPL (Read–Eval–Print Loop) is what you get when you run python3 with no filename. It shows a >>> prompt, evaluates whatever you type, and prints the result immediately. It is the fastest way to answer "what does this expression do?".

A file is what you get when you save code as hello.py and run python3 hello.py. Nothing is printed unless you ask for it with print(). That difference surprises people the first time. 

$ python3
>>> 2 + 3
5
>>> exit()

$ python3 hello.py
Hello, world!

3Statements, expressions, and print

Two words describe almost every line you will write. An expression is code that produces a value — 2 + 3, "a" + "b", len("cat"). A statement is an instruction the interpreter carries out, like assigning a name or printing something.

In the REPL, expressions are printed for you automatically. In a file they are not. That is why print() exists: it is the built-in function that turns a value into visible output. 

# hello.py
print("Hello, world!")     # a statement: prints text
print(2 + 3)               # prints 5
print("2 + 3")             # prints 2 + 3 — it is a string

The third line is the one to notice. Quotes make a string: the characters are data, not code. print("2 + 3") prints the text 2 + 3; print(2 + 3) prints 5.

4When it goes wrong

Errors are not a failure of the lesson — they are the interpreter telling you exactly where it got stuck. When a program fails, Python prints a traceback: the file, the line number, the kind of error, and a message. 

$ python3 broken.py
Traceback (most recent call last):
  File "broken.py", line 2, in <module>
    print("hello"
          ^
SyntaxError: '(' was never closed

Read a traceback bottom-up: the last line names the error, the line above it shows the offending source. SyntaxError means the interpreter could not even parse the file; NameError means it parsed fine but a name did not exist at runtime.

Common trap A SyntaxError stops the whole file before any of it runs. A runtime error stops it at the line that failed — everything before that line has already happened.

5Check yourself

Answer from memory — do not scroll back up. Each option has the same number of words, so nothing gives the answer away.

✓ Your win for today

You can run Python two ways, tell a statement from an expression, and read a traceback without panicking. That loop — write, run, read the output — is the one you will use for the rest of this course.

6Do this next

  1. Open a terminal and run python3. Evaluate 2 + 3, "2" + "3" and 2 * 3. Notice which one surprises you.
  2. Save a file called hello.py with three print() lines, run it with python3 hello.py, then delete one closing bracket and run it again. Read the traceback bottom-up.
  3. Write a file that prints 2 + 3 and another that prints "2 + 3". Predict the output before you run each one.
