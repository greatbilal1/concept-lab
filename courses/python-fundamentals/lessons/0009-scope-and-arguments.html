Lesson 09 · Functions

Scope and arguments

Functions have their own little world of names. Understanding that world — scope — explains why some variables vanish and others leak. This lesson also covers the argument features that make functions pleasant to call: defaults and keyword arguments.

Time ~14 min Win Predict which names a function can see Mission link Scope is why functions stay independent

1Local names live inside the function

A name assigned inside a function is local to that function. It is created when the function is called and disappears when the call ends. 

def double(n):
    result = n * 2
    return result

double(5)          # 10
print(result)      # NameError: result is not defined

result existed only during the call. Outside, the name was never bound, so reading it raises NameError.

Key idea Each call gets a fresh set of local names. Two calls to the same function do not share their locals.

2LEGB: the lookup order

When Python sees a name, it searches four scopes in order: Local, Enclosing, Global, Built-in. It stops at the first match. 

message = "global"

def show():
    print(message)     # finds the global

show()                 # global

A function can read a global name without any special syntax. To rebind one, you must declare global — and you usually should not, because it makes code harder to follow.

3Default and keyword arguments

A parameter can have a default, used when the caller omits it. And any argument can be passed by keyword, which makes calls readable. 

def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

greet("Ada")                       # Hello, Ada!
greet("Ada", "Hi")                 # Hi, Ada!
greet("Ada", greeting="Hey")       # Hey, Ada!

Parameters with defaults must come after parameters without them. Keyword arguments let you skip the ones you do not care about.

4The mutable default trap

A default value is evaluated once, when the function is defined — not on each call. That is harmless for numbers and strings, but dangerous for lists. 

def add_item(item, items=[]):     # BAD
    items.append(item)
    return items

add_item("a")     # ["a"]
add_item("b")     # ["a", "b"]  — the same list again!

The fix is to use None as the default and create a fresh list inside the function. 

def add_item(item, items=None):   # GOOD
    if items is None:
        items = []
    items.append(item)
    return items
Common trap Never use a mutable value — list, dict, set — as a default argument. Use None and build the value inside the function.
