Lesson 06 · Control flow

Making decisions

So far every line has run. Real programs choose. This lesson introduces if, elif and else, the comparison operators that feed them, and the indentation rule that keeps Python readable.

Time ~13 min Win Branch on a condition with if / elif / else Mission link Decisions are the first half of control flow

1Conditions are just values

A condition is an expression that produces True or False. Comparison operators build them. 

3 > 2          # True
3 == 3         # True   — equality
3 != 4         # True   — not equal
3 >= 4         # False
"a" < "b"      # True   — strings compare alphabetically

Notice the double equals. A single = is assignment; a double == is comparison. Mixing them up is the single most common beginner bug.

Key idea = binds a name. == asks a question. They are different operators and Python will not let you swap them.

2if, elif, else

An if statement runs a block only when its condition is true. elif adds another test, and else catches everything left over. Python checks them in order and runs the first match only. 

score = 72
if score >= 90:
    grade = "A"
elif score >= 70:
    grade = "B"
else:
    grade = "C"
print(grade)      # B

The colon ends the condition, and the indented block is what runs. Python uses indentation instead of braces, so the whitespace is part of the syntax, not decoration.

3Combining conditions

The operators and, or and not combine conditions. and needs both sides true; or needs at least one; not flips a value. 

age = 25
has_ticket = True
if age >= 18 and has_ticket:
    print("Welcome")

if not has_ticket:
    print("Buy a ticket first")

Python short-circuits: in a and b, if a is false, b is never evaluated. That matters when b is expensive or could fail.

4Truthiness

You do not always need a comparison. Any value can be used as a condition, and Python decides whether it is truthy or falsy. 

if []:            # falsy — empty list
if "hello":       # truthy — non-empty string
if 0:             # falsy — zero
if None:          # falsy — None
Common trap if x: is not the same as if x is not None:. When 0 or "" are valid values, test for None explicitly.
