Lesson 02 · Defining

Calling a function

A definition is a promise; a call is the promise being kept. This lesson is about what actually happens at the moment of a call — where the program goes, and where it comes back to.

Time ~10 min Win Predict the order of a define-and-call script Mission link Know when work runs

1Definition is not execution

The single most common beginner surprise is that a def line does nothing visible. Python reads the definition, binds the name, and moves on. The body sits there, waiting. 

def greet():
    print("Hello")

print("before")
greet()
print("after")

That prints before, then Hello, then after. The definition line produced no output at all — it only made the name greet available for the two lines that follow.

2Where the program goes

A call is a jump. When Python reaches greet(), it leaves the current line, runs the whole body, and then comes back to the line after the call. That place is the call site.

This is why a function can be called from many places: each call site is a different "return address". The body does not know or care who called it — it just runs, and control comes back to whoever asked.

3Calling many times

Because a call is just a jump, you can call the same function as often as you like. Each call runs the body from the top, fresh. 

def cheer():
    print("Go!")

cheer()
cheer()
cheer()

Three calls, three lines of output. The body was written once. This is the reuse that a loop cannot give you, because the calls can be scattered anywhere in the program — not just repeated in one spot.

Key idea A call is a jump out and a jump back. The body runs, then control returns to the line after the call — the call site.
