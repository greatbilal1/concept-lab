Splitting a program

Everything in this course has been building to one move: take a long script and break it into named pieces, each doing one job. This lesson is that move, done on a real program.

Time ~12 min Win Split a script into functions Mission link Make a program you can change

1The long script

Here is a program that works. It reads a list of scores, works out the average, and prints a report. It is also a wall of statements with no names. 

scores = [88, 92, 79, 95, 61]

total = 0
for s in scores:
    total = total + s
average = total / len(scores)

print("Scores:", scores)
print("Average:", average)
if average >= 70:
    print("Result: pass")
else:
    print("Result: fail")

Nothing here is wrong. But if you want to reuse the average, or test the pass rule, or change the report format, you have to cut into the middle of the script.

2One job per function

Single responsibility means each function does one thing, and its name says what that thing is. Read the script above and ask: what are the separate jobs?

Three jobs: compute the average, decide the result, print the report. Each one becomes a function. The script at the bottom becomes three calls. 

def average(numbers):
    """Return the mean of a list of numbers."""
    return sum(numbers) / len(numbers)

def result(avg):
    """Return 'pass' or 'fail' for an average."""
    return "pass" if avg >= 70 else "fail"

def report(scores):
    """Print a report for a list of scores."""
    avg = average(scores)
    print("Scores:", scores)
    print("Average:", avg)
    print("Result:", result(avg))

report([88, 92, 79, 95, 61])

The behaviour is identical. But now each piece has a name, a contract, and a place to be tested on its own.

3Decomposition and refactoring

Decomposition is the act of breaking a problem into smaller pieces. Refactoring is changing the structure of code without changing what it does. This lesson is both: the output is the same, the shape is new.

The test of a good split is simple. Can you describe each function in one sentence without using the word "and"? If not, it is probably two functions wearing one name.

Key idea Split by job, not by line count. Each function should do one thing, be named for that thing, and be usable without reading the rest of the program.
