Lesson 08 · Scope & the stack

Scope: local and global

A name created inside a function lives inside that function. A name created at the top of the file lives everywhere. Knowing which is which is what stops a function from quietly changing the rest of your program.

Time ~10 min Win Tell local names from global ones Mission link Keep functions self-contained

1Names live in scopes

A scope is the region where a name can be seen. Names assigned inside a function are local to that call; names assigned at the top level of the file are global. 

count = 0            # global

def bump():
    count = 1        # local — a different name
    print(count)     # 1

bump()
print(count)         # 0 — the global never changed

The assignment inside bump created a brand-new local name. It shadowed the global for the duration of the call, then vanished. The global count was never touched.

2Reading out, writing in

A function can read a global name without any ceremony. But the moment it assigns to that name, Python treats it as local for the whole function. 

count = 0

def bump():
    print(count)     # reads the global: 0
    count = count + 1  # UnboundLocalError!

bump()

The error is confusing until you know the rule: because there is an assignment somewhere in the body, count is local everywhere in that body — including the line that tries to read it before it exists.

3Shadowing

Shadowing is when a local name hides a global one of the same name. It is legal, and it is usually a mistake — the reader sees one name and gets two different values depending on where they are. 

size = 10

def scale(size):     # parameter shadows the global
    return size * 2

print(scale(3))      # 6
print(size)          # 10 — untouched

The fix is not global. The fix is a better name, or passing the value in as a parameter and returning the new value out. A function that only touches its own parameters and locals is a function you can trust anywhere.

Watch out Avoid global in new code. If a function needs to change something, pass it in and return the new value. Globals make a function's effect invisible from its call site.
