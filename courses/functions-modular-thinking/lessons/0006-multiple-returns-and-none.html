Lesson 06 · Returning

Multiple returns and None

A function can have more than one return, but only one of them ever runs. And a function with no return at all still hands something back. This lesson is about both halves of that surprise.

Time ~10 min Win Write a function with two exits Mission link Handle the empty case

1More than one exit

A function body can contain several return statements. They are not all used — the first one reached ends the function, and the rest are skipped. 

def sign(n):
    if n > 0:
        return "positive"
    if n < 0:
        return "negative"
    return "zero"

Exactly one of those three lines runs, depending on n. This is the early-exit shape from the control-flow course, now producing a value instead of printing one.

2Every path must return

If a function is supposed to produce a value, every path through its body must reach a return. Miss one, and that path hands back None — silently. 

def sign(n):
    if n > 0:
        return "positive"
    if n < 0:
        return "negative"
    # no return for zero!

print(sign(0))   # None

The bug is invisible until you call it with 0. This is why the final return with no condition is worth writing even when it feels redundant: it makes the last path explicit.

3The implicit None

A function whose body finishes without reaching any return hands back None. This is not an error — it is Python's value for "no value", and it is what every printing function has been returning all along. 

def show(x):
    print(x)

result = show(5)   # prints 5
print(result)      # None

So None is a signal. When a call evaluates to None, either the function is meant to be used for its side effect (like printing), or a path forgot to return. Learning to tell those two apart is a real skill.

Key idea Only the first return reached runs. A function with no return hands back None — so None is either a deliberate "no value" or a forgotten return.
