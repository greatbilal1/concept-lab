Lesson 05 · Returning

Returning a value

So far every function has printed. Printing shows a value to a human; returning hands it back to the program. This lesson is about the difference — and why it is the difference between a function you can build on and one you cannot.

Time ~10 min Win Write a function that returns a result Mission link Build on results

1Printing is a dead end

A function that prints has done its work and thrown the result away. The value appeared on screen and then vanished — the program cannot use it. 

def add(a, b):
    print(a + b)

add(2, 3)          # shows 5
total = add(2, 3)  # shows 5, but total is None

The second line is the problem. add(2, 3) printed 5, but the call itself evaluated to nothing useful. You cannot add that result to anything, because there is no result — only a side effect.

2Hand the value back

The return statement ends the function and hands a value back to the call site. The call expression then evaluates to that value, exactly as if you had written the value in its place. 

def add(a, b):
    return a + b

total = add(2, 3)   # total is 5
print(add(2, 3) * 10)  # 50 — the result is usable

Now the function is a value factory. It takes inputs, produces an output, and the rest of the program can do anything with that output: store it, print it, pass it to another function.

3Return ends the function

return does two things at once: it hands back a value, and it stops the function immediately. Any lines after it in the body do not run. 

def check(n):
    if n < 0:
        return "negative"
    return "not negative"
    print("never runs")   # unreachable

This is why return is the natural partner of the early exit you met in the control-flow course: as soon as the answer is known, you hand it back and leave.

Key idea print shows a value to a human. return hands a value to the program. Only a returned value can be used in further work.

✓ Your win for today

You have turned a function from something that shows a result into something that produces one. That is the change that lets functions compose: the output of one becomes the input of the next, and a program becomes a chain of named steps instead of a pile of prints.
