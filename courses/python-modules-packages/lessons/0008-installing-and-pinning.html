Lesson 08 · Environments

Installing and pinning dependencies

An environment you cannot rebuild is a one-off, not a project. This lesson is about the file that turns "it works on my machine" into "it works on every machine, identically".

Time ~10 min Win Reproduce an environment exactly Mission link Reproducibility is a feature

1pip installs, but does not remember

pip install requests fetches the newest compatible version and drops it into the active environment. It does not write anything down. Close the terminal, hand the project to a colleague, and they have no idea what to install.

The fix is a requirements file: a plain text list of what the project needs. It is not a Python file, not a config format — just names and versions, one per line. 

# requirements.txt
requests==2.32.3
pandas>=2.0,<3.0
pytest

2Reading a version specifier

The characters after a package name are a small language, and each one makes a different promise about what is acceptable:

The == form is called a pin. It is the only one that guarantees the same bytes on every machine, which is why applications pin and libraries usually do not.

Key idea A pin trades flexibility for reproducibility. For an app you want the same version everywhere; for a library you want to accept compatible upgrades.

3Freezing what you actually have

You rarely write a full requirements file by hand. You install what you need, then ask pip to report the exact set it resolved — including the transitive dependencies you never named: 

pip install requests pandas pytest
pip freeze > requirements.txt

# later, on a fresh machine:
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

pip freeze prints every installed package with an exact == version. That output is a complete, replayable recipe.

4Why transitive dependencies matter

You asked for requests. You got requests, urllib3, certifi, charset-normalizer and idna. Those are transitive dependencies — packages your package needs.

If you only list requests, a future install may resolve a different urllib3 and break you. Freezing captures the whole tree, which is why the generated file is longer than the list you typed.

Why this matters later Every CI job, every Docker build, every deployment starts with pip install -r requirements.txt. When a build fails six months from now, the pinned file is the only thing that tells you what changed. Treat it as part of the source, because it is.

✓ Your win for today

You can now capture an environment as a file and rebuild it byte-for-byte on another machine, and you can read any version specifier and say what it permits. That is the reproducibility half of this course done.

6Do this next

  1. In a scratch environment, install two packages, run pip freeze, and count how many lines appear versus how many you asked for.
  2. Delete the environment, recreate it, and install from the frozen file. Confirm pip freeze now matches exactly.
  3. Change one == to >= and reinstall. Notice that pip is now free to pick a newer version.
