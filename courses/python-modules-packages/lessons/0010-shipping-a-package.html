Shipping a package

Everything so far has been about importing code that lives on your disk. The last step is making your code installable by someone else — turning a folder into a distribution that pip install understands.

Time ~10 min Win Describe a package properly Mission link Code that others can actually use

1Source tree vs distribution

The folder you develop in is the source tree. What pip installs is a distribution — a built artifact, either a .whl (wheel) or a .tar.gz (sdist). They are not the same thing, and the gap between them is what packaging fills.

A wheel is a zip of the files that will be placed into site-packages, plus metadata describing the package. An sdist is the raw source, which pip builds into a wheel before installing.

2pyproject.toml: the description

Modern Python projects declare themselves in pyproject.toml. It is the single file that says what the package is called, what it needs, and how to build it. 

[project]
name = "myapp"
version = "0.1.0"
dependencies = ["requests>=2.28"]

[project.scripts]
myapp = "myapp.cli:main"

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

Three sections, three jobs. [project] is the metadata, [project.scripts] declares a command-line entry point, and [build-system] names the tool that turns the tree into a distribution.

Key idea pyproject.toml is the package's identity card. Everything a tool needs to know about your project is declared here, in one place.

3The entry point points at main

Look again at myapp = "myapp.cli:main". That line says: when someone runs the myapp command, import myapp.cli and call its main function.

This is exactly the main() function from lesson 6. The guard made the file runnable; the entry point makes the function installable as a command. The two ideas meet here.

4Build, then install

With the description in place, building is one command, and the result is a file you can hand to anyone: 

python -m build
# dist/myapp-0.1.0-py3-none-any.whl
# dist/myapp-0.1.0.tar.gz

pip install dist/myapp-0.1.0-py3-none-any.whl

The wheel filename encodes the package name, version, Python version and platform. py3-none-any means "any Python 3, no compiled code, any platform" — the common case for pure-Python packages.

Why this matters later Every library you have ever installed went through this exact pipeline. When you publish your own, the same pip install that fetched requests will fetch yours. That is the last mile of this course: your code, importable by strangers.

✓ Your win for today

You can now describe a package in pyproject.toml, build it into a wheel, and explain how a console command is wired to a function. That is the whole course: a file, a package, an environment, and a distribution.

6Do this next

  1. Write a minimal pyproject.toml for a package you already have and run python -m build. Inspect the wheel with unzip -l.
  2. Add a [project.scripts] entry pointing at a main function, install the wheel, and run the command.
  3. Install your own wheel into a fresh environment and import it. You have just shipped a package.
