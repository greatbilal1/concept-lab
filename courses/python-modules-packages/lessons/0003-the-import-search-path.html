Where Python looks for modules

"ModuleNotFoundError" is the most common error in Python, and it is almost never about the module. It is about the search. This lesson shows you the list Python walks, in order, and why your file is not on it.

Time ~10 min Win Diagnose any import error Mission link Debugging beats guessing

1The search is a list, not a guess

When you write import helpers, Python does not scan your disk. It walks an ordered list of directories called sys.path, left to right, and stops at the first match. If nothing matches, you get ModuleNotFoundError.

You can print that list at any time. It is the single most useful debugging command in this whole course: 

import sys
for p in sys.path:
    print(p)

2What is on the list, in order

The list is built at startup, and the order is the whole story. Earlier entries win. Here is what you will typically see:

The first entry is the one that surprises people. When you run python main.py, the directory containing main.py is placed at the front of the path. That is why a script can import its neighbours with no configuration at all.

Key idea The first match wins. A file named json.py sitting next to your script will beat the standard library's json, because your directory is earlier in the list.

Here is the same import traced through the path, entry by entry. Notice that the search stops the moment it finds a match — later entries are never checked.

4The cache sits in front of the path

There is one more layer. Before Python touches sys.path at all, it checks sys.modules — a dictionary of everything already imported in this process. If the name is there, the search never happens.

This is why editing a module and re-running an import inside a long-lived process (a notebook, a REPL, a server) does not pick up your change. The cache is holding the old object. Restart the process, or use importlib.reload.

Why this matters later Every "it works in my terminal but not in the test runner" bug is a sys.path difference. Every "my edit did nothing" bug is the module cache. Knowing these two mechanisms turns a class of mysterious failures into a two-line check.

6Do this next

  1. Run python -c "import sys; print('\n'.join(sys.path))" and identify which entry is your current directory.
  2. Create a file called random.py next to a script that imports random. Watch the standard library lose. Then delete it.
  3. In a REPL, import a module, edit the file on disk, and import it again. Confirm nothing changed, then try importlib.reload.
