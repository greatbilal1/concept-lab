Packages and __init__.py

One module is a file. A hundred modules need a shape. A package is how Python gives a folder of files a single importable name — and the dotted path is how you address anything inside it.

Time ~10 min Win Turn a folder into a package Mission link Structure is what makes scale possible

1A folder becomes a name

You already know that a file can be imported. A package extends that idea one level up: a directory of modules that Python treats as a single importable unit. The directory's name becomes the first part of a dotted path. 

myapp/
  __init__.py
  helpers.py
  report.py

# from anywhere on the path:
import myapp.helpers
from myapp.report import build

myapp is the package. myapp.helpers is a module inside the package. The dot is the same attribute access you learned in lesson 1 — it just walks through a directory now.

2What __init__.py is for

The file __init__.py is what marks a directory as a regular package. It runs the first time the package is imported — exactly like a module's top-level code, because that is what it is.

It is allowed to be empty, and for a long time "empty __init__.py" was the standard advice. Modern practice is to use it deliberately: re-export the names you want callers to use, so the package presents a clean front door.

Key idea __init__.py is the package's public face. What you import there is what callers can reach without knowing your internal file layout.

3Re-exporting: the front door

Suppose myapp/helpers.py defines clean. Without any __init__.py content, callers must write from myapp.helpers import clean — they have to know your file layout. Add one line to __init__.py and that changes: 

# myapp/__init__.py
from .helpers import clean

# callers can now write:
from myapp import clean

You have just made helpers.py an implementation detail. You can rename it, split it, or move it, and callers never notice. That is the whole value of a package boundary.

4Subpackages: nesting all the way down

Packages can contain packages. A directory inside a package with its own __init__.py is a subpackage, and the dotted path simply grows:

myapp.data.loaders is a module, three levels deep. Nothing new is happening — it is the same rule applied recursively. This is how libraries like django.contrib.auth are built.

Why this matters later Every library you install is a package tree. When you read from sklearn.linear_model import LogisticRegression, you are reading a dotted path through a package, a subpackage, and a module. You now know exactly what each dot means.

  1. Take three related modules and put them in a folder with an __init__.py. Import them by dotted path.
  2. Add a re-export to __init__.py and change your call sites to use the short form. Notice how the file layout disappears from the caller.
  3. Add a print() to __init__.py and import two different submodules. Confirm it prints exactly once.
