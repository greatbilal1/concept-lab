A module is just a file

You have been writing one file at a time. The moment a program grows past a screenful, that stops working — and the fix is not a new language feature. It is a file. This lesson shows you that "module" is a fancy word for something you already know how to make.

Time ~10 min Win Split one file into two Mission link The unit every Python project is built from

1The problem with one big file

Imagine a script that reads a CSV, cleans the rows, computes a summary, writes a report, and emails it. That is five jobs in one file. It works — until you want to reuse the cleaning step somewhere else, or test the summary without sending an email, or find the bug that only happens on Tuesdays.

The fix is the oldest one in programming: put related code in its own file. Python gives that idea a name. A file of Python code that other files can load is called a module.

Key idea A module is not a special kind of file. It is any .py file that something else imports. The word describes a role, not a format.

When you write import helpers, Python does three things, in order:

The second step is the one people miss. Importing a module runs its top-level code — every statement not inside a function or class. That is why a module with a stray print() at the top prints the moment you import it.

3Names travel with the module

Everything defined at the top level of a module — functions, classes, constants — becomes an attribute of the module object. If helpers.py defines clean_row, then after import helpers you reach it as helpers.clean_row.

That dot is not decoration. It is the whole point: the module name is a namespace, a prefix that keeps your names from colliding with everyone else's. Two modules can both define clean and nothing breaks, because one is helpers.clean and the other is csv_tools.clean.

Why this matters later Every package, every library, every framework you will ever install is built from this one move: a file, imported by name, exposing its top-level names as attributes. Once you see it here, you will see it everywhere.

4Split a file, right now

Take a script with two functions and a constant. Move the reusable parts into helpers.py and import them back: 

# helpers.py
TAX_RATE = 0.2

def with_tax(price):
    return price * (1 + TAX_RATE)

# main.py
import helpers

print(helpers.with_tax(50))   # 60.0
print(helpers.TAX_RATE)       # 0.2

Nothing was rewritten. The code moved, and a name was bound. That is the entire operation, and it scales to a hundred files without changing shape.

✓ Your win for today

You can now take a single-file script and split it into a module plus a caller, and you know exactly what happens when Python executes the import. That is the foundation the next nine lessons stand on.

6Do this next

  1. Take any script you have written with more than one function. Move the reusable functions into a second file and import them back.
  2. Add a print("loading helpers") at the top of the module and import it twice. Notice it prints once — the module cache is doing its job.
  3. Deliberately break it: import a module that does not exist and read the ModuleNotFoundError message carefully. You will meet it again.
