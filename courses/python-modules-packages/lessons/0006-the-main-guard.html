The __main__ guard

A file can be two things at once: a library other code imports, and a program you run. The __main__ guard is the one line that lets it be both without the two roles interfering.

Time ~10 min Win Make a file importable and runnable Mission link One file, two honest jobs

1The problem: import runs everything

You learned in lesson 1 that importing a module runs its top-level code. That is fine until the top-level code is a program — a print, a main() call, a network request. Now importing the file to reuse one function also fires the whole script. 

# report.py
def build(rows):
    return {"count": len(rows)}

print(build([1, 2, 3]))   # runs on import. bad.

Import report from anywhere and you get a stray {"count": 3} in your output. The fix is to make that line conditional.

2__name__ tells you how you were loaded

Every module has a built-in variable called __name__. Its value depends entirely on how the file was reached:

That is the entire mechanism. When you run a file directly, Python sets its __name__ to the string "__main__". When you import it, Python sets __name__ to the module's dotted path. One variable, two values, and you can branch on it.

Key idea __name__ is not a flag you set. It is a fact Python reports about how this file entered the program.

3The guard, line by line

The idiom is a single if that reads almost like English: "if this file is the main program, run it". 

def build(rows):
    return {"count": len(rows)}

def main():
    print(build([1, 2, 3]))

if __name__ == "__main__":
    main()

Now import report defines build and main and stops. Running python report.py defines them and then calls main(). Same file, two behaviours, no conflict.

4Why the main() function matters

You could put the program directly inside the if block. Wrapping it in a main() function is better for three reasons:

The last one is the quiet winner. A main() function can be called from a test, from another script, or from a console-script entry point. Code buried in an if block can only be run one way.

Why this matters later Every command-line tool you will ever write uses this shape. Every package that ships a CLI uses it. When you get to packaging in lesson 10, the entry point you declare will point at exactly this main function.

✓ Your win for today

You can now write a file that is a clean library when imported and a working program when run, and you can explain the mechanism in one sentence. That is the difference between a script and a module.

6Do this next

  1. Take a script with a top-level print and wrap the program in a main() plus the guard. Import it and confirm silence.
  2. Add print(__name__) at the top of a file. Run it directly, then import it. Watch the value change.
  3. Write a test that imports your module and calls main() directly. Notice that this is only possible because the code is in a function.
