Lesson 05 · The core moves

Algorithms

Decomposition, patterns and abstraction are thinking. An algorithm is the thinking written down — as steps so clear that a machine could follow them without asking a single question.

Time ~10 min Win You can write and trace an unambiguous set of steps Mission link Move 4 of six — the output of the first three

1Four rules an algorithm must obey

An algorithm is a finite, ordered set of unambiguous steps that turns an input into the required output. That definition is dense, so let us unpack it — each word is doing work.

Miss any one of these and you do not have an algorithm. A recipe that says "cook until done" is not finite or unambiguous. A list of steps that never ends is not an algorithm at all.

Key idea The test of an algorithm is not "does it look right?" It is: could a machine with no common sense follow this and get the right answer?

2Order is not decoration

Steps run in the order written, and changing the order changes the result. This is the single most common source of bugs in the world. 

1. put bread in toaster
2. set toaster to 3
3. press the lever down
4. wait for the toast to pop
5. take the toast out

Move step 5 to the top and the algorithm is nonsense. Move step 2 after step 3 and the toast burns. The steps are the same; the sequence is what makes it work.

3Two shapes that cover almost everything

Most algorithms are built from just two extra shapes on top of plain sequence. Selection chooses between paths based on a condition. Iteration repeats a group of steps until a condition is met. 

if the bread is stale:
    use the fresh loaf
else:
    use the loaf on the counter

repeat until the toast is golden:
    wait 20 seconds
    check the colour

That is the whole vocabulary. Sequence, selection, iteration — and with those three you can describe any procedure a computer can carry out. Notice that iteration is where Lesson 3's patterns finally get used: a repeated step becomes a loop.

Common mistake Writing steps that assume the reader knows what you meant. "Add the usual amount of milk" is not a step — it is a memory test. Every step must be something the executor can do without asking.

4Trace it before you trust it

You cannot tell whether an algorithm is correct by reading it. You have to trace it: pick an input, walk through the steps by hand, and write down the state after each one. If the state ever surprises you, you have found a bug before it existed.

Tracing is also how you find the case that breaks it. Try the empty input, the zero, the largest value — the edge cases. Algorithms almost always fail at the edges, and tracing is the cheapest place to catch that.

✓ Your win for today

You wrote a set of steps that a machine could follow without asking questions, used selection and iteration to handle choices and repetition, and traced it by hand to check it actually works.

5Do this next

  1. Write the algorithm for making your usual breakfast, in numbered steps.
  2. Add one selection and one iteration to it.
  3. Trace it with an edge case — no bread, or no time.
