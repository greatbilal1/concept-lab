# Mission: Programming & Computational Thinking

## Why

Most people learn to program by memorising syntax. That works until the problem
changes shape — then the syntax is useless, because the hard part was never the
syntax. The hard part is *thinking*: turning a messy real-world situation into
something precise enough that a machine can carry it out.

This course teaches that thinking first, before any language. It is the layer
that every later programming course assumes you already have.

## Success looks like

By the end of this course, a beginner should be able to:

- Take a vague, real-world problem and **decompose** it into smaller problems
  that can each be solved on their own.
- **Recognise patterns** — repetition, similarity and reusable structure — and
  use them to avoid solving the same problem twice.
- **Choose an abstraction**: decide which details matter for the problem at hand
  and which can be safely hidden.
- **Express a solution as an algorithm** — a precise, ordered sequence of steps
  with a clear start, a clear end, and no ambiguity.
- **Combine all six** to analyse and design a solution to a problem they have
  never seen before.
- **Evaluate** a solution against named criteria — correctness, efficiency,
  clarity, simplicity — and decide whether to keep it or refine it.
- **Generalise** a solution from one case to a whole family of cases, and know
  where that family ends.
- Explain *why* each of the six ideas exists, not just what it is called.

## Constraints

- **Audience:** absolute beginners. No prior programming knowledge is assumed.
- **Level:** beginner. Examples start in the physical world (sandwiches, trips,
  routines) and only later move toward programming-style examples.
- **Platform:** the existing Concept Lab course system. No new runtime, no new
  navigation, no new visual language.
- **Length:** 8 lessons. Each lesson must earn its place; do not pad.

## Out of scope

- Any specific programming language's syntax.
- Writing or running real code (the `lab` widget is used only where it genuinely
  helps, and only with the tiny built-in interpreter).
- Data structures, complexity analysis, or formal algorithm design — those are
  later courses (`data-structures`, `algorithms-problem-solving`, `big-o-complexity`).
- Mathematical formalism. This is a thinking course, not a maths course.
