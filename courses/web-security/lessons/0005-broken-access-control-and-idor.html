Broken Access Control and IDOR (Insecure Direct Object References)

The #1 web vulnerability: Insecure Direct Object References (IDOR), parameter tampering, horizontal vs vertical privilege escalation, and tenancy checks.

Time ~10 min Win You know how to diagnose, exploit, and prevent Broken Access Control and IDOR vulnerabilities. Mission link Mastering broken access control and idor (insecure direct object references) across modern software engineering

1Core principles of Broken Access Control and IDOR (Insecure Direct Object References)

You log into your medical portal. The URL reads: `https://clinic.com/api/records/8492`. You change the URL to `https://clinic.com/api/records/8493`, hit enter, and see another patient's confidential medical records. This is an Insecure Direct Object Reference (IDOR), and it is the single most common vulnerability discovered in enterprise web penetration tests.

Key idea The #1 web vulnerability: Insecure Direct Object References (IDOR), parameter tampering, horizontal vs vertical privilege escalation, and tenancy checks.

2Horizontal vs Vertical Privilege Escalation

Types of Broken Access Control:

3The Mandatory Ownership Check

  • Horizontal Privilege Escalation (IDOR): User A accesses records belonging to User B at the same permission level (e.g. Customer viewing another customer's invoice).
  • Vertical Privilege Escalation: A regular user performs actions reserved for administrators (e.g. sending a request to `POST /api/admin/delete_user`).
  • Missing Function-Level Access Control: Hiding a button in the UI, but leaving the underlying API endpoint completely unprotected against direct HTTP requests.
# VULNERABLE CODE (IDOR): 
@app.get("/api/invoices/{invoice_id}")
async def get_invoice(invoice_id: int, current_user: User = Depends(get_current_user)):
    # BUGS: Fetches invoice by ID directly without checking who owns it!
    return await db.invoices.find(invoice_id)

# SECURE CODE (Enforcing Ownership & Tenant Scoping):
@app.get("/api/invoices/{invoice_id}")
async def get_invoice(invoice_id: int, current_user: User = Depends(get_current_user)):
    invoice = await db.invoices.find(invoice_id)
    # Mandatory Authorization Ownership Gate:
    if not invoice or invoice.tenant_id != current_user.tenant_id:
        raise HTTPException(status_code=404, detail="Invoice not found")
    return invoice

The 404 Obfuscation Rule: When unauthorized access is attempted, return 404 Not Found rather than 403 Forbidden. Returning 403 confirms to an attacker that the target record ID actually exists.
