1Core principles of Secure API Design: Rate Limiting, Input Validation, and JWT Security

Modern web and mobile applications are driven by APIs. If your web frontend has robust security but your underlying REST API accepts unvalidated payloads, lacks rate limits, or misconfigures JWT tokens, your application is completely wide open.

3The Infamous 'none' Algorithm Attack

  • 1. Strict Schema Input Validation (Pydantic / Zod): Never accept raw dictionaries or unvalidated JSON. Enforce types, string length bounds, and regex patterns: username: str = Field(min_length=3, max_length=30, pattern=r"^[a-zA-Z0-9_]+$").
  • 2. Distributed API Rate Limiting: Enforce strict per-IP and per-user Token Bucket rate limits in Redis on authentication endpoints (`/login`, `/reset-password`) to defeat brute-force and credential stuffing bots.
  • 3. JWT Security & The 'None' Algorithm Attack: Verify the cryptographic signature on every request! Explicitly specify allowed algorithms: jwt.decode(token, SECRET, algorithms=["HS256"]) to prevent the infamous 'none' algorithm bypass attack!
# The Secure JWT Verification Pattern in Python:
ALLOWED_ALGORITHMS = ["HS256"] # Explicitly forbid 'none'!

def verify_user_jwt(token: str) -> dict:
    try:
        # Cryptographically verifies signature, expiration (exp), and algorithm:
        payload = jwt.decode(
            token,
            JWT_SECRET_KEY,
            algorithms=ALLOWED_ALGORITHMS,
            options={"require": ["exp", "sub", "tenant_id"]}
        )
        return payload
    except jwt.ExpiredSignatureError:
        raise HTTPException(401, "Session expired. Please log in again.")
    except jwt.InvalidTokenError:
        raise HTTPException(401, "Invalid or tampered authentication token!")

The JWT Rule: Always enforce token expiration (`exp`) and sign tokens using strong cryptographic secrets. Never transmit sensitive PII in unencrypted JWT payloads.
