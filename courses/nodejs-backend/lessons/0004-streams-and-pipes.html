Streams & Piping Large Datasets

Never load gigabyte files into memory at once. Streams process data chunk-by-chunk with automatic backpressure control.

Time ~10 min Win Pipe data efficiently using stream.pipeline and manage backpressure across read and write operations Mission link Prevent Out-Of-Memory (OOM) crashes when handling large file uploads and data exports

1The problem with buffering everything

If a client uploads a 2GB video file and your server runs await fs.readFile(), Node.js attempts to allocate a 2GB contiguous buffer in RAM. If five clients upload simultaneously, the server crashes with JavaScript heap out of memory.

Streams solve this by processing data in manageable chunks (typically 64KB). Data flows from the source (Readable) to the destination (Writable) continuously, keeping memory usage constant regardless of file size.

Key idea Streams process data chunk by chunk, enabling constant memory usage even when handling gigabytes of data.

2The four stream types & pipeline

Node.js defines four fundamental stream types:

  • Readable: Source of data (e.g. fs.createReadStream, HTTP incoming request).
  • Writable: Destination for data (e.g. fs.createWriteStream, HTTP response).
  • Duplex: Both readable and writable (e.g. TCP net socket).
  • Transform: Duplex stream that modifies data as it passes through (e.g. zlib.createGzip()).

Always use the promise-based stream/promises.pipeline() helper: it handles errors, cleans up file descriptors, and manages backpressure automatically.
