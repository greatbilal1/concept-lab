Lesson 02 · The Node.js Runtime & Architecture

Modules: CommonJS and ECMAScript Modules

Node.js supports both historical CommonJS (require) and standard ECMAScript Modules (import). Learn how they interoperate.

Time ~10 min Win Configure package.json for ESM and navigate import/export interoperability smoothly Mission link Modernize dependencies and prevent module loading syntax errors in server applications

1Two module systems under one roof

For years, Node.js exclusively used CommonJS (require() and module.exports). In CommonJS, modules load synchronously at runtime. Variable exports are copied by value or reference at the moment of evaluation.

Modern JavaScript uses ECMAScript Modules (ESM) (import and export). ESM is static: imports are parsed and linked before code executes, enabling tree-shaking, static analysis, and top-level await.

Key idea CommonJS loads synchronously at runtime; ESM resolves statically ahead of execution.

2Configuring ESM in package.json

To enable standard ESM across an entire project, set "type": "module" in your package.json. All .js files will then be treated as ES modules.

You can also use explicit file extensions: .mjs for ES Modules, and .cjs for CommonJS modules.
