Lesson 01 · The Node.js Runtime & Architecture

The Event Loop & Libuv Architecture

Node.js runs JavaScript on a single thread while delegating I/O to operating system kernels and libuv thread pools.

Time ~10 min Win Explain the event loop phases and trace how asynchronous operations execute across queues Mission link Prevent synchronous bottlenecks that freeze server throughput for all connected clients

1Single thread, non-blocking execution

In traditional server platforms, every incoming request spawns an OS thread or worker process. If a thread waits 50ms for a database query, that entire thread sits idle while consuming 1–2MB of stack RAM.

Node.js runs on a single main JavaScript thread. When an I/O operation (reading a disk file, querying a database, or contacting an external API) is initiated, Node.js hands the request to the OS kernel or libuv's background worker pool and immediately continues executing other JavaScript code.

Key idea JavaScript runs on one thread; all blocking I/O is offloaded asynchronously to the operating system and libuv.

2The six event loop phases

Libuv drives the event loop through distinct phases in a continuous circle:

  • Timers: Executes callbacks scheduled by setTimeout() and setInterval().
  • Pending callbacks: Executes I/O callbacks deferred from the previous cycle.
  • Idle / Prepare: Internal libuv coordination.
  • Poll: Retrieves new I/O events from the OS kernel; blocks here if idle.
  • Check: Executes callbacks scheduled by setImmediate().
  • Close callbacks: Executes socket and handle close callbacks (e.g. socket.on('close')).
