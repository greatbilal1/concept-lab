Optional and Union

Real values are often one of several types. Unions say so, and narrowing is how the checker keeps you safe when you use them.

Time ~12 min Win Write and narrow unions Mission link Honest types for messy data

1Union

A union says "any one of these types". The modern syntax uses a pipe: 

def parse(value: str | int) -> int:
    return int(value)

Before Python 3.10 you had to write Union[str, int]. Both still work, but the pipe form is shorter and reads better.

2Optional

Optional[X] is exactly X | None. It is not "this argument is optional" — that is what default values do. This is the single most misread name in Python typing. 

def find(name: str) -> Optional[str]:
    return table.get(name)

3Narrowing

When you check a union at runtime, the checker narrows it. After if x is not None:, the type of x inside the block is just str — the None branch is gone.

Narrowing is why unions are safe rather than annoying. The checker tracks which branch you are in and only complains when you use a value without ruling out the impossible cases.

4Reading unions out loud

A good habit: read str | None as "a string, or nothing". If that sentence does not describe your function honestly, the annotation is wrong.

Key idea Optional[X] means X | None, not "argument is optional". Narrowing is what makes unions usable.
