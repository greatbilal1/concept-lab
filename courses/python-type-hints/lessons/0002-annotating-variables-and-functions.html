Lesson 02 · Annotations

Annotating variables and functions

There are only three places to put an annotation. Learn them once and you can annotate any code you meet.

Time ~12 min Win Annotate any function correctly Mission link Signatures that explain themselves

1Parameters

A parameter annotation goes after the parameter name, separated by a colon: 

def area(width: float, height: float):
    return width * height

The annotation describes what the function accepts. It does not stop anyone passing something else — it tells the checker what you promised.

2Return types

The return annotation goes after an arrow, between the closing parenthesis and the colon: 

def area(width: float, height: float) -> float:
    return width * height

If a function returns nothing useful, annotate it -> None. That is not the same as leaving it blank: None is a promise that callers should not use the result.

3Variables

A variable annotation goes after the name. You can annotate without assigning, which is useful for declaring intent before a loop fills the value in: 

total: int = 0
names: list[str] = []
pending: str

Local variables rarely need annotations — the checker can usually infer them. Module-level and class-level variables benefit most, because they are the ones other files read.

4The three positions

Every annotation you will ever write sits in one of three positions: parameter, return, or variable. When you are unsure where a type belongs, ask which of those three you are looking at.

Key idea Parameter, return, variable. Three positions, one syntax. Everything else in this course is about which type expression you put there.
