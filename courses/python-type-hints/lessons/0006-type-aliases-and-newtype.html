Type aliases and NewType

Long type expressions get unreadable fast. Aliases name them, and NewType goes further by making two identical shapes distinct.

Time ~12 min Win Name and distinguish your types Mission link Types that read like domain words

1Type aliases

An alias is just a name for a type expression: 

UserId = int
Scores = dict[str, list[float]]

def top(scores: Scores) -> UserId:
    ...

The alias is not a new type — it is a nickname. The checker treats UserId and int as interchangeable, but your readers get a word from the domain instead of a raw built-in.

2NewType

NewType creates a genuinely distinct type from an existing one: 

UserId = NewType("UserId", int)
OrderId = NewType("OrderId", int)

def load(uid: UserId) -> None:
    ...

load(OrderId(7))   # checker error

At runtime UserId(7) is just 7 — no wrapper object, no cost. But the checker now refuses to let you pass an order id where a user id belongs. That is a whole class of bug eliminated for free.

3Literal and TypedDict

Two more shapes worth knowing. Literal restricts a value to an exact set, and TypedDict gives a dictionary fixed keys: 

Mode = Literal["read", "write"]

class Row(TypedDict):
    name: str
    age: int

Literal turns a stringly-typed parameter into a checked one. TypedDict turns a loose dictionary into a record with known fields.

4Alias or NewType?

Use an alias when you want a shorter, clearer name for the same thing. Use NewType when two things share a representation but must never be confused — ids, currencies, units.

Key idea An alias is a nickname. NewType is a distinct type with zero runtime cost. Choose based on whether confusion between the two would be a bug.
