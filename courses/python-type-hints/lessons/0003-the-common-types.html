Lesson 03 · Annotations

The common types

Ninety percent of annotations use a handful of names. Learn those first, and learn when Any is the honest answer.

Time ~10 min Win Reach for the right type name Mission link Vocabulary before syntax

1The scalars

Four built-in types cover most values you will annotate: 

name: str = "Ada"
age: int = 36
ratio: float = 0.75
active: bool = True

Note that bool is a subtype of int in Python — a quirk worth knowing, because it means a checker will accept True where an int is expected.

2None and NoneType

None has its own type, and in annotations you simply write None: 

def find(name: str) -> str | None:
    ...

That return annotation says "a string, or nothing found". It is the single most common annotation in real code, because most lookups can fail.

3Any versus object

Any switches checking off for that value. object is the opposite: it accepts every value but lets you do almost nothing with it without narrowing first.

Reach for Any when you genuinely cannot say more — for example at a boundary with untyped third-party code. Reach for object when you mean "anything, but I will check before using it".

4Choosing honestly

The temptation is to annotate everything as Any to silence the checker. That works, and it throws away the entire benefit. An Any is a small admission of defeat; use it deliberately, not by default.

Key idea Any disables checking. object keeps checking but demands narrowing. Prefer object when you can.
