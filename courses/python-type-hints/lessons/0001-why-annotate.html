Lesson 01 · Annotations

Why annotate?

Python does not need type hints to run. So why does almost every serious codebase have them? Because they are documentation that a machine can check.

Time ~10 min Win Know what annotations are for Mission link Intent that tools can verify

1What an annotation is

An annotation attaches a type expression to a name. It is written after a colon, and it changes nothing about how the code runs: 

def greet(name: str) -> str:
    return "Hello, " + name

count: int = 0

Python ignores those types at runtime. greet(42) still runs and still fails — just later, and with a less helpful message.

So the value is not enforcement. The value is that a checker can read the annotations and tell you about the mistake before you run anything.

2Three things annotations buy you

Annotations pay off in three distinct ways, and it is worth being able to name them:

Documentation that cannot drift out of date, because the checker complains when it does. Tooling — editors complete and navigate far better with types. And errors caught early, at the moment you write the code rather than the moment a user hits it.

3Gradual typing

Python's typing is gradual: annotated and unannotated code coexist. You can add hints to one function today and leave the rest alone. Nothing breaks, and the checker simply has less to work with in the unannotated parts.

Key idea Annotations are evidence for tools, not runtime enforcement. They make mistakes visible earlier, not impossible.

4What annotations are not

They are not validation. Passing a string where an int is annotated will not raise. They are not performance hints either — Python does not use them to optimise anything.

Why this matters later Every lesson after this one adds vocabulary to the same idea: write down what you mean, and let a tool check that you meant it. Once that clicks, the syntax is just detail.

6Do this next

  1. Annotate one function in a script you already have. Run it and confirm nothing changed.
  2. Call it with the wrong type and confirm Python does not complain.
  3. Write down, in one sentence, what you expected the annotation to do. Compare it to what it actually does.
