Color Systems & Semantic Palettes

Stop picking random hexadecimal colors. Master the 60-30-10 color balance rule, neutral scales, and semantic palettes.

Time ~10 min Win Build cohesive, accessible color systems using the 60-30-10 rule and semantic tokens Mission link Create balanced, professional interfaces that communicate intent with clarity

1The 60-30-10 rule of color distribution

A common mistake developers make is overusing their brand accent color: making backgrounds, cards, sidebars, headers, and text all bright blue. This causes visual exhaustion.

Borrow the classic 60-30-10 Rule from interior design:

  • 60% Dominant Neutral: Clean background canvas (white, off-white, or dark slate gray).
  • 30% Secondary Structure: Cards, sidebars, table headers, borders, and modal surfaces.
  • 10% Accent Intent: Reserved exclusively for interactive elements that demand attention (primary buttons, active tabs, links).
Key idea Keep 90% of your interface neutral; reserve your bright accent color for the 10% of elements that require action.

2Semantic color tokens

Never name CSS color variables after their appearance (like --blue: #2563eb;). What happens in dark mode or a rebrand? Always use semantic functional naming:

  • --color-primary: Brand action color (buttons, active states).
  • --color-success: Green (completed tasks, positive status).
  • --color-warning: Amber/Yellow (caution, expiring sessions).
  • --color-danger: Red (destructive actions: delete, critical errors).
  • --color-neutral: A ramp of 9 grays from light to dark for text, borders, and backgrounds.
