Interaction Feedback, Skeletons & Latency

Slow network responses make apps feel broken. Master skeleton screens, optimistic UI, and the psychological perception of speed.

Time ~10 min Win Design resilient loading states, skeleton screens, and optimistic UI to optimize perceived performance Mission link Make web applications feel fast, responsive, and trustworthy even over sluggish network connections

1The psychology of waiting: Latency thresholds

How fast does software need to feel? Decades of human-computer interaction (HCI) research define three critical time limits:

  • < 100 milliseconds: Perceived as instantaneous. Direct tactile feedback (button depression, hover states, toggles) must happen within 100ms.
  • 100ms to 1 second: The user notices a slight delay, but feels in control. A subtle loading spinner or progress bar is recommended.
  • > 1 second: The user's focus wavers. Without feedback, users assume the app crashed, click the button again, or close the tab.
  • > 10 seconds: Complete task abandonment.
Key idea Respond within 100ms for tactile feedback; provide immediate loading indicators for any operation exceeding 1 second.

2Optimistic UI and Empty States

To make apps feel blazing fast, use Optimistic UI: when a user clicks 'Like' or sends a chat message, update the screen immediately (assume success). Send the network request in the background. If the request fails, revert the state and display an error alert.

Never forget Empty States: when a user has no messages, orders, or saved items, do not display a barren blank screen. Use an illustration, friendly copy, and a clear primary button directing them how to get started.
