Secrets Management, Encryption & Policy-as-Code

Never commit database passwords or private keys in .tf files. Master secrets injection and Policy-as-Code guardrails.

Time ~10 min Win Keep credentials out of source code and state files, and enforce guardrails using Policy-as-Code Mission link Prevent leaked credentials and block insecure cloud configurations before deployment

1The rule of secrets in IaC

Hardcoding API tokens, database master passwords, or private keys directly in .tf files is one of the most common causes of enterprise security breaches.

Best practices for credentials in IaC:

  • Dynamic retrieval: Query secrets at runtime from a dedicated secrets manager (HashiCorp Vault, AWS Secrets Manager, Doppler).
  • Ephemeral credentials: Use short-lived OIDC (OpenID Connect) tokens in CI/CD rather than permanent IAM user access keys.
  • Sensitive markings: Mark variables and outputs with sensitive = true to prevent logging to stdout.
Key idea Never store credentials in code; retrieve them dynamically from secret stores or inject via short-lived OIDC.

2Policy as Code: Guardrails before apply

How do you prevent a junior engineer from accidentally creating a public S3 bucket or opening port 0.0.0.0/0 to the world? Relying on human peer review is fallible.

Policy as Code (using Open Policy Agent / Rego or HashiCorp Sentinel) evaluates rules against the terraform plan JSON output. If a policy is violated (e.g. "All storage volumes must be encrypted with KMS"), the CI pipeline automatically fails and blocks terraform apply.
