Lesson 02 · Terraform Primitives, Providers & State

Terraform Architecture & Workflow

Terraform connects to hundreds of clouds via plugins called providers. Learn the core syntax and CLI lifecycle.

Time ~10 min Win Write provider and resource blocks in HCL and navigate the init, plan, apply, and destroy workflow Mission link Provision cloud infrastructure cleanly using the industry-standard HashiCorp Configuration Language (HCL)

1The Terraform architecture: Core + Plugins

Terraform is divided into two parts:

  • Terraform Core: The open-source engine that parses HCL code, builds the directed acyclic graph (DAG) of resource dependencies, and computes plans.
  • Providers (Plugins): Independent binary executables (e.g. AWS, GCP, Azure, GitHub, Cloudflare, Kubernetes) that translate Terraform resource requests into real REST API calls.

When you run terraform init, Terraform inspects your provider requirements and downloads the matching provider binaries.

Key idea Terraform Core calculates dependencies and plans; Providers make the actual vendor-specific API calls.

2The four core workflow commands

Mastering Terraform requires mastering the four primary lifecycle commands:

  • terraform init: Downloads provider plugins and initializes the state backend.
  • terraform plan: Compares code against live state and displays a non-destructive preview of changes.
  • terraform apply: Prompts for confirmation and executes the changes against cloud APIs.
  • terraform destroy: Safely tears down and deletes all resources tracked by the state file.
