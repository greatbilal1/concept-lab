Lesson 06 · Drift Detection, CI/CD & Security

Plan Lifecycle & Drift Detection

What happens when an engineer modifies a security group manually in the cloud console? Learn how Terraform detects and reconciles drift.

Time ~10 min Win Detect infrastructure drift with terraform plan and safely reconcile discrepancies without downtime Mission link Maintain 100% fidelity between your Git codebase and live cloud deployments

1The three-way merge: Code vs State vs Reality

Whenever you execute terraform plan, Terraform performs a sophisticated three-way reconciliation:

  • Code: What your HCL manifests declare.
  • State: What Terraform previously recorded in terraform.tfstate.
  • Reality: The actual live resources queried right now via cloud APIs.

First, Terraform runs a refresh step, querying cloud APIs to update its in-memory view of Reality. It compares Reality to Code and calculates the exact surgical steps required to restore compliance.

Key idea Terraform plan refreshes live reality, compares it to declared code, and computes the restorative plan.

2Importing existing resources into Terraform

What if you have existing cloud resources created before you adopted Terraform? You use the import block (or terraform import command).

Importing attaches an existing cloud resource ID (e.g. i-0123456789abcdef0) to a declared resource block in your code, recording it in the state file without recreating it.
