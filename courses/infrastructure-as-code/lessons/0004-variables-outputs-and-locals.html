Variables, Outputs & Locals

Hardcoded values make code brittle. Use input variables for parameterization, local values for DRY logic, and outputs for exports.

Time ~10 min Win Parameterize Terraform code with typed input variables, compute locals, and export resource attributes via outputs Mission link Write flexible, parameterized configurations that deploy across dev, staging, and production effortlessly

1Input variables: Parameterizing code

Hardcoding values like region = "us-east-1" or instance_type = "t3.micro" makes configurations rigid and impossible to reuse across environments. Input variables act as function parameters for your infrastructure.

A variable declaration specifies its type (string, number, bool, list, map), a description, an optional default, and optional validation blocks with custom error messages.

Key idea Input variables parameterize infrastructure; always declare explicit types and descriptions.

2Locals and Output values

Two other primitives round out configuration flexibility:

  • Locals (local.name): Named expressions used to eliminate repetition (DRY) and compute complex values (e.g. combining environment and project name into standard tag conventions).
  • Outputs (output.name): Exposes values to the terminal user, other modules, or external tools via terraform output (e.g. database endpoint or load balancer DNS).
