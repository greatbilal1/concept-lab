Lesson 01 · IaC Philosophy & Declarative Infrastructure

Why IaC: Declarative vs Imperative

Manual cloud configuration creates untracked drift and outages. Learn how declarative code brings software engineering rigor to infrastructure.

Time ~10 min Win Contrast declarative vs imperative models and explain the consequences of configuration drift Mission link Prevent undocumented snowflake infrastructure and catastrophic cloud misconfigurations

1The failure of manual infrastructure

When an engineer provisions a cloud database by clicking through an AWS or Azure web dashboard, zero record of that action is stored in version control. Who made the change? Why was that subnet chosen? What was the previous setting?

This produces snowflake servers: unique systems that nobody understands and nobody dares touch. Infrastructure as Code (IaC) models all infrastructure as declarative source code stored in Git, reviewed via Pull Requests, and applied predictably.

Key idea IaC replaces manual console clicks with version-controlled, auditable, reproducible source code.

2Idempotence and configuration drift

A hallmark of quality IaC tools is idempotence: running terraform apply ten times in a row without code changes produces zero modifications after the first run.

When an administrator makes emergency manual edits directly in the web console, configuration drift occurs: the live cloud reality diverges from Git code. IaC tools detect this drift during the planning phase.

3Tracing declarative delta computation

Trace how a declarative engine computes only the necessary changes between live state and desired state.

Test your understanding of IaC concepts and declarative paradigms.
