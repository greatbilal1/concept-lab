Lesson 05 · Modules, Variables & Composition

Modules & Reusable Architecture Patterns

Do not copy-paste 300 lines of VPC code across 10 repositories. Package infrastructure into clean, reusable modules.

Time ~10 min Win Author reusable Terraform modules with inputs, outputs, and semantic versioning Mission link Standardize cloud infrastructure architecture across enterprise development teams

1What is a Terraform Module?

Any directory containing .tf files is technically a module (the root module). When you organize code into subdirectories and call them using a module "name" { source = "..." } block, you create a reusable child module.

Modules function like functions in programming languages: they accept input variables as arguments, provision resources internally, and return output values to the caller.

Key idea Modules package related resources into standardized, reusable infrastructure building blocks.

2Module sources: Local vs Remote vs Registry

The source argument specifies where Terraform fetches the module code:

  • Local paths: source = "./modules/database" (great for mono-repos).
  • Public Registry: source = "terraform-aws-modules/vpc/aws" with version = "5.0.0".
  • Private Git: source = "git::https://github.com/corp/tf-modules.git?ref=v1.2.0".

Always pin remote module sources to a specific tag or version to prevent unexpected breaking changes during deployment.
