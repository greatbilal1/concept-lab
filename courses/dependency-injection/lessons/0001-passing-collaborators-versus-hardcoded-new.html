Lesson 01 · Dependency Injection & IoC

Passing collaborators versus hardcoded 'new'

The root of all coupling: the 'new' keyword. Discover why hardcoding constructor calls inside classes freezes your architecture, and how passing arguments frees it.

Time ~10 min Win Replace hardcoded object instantiations with constructor parameter injection Mission link The foundational habit that unlocks all software testability and flexibility

1The problem with 'new'

Whenever you write this.mailer = new SmtpMailer(); inside a class, you have welded that class to a concrete implementation. You cannot test your class without sending real emails! You cannot switch from SMTP to SendGrid without modifying every single class that uses it.

Dependency Injection (DI) is simply the practice of passing that collaborator in from the outside: constructor(mailer) { this.mailer = mailer; }. Your class no longer knows or cares how the mailer was created; it simply uses the collaborator provided to it.

Key idea Never construct collaborators with 'new' inside business classes; pass them in from the outside.
