Lesson 05 · Containers & Lifecycles

Object lifecycles: transient, scoped, singleton

When should an object be created, and when should it die? Master the three fundamental DI lifecycles: Transient (new every time), Scoped (per request), and Singleton (forever).

Time ~10 min Win Select and configure appropriate object lifecycles in dependency injection containers Mission link Prevents memory leaks, stale state, and concurrency bugs in backend services

1The three lifecycle tiers

When an IoC container or dependency system creates an object, it must decide how long that instance should live. There are three standard Lifecycles:

1. Transient: A brand new instance is created every single time it is requested. 2. Scoped: Created once per bounded context (typically once per incoming HTTP request) and shared among all components handling that request. 3. Singleton: Created once when the server boots and shared globally across all requests for the entire life of the process.

Key idea Transient creates new every time; Scoped lives for one HTTP request; Singleton lives forever.
