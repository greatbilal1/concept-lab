1The test double taxonomy

Why do we inject dependencies? The greatest practical payoff is Testability. If a class receives its collaborators as arguments, we can substitute them during automated tests with Test Doubles.

Gerard Meszaros categorized test doubles into five distinct roles: Dummy (filler object), Stub (provides canned responses), Spy (records calls), Mock (verifies expected interactions), and Fake (working in-memory implementation, like an in-memory SQLite database or dictionary store).

Key idea Test doubles substitute real external dependencies in tests; DI makes substitution effortless.
