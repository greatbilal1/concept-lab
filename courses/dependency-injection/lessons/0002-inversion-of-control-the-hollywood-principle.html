Lesson 02 · Dependency Injection & IoC

Inversion of Control: the Hollywood Principle

Don't call us, we'll call you. Discover Inversion of Control (IoC): how frameworks and dependency containers reverse the flow of control in software systems.

Time ~10 min Win Explain Inversion of Control and the distinction between libraries and frameworks Mission link The architectural shift distinguishing modern extensible systems from traditional scripts

1The Hollywood Principle

In traditional procedural programming, your code is in charge: it creates objects, calls library functions, and controls the program execution from start to finish. You call the library.

Inversion of Control (IoC) flips this dynamic upside down. Coined as the Hollywood Principle ('Don't call us, we'll call you'), an IoC container or framework is in charge of the main control loop. You plug your components into the framework, and the framework calls your code when appropriate.

Key idea With a library, your code is in control; with Inversion of Control, the framework is in control.
