1Core principles of The JSON Repair Loop: Self-Correction with Error Feedback

Even with constrained decoding, real-world systems occasionally experience validation errors: a string was 101 characters when the limit was 100, an enum had an unexpected character, or custom business validation failed. In amateur software, this throws an unhandled exception. In professional systems, it triggers a JSON Repair Loop.

Key idea Automated error recovery: building self-healing JSON repair loops that feed Pydantic validation errors back to the model.

The Self-Healing Repair Protocol:

3Error Recovery Success Rate

  • 1. Attempt Parsing: The application attempts to validate the model's output using Pydantic: `Model.model_validate(json_data)`.
  • 2. Catch ValidationError: If validation fails, capture the exact Pydantic error details (field name, invalid value, expected type).
  • 3. Feedback Turn: Send an immediate follow-up message: 'Your previous output had validation errors: [Field 'severity' must be one of: 'low', 'high']. Please correct the JSON and return valid output.'
  • 4. Re-Validate: The model reads the error, understands its exact mistake, and emits corrected JSON in 1 turn!
# The Self-Healing JSON Repair Loop in Python:
for attempt in range(3):
    raw_response = call_llm(prompt)
    try:
        return MySchema.model_validate_json(raw_response)
    except ValidationError as err:
        if attempt == 2:
            raise  # Exhausted retries, fail safely
        # Feed error back to model for self-correction!
        prompt = f"""Your previous response failed validation:
{err.json()}
Correct the errors and return valid JSON matching the schema."""
