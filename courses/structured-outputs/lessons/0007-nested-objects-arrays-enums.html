1Core principles of Nested Objects, Arrays, and Enums in Output Schemas

Real enterprise data is rarely flat. A single customer order contains shipping addresses, billing addresses, lists of purchased line items, tax breakdowns, and payment status enums. To capture this complexity, engineers use Hierarchical Nested Schemas.

Key idea Authoring complex hierarchical schemas: nested sub-models, typed arrays, polymorphic unions, and categorical enums.

2Hierarchical Schema Architecture

Key patterns for complex schema composition in Pydantic v2:

3Nesting Depth Guideline

  • 1. Nested Child Models: Break complexity into reusable sub-models (`Address`, `LineItem`, `TaxDetails`) and compose them inside the top-level entity.
  • 2. Typed Array Collections: Use `list[ChildModel]` with `min_length` constraints: `items: list[LineItem] = Field(min_length=1)`.
  • 3. Enums for State: Use Python standard `Enum` or `Literal` for finite status fields: `status: OrderStatus = OrderStatus.PENDING`.
  • 4. Constrained Primitives: Use specialized types like `EmailStr`, `HttpUrl`, and `PositiveInt` to guarantee valid primitive formats.
# Complex Hierarchical Schema Composition:
from pydantic import BaseModel, Field, EmailStr
from typing import Literal

class LineItem(BaseModel):
    sku: str = Field(description="Product SKU")
    quantity: int = Field(gt=0, description="Quantity purchased")
    price_cents: int = Field(ge=0, description="Unit price in integer cents")

class CompleteOrder(BaseModel):
    order_id: str
    customer_email: EmailStr
    status: Literal["pending", "paid", "shipped", "cancelled"]
    items: list[LineItem] = Field(min_length=1, description="List of purchased items")
    subtotal_cents: int = Field(ge=0)

When compiled to JSON Schema, this provides a complete hierarchical blueprint that constrained decoding engines follow with mathematical precision.

Hierarchy Depth Limit: Keep nesting under 3-4 levels deep. Excessively deep nesting (8+ levels) strains model attention and increases decoding latency.
