2Pydantic v2 Schema Anatomy

Key rules for authoring agent-ready schemas in Pydantic v2:

3TypeScript Zod Equivalent

  • 1. Explicit Field Descriptions: Use `Field(description="...")`. The model reads these descriptions as instruction prompts for what that specific field should contain!
  • 2. Bounded Constraints: Use `gt`, `lt`, `min_length`, and `max_length` to constrain numbers and strings: `Field(ge=0, le=100)`.
  • 3. Explicit Literals & Enums: Never use raw `str` if only a fixed set of options is allowed. Use `Literal["low", "medium", "high"]` or standard Python `Enum`.
  • 4. Strict Schema Mode: Set `model_config = ConfigDict(strict=True, extra="forbid")` to prevent coercive casting or hallucinated keys.
# Production Pydantic v2 Schema for Structured Extraction:
from pydantic import BaseModel, Field, ConfigDict
from typing import Literal

class BugReportSchema(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")

    title: str = Field(description="Concise 5-10 word summary of the bug")
    severity: Literal["low", "medium", "high", "critical"] = Field(
        description="Impact of the bug on user operations"
    )
    affected_module: str = Field(description="Component path (e.g. auth, billing, api)")
    steps_to_reproduce: list[str] = Field(
        min_length=1, description="Numbered list of reproduction steps"
    )

Field Descriptions as Prompts: Field descriptions in your Pydantic model are micro-prompts! Write clear descriptions to guide the model on exactly how to populate each attribute.
