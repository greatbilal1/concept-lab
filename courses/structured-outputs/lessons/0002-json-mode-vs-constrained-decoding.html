1Core principles of JSON Mode vs Constrained Decoding (Grammar Sampling)

Historically, getting an LLM to return JSON was a battle of prompt hacks: 'Return JSON. Do not write text. Please!'. The evolution of structured output enforcement progressed across three distinct eras:

Key idea The evolution of structured generation: Prompting hints -> JSON Mode -> Grammar-Constrained Decoding (100% schema guarantee).

2The Structured Output Evolution

  • Era 1: Prompted JSON (Unreliable): Telling the model in text to output JSON. The model would still occasionally emit markdown fences or conversational preambles (85-90% reliability).
  • Era 2: JSON Mode (Semi-Constrained): Provider flags (e.g. `response_format={"type": "json_object"}`). Forces the model to emit syntactically valid JSON, but does not guarantee field names or types. The model could emit `{}` or `{"random_key": 123}`!
  • Era 3: Constrained Decoding / Structured Outputs (Guaranteed): Modern engines (OpenAI Structured Outputs, Outlines, Guidance, llama.cpp GBNF grammars). The model is constrained at the logit sampling level: any token that would violate the JSON Schema is masked to $-\infty$! 100% mathematical schema compliance!

3How Grammar Masking Works

# OpenAI Structured Outputs with Pydantic:
from pydantic import BaseModel

class UserProfile(BaseModel):
    name: str
    age: int
    roles: list[str]

# Enforces 100% schema guarantee via constrained decoding:
completion = client.beta.chat.completions.parse(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Extract user profile: Bob is 32, admin and editor"}],
    response_format=UserProfile # Guaranteed exact Pydantic instance!
)
user: UserProfile = completion.choices[0].message.parsed
print(user.name)  # "Bob" (Strictly typed, 0% parse failure risk!)

The Mathematical Guarantee: With constrained decoding, it is impossible for the model to emit invalid JSON, miss required fields, or invent unapproved keys. The grammar engine will not permit it to sample an illegal token!
