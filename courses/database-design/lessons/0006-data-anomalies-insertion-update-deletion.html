Lesson 06 · Normalization Forms & Anomalies

Data anomalies: insertion, update, deletion

What happens when bad design corrupts your business records? Discover the three classic database anomalies and how normalized schemas protect data integrity.

Time ~10 min Win Identify and eliminate insertion, update, and deletion anomalies in unnormalized tables Mission link Explains the concrete catastrophic consequences that normalization prevents

1The three classic anomalies

When a database schema is not normalized, it falls victim to three classic data anomalies: Update Anomaly (changing a customer address requires updating 50 rows; if one update fails, the database has contradictory addresses).

Insertion Anomaly (you cannot add a new course unless at least one student is enrolled). Deletion Anomaly (deleting the last student enrolled in a course accidentally erases the entire course from the database!).

Key idea Unnormalized schemas cause update contradictions, insertion blocks, and accidental data loss.

2The anomaly trio

Understand how conflating two entities into one table triggers all three anomalies.

3Tracing an update anomaly

Trace how updating a customer's address in an unnormalized table produces inconsistent data.

4Practice

Test your recall of database anomalies.

✓ Your win for today

You can spot data anomalies in flawed schemas and refactor them into safe, normalized architectures.

5Do this next

  1. Audit a spreadsheet and identify an update anomaly where data is repeated.
  2. Demonstrate a deletion anomaly by deleting a parent row in an unnormalized table.
  3. Refactor the table into two separate entities to eliminate all three anomalies.
