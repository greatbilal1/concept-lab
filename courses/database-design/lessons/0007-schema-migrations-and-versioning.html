Schema migrations and versioning

Code is versioned in git; how do you version a live database without losing data? Master evolutionary database migrations, up/down scripts, and non-blocking DDL.

Time ~10 min Win Design and execute reversible database schema migrations without downtime Mission link Ensures database schemas evolve safely across production deployments

1The problem of stateful migrations

If you break code, you can roll back your git commit in seconds. But a database is stateful: you cannot simply 'roll back' a table drop that deleted 5 million customer records.

Database changes must be managed via Schema Migrations: versioned, incremental, reversible scripts (like Alembic, Prisma, or Flyway) that transition database state from version N to N+1. Every migration has an up (apply change) and a down (revert change) script.

Key idea Database schemas evolve through incremental, versioned, reversible migration scripts.

Observe how migration tools track applied schema versions using a dedicated database table.

You can write reversible database migrations and evolve production schemas with zero user downtime.
