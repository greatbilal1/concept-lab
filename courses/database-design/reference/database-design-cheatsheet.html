1Cardinality Implementations

Foreign key placement patterns
-- 1:1 Relationship (Users & Profiles)
CREATE TABLE profiles (
  user_id INTEGER PRIMARY KEY REFERENCES users(id),
  bio TEXT
);

-- 1:N Relationship (Author & Books)
CREATE TABLE books (
  id SERIAL PRIMARY KEY,
  author_id INTEGER NOT NULL REFERENCES authors(id),
  title TEXT NOT NULL
);

See Lesson 02 — One-to-one and one-to-many relationships.

2Many-to-Many (N:M)

Junction table pattern
CREATE TABLE students (id SERIAL PRIMARY KEY, name TEXT);
CREATE TABLE courses (id SERIAL PRIMARY KEY, title TEXT);

-- Junction / Join Table
CREATE TABLE enrollments (
  student_id INTEGER REFERENCES students(id) ON DELETE CASCADE,
  course_id INTEGER REFERENCES courses(id) ON DELETE CASCADE,
  enrolled_at TIMESTAMP DEFAULT NOW(),
  PRIMARY KEY (student_id, course_id)
);

See Lesson 03 — Many-to-many relationships and junction tables.

3Normalization Checklist

1NF, 2NF, and 3NF rules
1NF: Atomic values only (no comma-separated lists); unique primary key
2NF: In 1NF + no partial dependencies (all non-keys depend on whole PK)
3NF: In 2NF + no transitive dependencies (non-keys depend ONLY on PK)
Rule of thumb: "Every attribute depends on the key, the whole key, and nothing but the key, so help me Codd."

See Lesson 05 — Third normal form (3NF) and transitive dependencies.

4Intentional Denormalization

Read optimization trade-offs
-- Denormalized cached counter
ALTER TABLE posts ADD COLUMN cached_comment_count INTEGER DEFAULT 0;

-- Maintenance via trigger or transaction:
-- Incremented on comment INSERT; decremented on comment DELETE.
-- Trade-off: Instant O(1) reads; write overhead and risk of desync.
