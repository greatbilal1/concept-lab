Lesson 05 · Objects & Collections

Objects, references, and properties

Objects are not copied; they are referenced. Discover the memory mechanics behind reference equality, property access, and shallow versus deep copying.

Time ~10 min Win Prevent accidental mutation bugs using immutability patterns and cloning Mission link Eliminates the single most common cause of unintended side-effect bugs

1Values versus references in memory

When you assign a primitive (like a number), JavaScript copies the value. When you assign an object, array, or function, JavaScript copies only the memory address reference.

If two variables point to the same object reference, mutating one variable mutates the other! This causes subtle bugs where modifying data in one component unexpectedly corrupts state in another.

Key idea Object variables hold memory references; assigning an object shares the reference, not a copy.

2Shallow copying versus deep copying

Understand why the spread operator ({...obj}) is only a shallow copy, leaving nested objects shared.

3Tracing object mutation bugs

Trace how a shallow copy leaves nested address objects linked between original and copy.

4Practice

Test your memory of object reference behavior.

✓ Your win for today

You can write pure functions that update object state without introducing accidental mutation side effects.
