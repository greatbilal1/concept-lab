Lesson 01 · Files

Files are streams of bytes

Everything you will do with data starts with one idea: a file is not a document, it is a stream of bytes with a position. Get that picture right and the rest of this course is detail.

Time ~10 min Win Open, read and close a file Mission link Data outlives the program

1A file is bytes on disk

When your program ends, its variables vanish. A file is how data survives that ending. On disk a file is just a named sequence of bytes — no structure, no types, no rows. Any meaning is something your program imposes when it reads.

Python gives you a file handle from open(). The handle is not the file; it is a connection to it, with a position that moves as you read.

2Open, read, close

The three-step shape is always the same, and the third step is the one people forget: 

f = open("notes.txt", "r")   # open
text = f.read()              # read
f.close()                    # close — releases the handle

Forgetting close() leaks a handle. On a small script you may never notice; in a long-running program you will run out of them. Lesson 3 shows the form that closes for you.

3The position moves

Reading is not a lookup — it is a walk. Each read advances the position, so a second read() returns what comes next, not the same text again.

This is why f.read() twice gives you the whole file and then an empty string. The handle is exhausted, not broken.

Key idea A file handle is a cursor over bytes. Reading moves the cursor forward; it never rewinds on its own.

4Text mode vs binary mode

open() defaults to text mode, which decodes bytes into str using an encoding. Binary mode gives you raw bytes with no decoding at all.

Use text mode for anything a human reads or writes. Use binary mode for images, archives, and any format whose bytes are not characters.

Why this matters later Every format in this course — JSON, CSV, plain text — is built on this one primitive. When a file "looks wrong", the cause is almost always the encoding or the mode, not the format.

✓ Your win for today

You can now open a file, read it, and close it, and you can explain why a second read returns nothing. That mental model — a cursor over bytes — is the foundation for everything that follows.

6Do this next

  1. Create a small text file and read it twice in one program. Confirm the second read is empty.
  2. Open the same file in binary mode and print the type of what you get back. Notice it is bytes, not str.
  3. Deliberately forget close() and read the docs on why it matters.
