A real data pipeline

Everything in this course now fits together into one shape: read, transform, write. This lesson builds that pipeline properly, with validation at the edges and a guarantee you can run it twice.

Time ~15 min Win Build a pipeline you can trust Mission link The whole course, working

1The three stages

Almost every data program is the same three stages. Naming them makes the code easier to reason about, test, and change:

Keeping them separate matters. If reading and transforming are tangled together, you cannot test the transform without a file on disk — and you cannot swap CSV for JSON without rewriting the logic.

2Read, transform, write

Here is the whole pipeline, using every tool from this course: 

import csv, json
from pathlib import Path

def read_rows(path):
    with open(path, newline="") as f:
        return list(csv.DictReader(f))

def transform(rows):
    out = []
    for r in rows:
        score = float(r["score"])          # CSV gives strings
        out.append({"name": r["name"], "score": score})
    return out

def write_json(rows, path):
    Path(path).parent.mkdir(parents=True, exist_ok=True)
    with open(path, "w") as f:
        json.dump(rows, f, indent=2, sort_keys=True)

rows = read_rows("in.csv")
write_json(transform(rows), "out/rows.json")

3Idempotency

A pipeline is idempotent when running it twice gives the same result as running it once. That sounds obvious and is easy to break: appending instead of overwriting, or accumulating into a global list, both destroy it.

The version above is idempotent because it reads fresh, builds a new list, and overwrites the output. Run it a hundred times and the file is identical.

Key idea Idempotency is what makes a pipeline safe to re-run after a failure. Without it, every retry makes the damage worse.

4Validate at the edges

Add validation where data enters and where it leaves. Inside, trust it: 

def read_rows(path):
    p = Path(path)
    if not p.exists():
        raise FileNotFoundError(f"missing input: {p}")
    with open(p, newline="") as f:
        rows = list(csv.DictReader(f))
    if not rows:
        raise ValueError("input has no data rows")
    return rows
Why this matters later This is the shape of every data tool you will write: a thin read, a pure transform, a thin write, and validation at both ends. Once you can build this, you can build the rest.
