Paths and the filesystem

"It works when I run it here" is almost always a path problem. This lesson is about naming files in a way that survives being run from somewhere else.

Time ~10 min Win Build paths that always resolve Mission link Code that runs anywhere

1Absolute vs relative

An absolute path starts from the root of the filesystem and means the same thing everywhere. A relative path is resolved against the current working directory — which is wherever the program was launched from, not where the script lives.

That gap is the bug. open("data.csv") works when you run the script from its own folder and fails the moment a scheduler or a test runner launches it from elsewhere.

2pathlib: paths as objects

The pathlib module gives you Path objects instead of strings. The / operator joins them, and the result is correct on every platform: 

from pathlib import Path

here = Path(__file__).parent      # the folder this script lives in
data = here / "data" / "rows.csv" # joined, not concatenated

print(data.exists())
print(data.read_text())

Path(__file__).parent is the key line. It anchors the path to the script, not to wherever you happened to be standing.

3Why string joining breaks

Building paths with + and "/" looks harmless and fails in three ways: a missing separator, a doubled separator, and the wrong separator on Windows.

Path handles all three. It also gives you exists(), mkdir(), suffix, stem and read_text() — the operations you would otherwise hand-roll.

Key idea Anchor paths to __file__, not to the working directory. A script should not care where it was launched from.

4Checking before you open

A path is a claim about the filesystem, and claims can be wrong. Check before you act: 

p = Path("config.json")
if not p.exists():
    raise FileNotFoundError(f"missing: {p}")

p.parent.mkdir(parents=True, exist_ok=True)  # ensure the folder
p.write_text("{}")

parents=True, exist_ok=True means "create the whole chain, and do not complain if it is already there". That pair is worth memorising.

Why this matters later Every pipeline in this course reads from and writes to paths. Getting the anchoring right once means the JSON and CSV lessons just work, wherever the code runs.

✓ Your win for today

You can now build paths that resolve correctly no matter where the program is launched, and you can check the filesystem before acting on it. That removes the most common "works on my machine" failure in data code.

6Do this next

  1. Write a script that opens a file with a relative path, then run it from a different directory. Watch it fail.
  2. Fix it with Path(__file__).parent and run it from anywhere.
  3. Use mkdir(parents=True, exist_ok=True) to create a nested output folder, then write a file into it.
