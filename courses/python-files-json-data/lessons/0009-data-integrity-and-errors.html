Data integrity and errors

Real files are malformed, truncated, or simply not what you expected. This lesson is about failing loudly and early instead of silently producing wrong answers.

Time ~12 min Win Fail loudly, never silently Mission link Trustworthy data handling

1The three failure modes

Data problems come in three flavours, and they need different responses: the file is missing, the file is malformed, or the file is valid but wrong — the right shape with the wrong values.

The first two raise exceptions you can catch. The third does not raise at all, which is why it is the most dangerous: your program runs happily and produces nonsense.

2Catching parse errors

json.loads raises json.JSONDecodeError on bad input. Catch it specifically — a bare except would also swallow your own bugs: 

import json

try:
    data = json.loads(text)
except json.JSONDecodeError as e:
    raise ValueError(f"bad JSON at line {e.lineno}: {e.msg}") from e

Note the from e. It keeps the original error attached, so the traceback shows both what went wrong and where.

3Validating what you got

Parsing successfully only means the syntax was fine. You still have to check the content — required keys present, values the right type, numbers in range. 

required = {"name", "score"}
missing = required - data.keys()
if missing:
    raise ValueError(f"missing fields: {missing}")

if not isinstance(data["score"], (int, float)):
    raise TypeError("score must be a number")

This is called validation, and it belongs at the boundary — the moment data enters your program. Validate once, then trust it everywhere inside.

Key idea Parsing checks syntax; validation checks meaning. A file can parse perfectly and still be useless.

4Fail loudly, fail early

The worst outcome is not a crash — it is a wrong answer that looks right. A crash tells you exactly where to look; a silent corruption can travel all the way into a report before anyone notices.

Why this matters later Every pipeline you build should validate at its edges. That single habit is what makes the difference between a script you run once and a tool you trust with real data.

✓ Your win for today

You can now catch parse errors precisely, validate content at the boundary, and explain why a silent wrong answer is worse than a loud crash.

6Do this next

  1. Feed json.loads a deliberately broken string and read the error message carefully.
  2. Write a validation function that checks for required keys and raises a clear error.
  3. Pass it a record with a missing field and confirm the message names the field.
