The with statement

Manual close() works until an exception skips it. The with statement guarantees cleanup no matter how the block exits — and it is the form you should use every single time.

Time ~10 min Win Never leak a file handle Mission link Correct even when things fail

1The problem with manual close

Look at this code. It looks fine, and it is wrong: 

f = open("data.txt")
text = f.read()
process(text)     # if this raises...
f.close()         # ...this never runs

An exception between open() and close() skips the close entirely. The handle leaks. In a loop, you eventually exhaust the operating system's limit.

2The with form

with moves the cleanup out of your hands and into the language: 

with open("data.txt") as f:
    text = f.read()
    process(text)
# f is closed here — always, even if process() raised

The block ends, the file closes. There is no path through the code that skips it, because the closing is not a statement you wrote — it is a guarantee the language provides.

3What "context manager" means

with works with any object that defines two methods: __enter__ (setup) and __exit__ (teardown). open() returns exactly such an object.

__exit__ runs whether the block finished normally or raised. That is the whole trick, and it is why with is not just shorter — it is safer.

Key idea with is a guarantee, not a shortcut. It ties cleanup to the block's exit, however that exit happens.

4Multiple files at once

You can open several files in one statement, which keeps the nesting flat: 

with open("in.txt") as src, open("out.txt", "w") as dst:
    for line in src:
        dst.write(line.upper())

Both handles close when the block ends, in reverse order. This is the shape you will use constantly when converting between formats later in the course.

Why this matters later Every file operation in the rest of this course uses with. Once you stop thinking about closing, you can focus on the data — which is the actual subject.
