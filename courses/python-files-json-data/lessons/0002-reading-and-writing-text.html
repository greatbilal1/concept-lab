Lesson 02 · Files

Reading and writing text

The mode you pass to open() decides whether you are reading, overwriting, or appending — and getting it wrong destroys data. This lesson is about choosing the mode deliberately.

Time ~10 min Win Choose the right mode every time Mission link Never lose data by accident

1The four modes

The second argument to open() is a short string. Each letter means something specific, and one of them is dangerous.

"w" is the one to respect. It does not add to the file — it truncates it to zero bytes the moment you open it, before you write anything. If your program crashes after opening, the old contents are already gone.

2Reading line by line

read() gives you the whole file as one string. Often you want it line by line, and a file handle is iterable: 

with open("log.txt") as f:
    for line in f:
        print(line.rstrip())   # strip the trailing newline

Each line keeps its \n. That is why rstrip() appears so often — without it, printing adds a second blank line.

3Writing and appending

Writing is the mirror image. "w" replaces the file; "a" adds to the end. Neither adds a newline for you. 

with open("out.txt", "w") as f:
    f.write("first\n")
    f.write("second\n")

with open("out.txt", "a") as f:
    f.write("third\n")   # appended, not replaced
Key idea write() writes exactly the characters you give it. Newlines are your responsibility, not Python's.

4Encoding is not optional

Text mode decodes bytes using an encoding. If you do not name one, Python uses the platform default, which differs between machines. That is how a file that works on your laptop breaks on a server.

Naming encoding="utf-8" explicitly makes the behaviour identical everywhere. It is one extra argument and it removes a whole class of bug.

Why this matters later Every JSON and CSV file you read in this course is text underneath. Choosing the mode and the encoding deliberately is what makes those formats reliable rather than lucky.

✓ Your win for today

You can now pick a mode on purpose, read a file line by line, and write text with an explicit encoding. No more accidental truncation, no more platform-dependent decoding.

6Do this next

  1. Write three lines to a file with "w", then open it again with "w" and write one line. Confirm the first three are gone.
  2. Repeat with "a" and confirm nothing is lost.
  3. Read a file line by line and print each line with and without rstrip(). See the difference.
