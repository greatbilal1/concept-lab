Putting it together

You now have booleans, comparisons, logic, branches and loops. This lesson is about the thing they make when you combine them: control flow — the shape of a program's decisions over time.

Time ~12 min Win Build a small state machine that runs Mission link The whole course, in one program

1Control flow is the shape

Control flow is the order in which a program's statements actually run. Written top to bottom, a program looks like a list. Executed, it is a path — with branches that skip whole regions and loops that revisit them. 

if ready:
    while work_left:
        do_one_thing()
else:
    wait()

Nothing in that snippet is new to you. What is new is seeing it as one shape: a decision that guards a repetition, with a fallback. That is the vocabulary you now read code in.

2Nesting depth is a cost

Every branch and loop you nest adds a level of indentation, and every level makes the code harder to hold in your head. Nesting depth is the number of levels you are currently inside. 

if user:
    if user.active:
        if user.balance > 0:
            if not user.locked:
                ship()          # four levels deep

Four levels is a warning sign. The fix is usually an early exit: check the failure cases first and leave, so the happy path stays flat. 

if not user: return
if not user.active: return
if user.balance <= 0: return
if user.locked: return
ship()                      # flat, one level
Rule of thumb Handle the exceptions first and return early. The main path of a function should read at the shallowest depth, because that is the path most readers care about.

3Sentinel values

A sentinel value is a special value that means "stop". It is how a loop knows the input has ended when the input is a stream rather than a list. 

total = 0
while True:
    n = read_number()
    if n == -1:          # the sentinel
        break
    total = total + n

-1 is not data — it is a signal. Sentinels are why while True with a break is not always a mistake: the loop is genuinely unbounded, and the exit is a decision made inside it.

4A state machine

A state machine is a program whose behaviour depends on which state it is in, and which moves between states in response to events. It is the natural shape for anything with modes: a traffic light, a checkout, a game. 

state = "idle"
while state != "done":
    event = next_event()
    if state == "idle" and event == "start":
        state = "running"
    elif state == "running" and event == "stop":
        state = "done"

Notice the pattern: a loop that keeps going, a variable holding the current state, and a branch that decides the next state. Every piece of this course is in those four lines.

✓ Your win for today

You have built a state machine — a loop, a state variable and a branch — and you can now read any program as a shape rather than a list. That is the whole course: values that are true or false, comparisons that produce them, logic that combines them, branches that choose, loops that repeat, and the discipline of keeping it flat.
