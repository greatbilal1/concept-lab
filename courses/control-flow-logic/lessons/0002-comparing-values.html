Lesson 02 · Booleans

Comparing values

A condition has to come from somewhere. Most of the time it comes from a comparison — a question you ask about two values that produces a boolean. This lesson is about the six comparison operators and the two ways they surprise people.

Time ~10 min Win Read a chained comparison correctly Mission link Where every condition comes from

1Six questions you can ask

Python gives you six comparison operators. Each one takes two values and hands back a boolean — never a number, never a string, always True or False.

Notice that == is two equals signs. A single = is assignment — it binds a name. This is the single most common typo in beginner Python, and the error message (SyntaxError) is your friend.

2Equality is not identity

You met this in the previous course, and it matters here because conditions are where the mistake shows up. == asks "do these have the same content?" while is asks "are these the very same object?" 

a = [1, 2]
b = [1, 2]
a == b      # True  — same contents
a is b      # False — two different lists

c = a
a is c      # True  — one list, two names

Use == in conditions almost always. The one place is belongs is comparing against None, where is None is both correct and faster.

Key idea == compares values; is compares identity. In a condition you almost always want the value.

3Chained comparisons

Here is a feature most languages do not have. In Python you can write a comparison that looks like a maths inequality, and it means what it looks like: 

0 <= x < 10

That is not two separate comparisons glued together. Python evaluates it as 0 <= x and x < 10, and — importantly — it evaluates x only once. In a language like C, the same-looking expression would compute (0 <= x) < 10, which is always true because booleans are numbers there.

Why this matters Chained comparisons let you write range checks the way you would say them out loud: "between zero and ten". No and, no repeated variable, no chance of getting the boundary wrong.

4Compare across types

Ordering comparisons (<, >) only work between values that can be ordered together. 3 < 5 is fine; 3 < "5" raises a TypeError, because Python refuses to guess whether you meant the number or the text.

Equality is more forgiving: 3 == "3" is simply False, not an error. Two values of different types are never equal, and Python says so quietly rather than crashing.
