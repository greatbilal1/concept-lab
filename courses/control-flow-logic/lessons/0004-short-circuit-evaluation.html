Short-circuit evaluation

Python does not always evaluate both sides of and and or. It stops the moment the answer is certain — and that is not an optimisation detail, it is a tool you will use deliberately for the rest of your career.

Time ~10 min Win Write a guard clause that prevents a crash Mission link Why condition order is a design choice

1Stopping early

Consider a and b. If a is false, the whole expression is false no matter what b is. So Python never looks at b. The same happens with a or b when a is true: the answer is already true, so b is skipped.

This behaviour is called short-circuit evaluation. The expression is evaluated left to right, and it stops as soon as the result is decided.

2You can see it happen

The easiest way to prove it is with a function that prints when it runs. If the print never appears, the function was never called. 

def noisy():
    print("called!")
    return True

False and noisy()   # prints nothing — noisy() never runs
True  or  noisy()   # prints nothing — noisy() never runs
True  and noisy()   # prints "called!" — the right side was needed
Key idea and stops at the first false value. or stops at the first true value. Anything to the right of that point never runs.

3The guard clause

Short-circuiting is what makes it safe to check a value and use it in the same expression. This is the single most useful pattern in the whole lesson: 

if items and items[0] == "start":
    ...

If items is empty, the left side is falsy, so Python stops — and items[0] is never evaluated. Without short-circuiting, that expression would raise an IndexError on every empty list. The condition that protects the rest of the expression is called a guard clause.

Watch out Order matters, and the wrong order crashes. items[0] == "start" and items raises on an empty list, because the dangerous part runs first. Put the guard on the left, always.

4Precedence, and why you should use brackets

When several operators appear together, Python applies them in a fixed order: comparisons bind tightest, then not, then and, then or. So a or b and c means a or (b and c).

Here is the win for today: you can now read any mixed condition correctly, and you know that adding brackets costs nothing and removes all doubt. When in doubt, bracket it.
