Lesson 06 · Branching

Many branches

Two paths are rarely enough. Grades have five bands, shipping has three speeds, a game has a dozen states. This lesson is about elif — the clause that lets one decision have as many outcomes as you need.

Time ~10 min Win Build a five-band grade classifier Mission link Decisions with more than two outcomes

1elif is "otherwise, if"

elif is short for "else if". It adds another condition that is tested only if every earlier condition was false. You can chain as many as you like, and an optional else at the end catches everything that fell through. 

if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"

2First match wins

This is the rule that catches everyone. Python tests the conditions from the top down and stops at the first one that is true. Every later condition is skipped entirely, even if it would also have been true.

That is why the grade example checks >= 90 before >= 80. A score of 95 satisfies both, but only the first is ever tested. Reverse the order and every score above 80 becomes a B.

Key idea An if/elif chain is a priority list. Order the conditions from most specific to least specific, and remember that exactly one branch runs.

3Nesting, and when to avoid it

You can put an if inside another if. That is called nesting, and it is the right tool when the second question only makes sense after the first — you cannot ask "is the account frozen?" before you know an account exists. 

if user is not None:
    if user.is_active:
        print("Welcome back")

But nesting adds a level of indentation for every question, and deep nesting is hard to read. When the inner condition is independent, and is flatter and clearer: if user is not None and user.is_active:.

Rule of thumb Nest when the second question depends on the first. Combine with and when the two questions are independent. If you are three levels deep, look for an early exit instead.
