Lesson 08 · Loops

Looping over things

A while loop repeats while something is true. A for loop repeats once per item in a collection — and because you already know lists and strings, you already know what to loop over.

Time ~10 min Win Total a list without writing the sum by hand Mission link Where loops meet the data you already have

1For each item

A for loop names a variable and walks it through a collection, one item per pass. You do not manage a counter and you do not check a condition — the loop ends when the items run out. 

for fruit in ["apple", "pear", "plum"]:
    print(fruit)

That prints three lines. On the first pass fruit is "apple", on the second "pear", on the third "plum", and then the loop is over. The name fruit is called the loop variable.

2Anything you can walk through

A for loop works on any iterable — any value that can hand out its items one at a time. Lists, strings, tuples, dictionaries and sets all qualify, and so does range. 

for ch in "abc":        # a, b, c
for n in range(3):      # 0, 1, 2
for k in {"a": 1}:      # a  (keys, not values)
for x in (1, 2):        # 1, 2

Notice range(3) gives 0, 1, 2 — the stop value is excluded. That is why range(10) is the idiomatic way to do something ten times.

Key idea for is for walking a collection. while is for repeating until a condition changes. If you have a list, you almost always want for.

3The accumulator pattern

The most common thing to do inside a loop is build up a result. Start a variable before the loop, update it inside, read it after. That variable is called an accumulator. 

total = 0
for n in [4, 8, 15, 16, 23, 42]:
    total = total + n
print(total)          # 108

The same shape works for counting (count = count + 1), for building a string, and for collecting a list. Learn it once and you will use it in every program you write.

Why this matters The accumulator is the bridge between loops and data. It is how you turn a collection into a single answer — a total, an average, a maximum, a filtered list. Almost every data task is an accumulator in disguise.
