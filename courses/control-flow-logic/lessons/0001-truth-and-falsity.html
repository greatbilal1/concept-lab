Lesson 01 · Booleans

Truth and falsity

Every decision a program makes comes down to one question with two answers. This lesson is about that answer — the boolean — and about the surprising fact that almost every value you already know can stand in for one.

Time ~10 min Win Predict which values count as true Mission link The atom every condition is built from

1Two answers, and only two

You already met True and False when you learned about types. They are the two values of the boolean type, named after George Boole, who worked out an algebra of yes-and-no in the 1800s — a century before there was a machine to run it on.

A boolean is not a small number, even though Python lets you add it like one. A boolean is an answer. Every if, every while, every filter you will ever write is asking a question and acting on the answer.

2Almost everything is true or false

Here is the part that surprises people. Python does not require a condition to be a boolean. It will accept any value and decide for itself whether that value counts as true. This rule is called truthiness.

The rule is short and worth memorising: empty and zero are false; everything else is true.

Key idea A value that behaves like False in a condition is called falsy. The falsy values are False, None, 0, 0.0, "", [], {} and (). Everything else is truthy.

3Why this rule exists

Truthiness is not a quirk — it removes a whole class of pointless comparisons. Without it you would have to write if len(items) > 0: every time you wanted to know whether a list had anything in it. With it, you write if items:, which reads like the question you are actually asking.

The same applies to strings, dictionaries and None. The rule lets the code say what it means instead of spelling out a mechanical test.

Watch out Truthiness is a trap when 0 is a legitimate value. If a score of zero is meaningful, if score: will silently treat it as "no score". In that case compare explicitly: if score is not None:.

4Turn any value into a boolean

When you want to see the answer rather than rely on it, wrap the value in bool(). This is the win for today: you can now predict, for any value, what a condition would do with it. 

bool(0)        # False
bool(1)        # True
bool(-1)       # True   — any non-zero number
bool("")       # False
bool("0")      # True   — a non-empty string!
bool([])       # False
bool([0])      # True   — a list with one item
bool(None)     # False

Read that list again and notice bool("0"). The string "0" is not the number zero — it is a one-character string, and it is not empty, so it is true. This is exactly the kind of bug truthiness causes when you forget which type you are holding.

✓ Your win for today

You can now look at any value and say whether a condition would treat it as true or false, and you know why the rule exists. That is the foundation for everything else in this course: comparisons produce booleans, logical operators combine them, and branches and loops consume them.
