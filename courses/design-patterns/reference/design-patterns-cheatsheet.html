1Factory Pattern

Decoupling creation from execution
class PaymentFactory:
    @staticmethod
    def create(method: str) -> PaymentGateway:
        if method == "stripe": return StripeGateway()
        if method == "paypal": return PayPalGateway()
        raise ValueError(f"Unknown payment method: {method}")

gateway = PaymentFactory.create("stripe")
gateway.charge(amount)

See Lesson 02 — Creational patterns: Factory and Builder.

2Adapter & Facade

Structural interface bridges
// Adapter: Makes an incompatible interface compatible
class StripeAdapter implements PaymentProcessor {
  constructor(private stripe: ThirdPartyStripeSDK) {}
  pay(amountCents: number) {
    return this.stripe.makeCharge({ cents: amountCents });
  }
}

// Facade: Provides a simple front door to a complex subsystem
class VideoConverterFacade {
  convert(file: string, format: string) { ... }
}

See Lesson 03 — Structural patterns: Adapter and Facade.

3Observer Pattern (Pub/Sub)

Event notification decouple
class EventEmitter {
    constructor() { this.events = {}; }
    on(event, listener) {
        (this.events[event] = this.events[event] || []).push(listener);
    }
    emit(event, data) {
        (this.events[event] || []).forEach(fn => fn(data));
    }
}

See Lesson 05 — Behavioral patterns: Observer and Pub/Sub.

4When NOT to Use Patterns

Preventing Patternitis
// Don't create an AbstractFactoryProviderStrategyManager
// for a single if/else statement!
// Rule: Simple procedural code beats a design pattern
// until variability or complexity genuinely demands it.
