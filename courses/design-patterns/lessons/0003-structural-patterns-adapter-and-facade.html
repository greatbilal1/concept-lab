Lesson 03 · Structural Patterns

Structural patterns: Adapter and Facade

How do you plug an incompatible third-party library into your clean architecture? Master the Adapter pattern to bridge interfaces, and the Facade pattern to simplify complex subsystems.

Time ~10 min Win Implement Adapter and Facade patterns to bridge interfaces and tame complex subsystems Mission link The primary structural patterns for integrating third-party SDKs and legacy code

1Adapting interfaces and simplifying systems

Two classic structural patterns solve interface incompatibility: Adapter and Facade.

An Adapter acts like a physical travel plug adapter: it converts an existing incompatible interface (like a third-party Stripe SDK) into an interface your application expects (PaymentGateway). A Facade provides a simple, unified front door to a complex subsystem (like wrapping 5 video codecs, audio decoders, and file parsers behind a single VideoConverter.convert(file) method).

Key idea Adapter makes an incompatible interface work; Facade simplifies a complex subsystem.

2Adapter versus Facade comparison

Understand the intent difference: interface translation versus subsystem simplification.

Trace how an adapter translates domain calls into vendor-specific API formats.
