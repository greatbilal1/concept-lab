Lesson 02 · Pattern Taxonomy & Creational

Creational patterns: Factory and Builder

Stop writing constructors with 12 parameters. Master the Factory Method for decoupling instantiation, and the Builder pattern for constructing complex objects step-by-step.

Time ~10 min Win Implement Factory Method and Builder patterns to streamline complex object creation Mission link Prevents constructor pollution and decouples callers from concrete implementation classes

1Decoupling creation from business logic

When a client class directly calls new SmtpTransport(), it is tightly coupled to that concrete class. If you want to switch to a SendGridTransport based on configuration, you must modify the client class.

The Factory Method pattern delegates instantiation to a factory: the client asks for a transport, and the factory returns an object implementing the Transport interface. The Builder Pattern tackles a different creational problem: constructing complex objects with dozens of optional configurations using fluent chained methods.

Key idea Factory decouples creation from usage; Builder constructs complex multi-step objects cleanly.
