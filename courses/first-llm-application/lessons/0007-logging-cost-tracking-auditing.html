1Core principles of Logging, Cost Tracking, and Usage Auditing

If you don't measure it, you cannot manage it. When you deploy an AI feature to thousands of users, some users will make 3 requests a day, while others will write automated bots that fire 5,000 requests an hour. Without Usage Auditing and Observability, you will receive an unexpected $15,000 invoice at the end of the month.

Key idea Production LLM observability: tracking prompt/completion tokens, calculating dollar costs, and tracing requests with OpenTelemetry.

2The Observability Dashboard

Every production LLM call returns a usage object in its response metadata:

3Per-Tenant Quota Enforcement

# Inspecting the Usage Object:
response = client.chat.completions.create(...)
usage = response.usage
print(usage.prompt_tokens)      # e.g. 1,420 input tokens
print(usage.completion_tokens)  # e.g. 280 output tokens
print(usage.total_tokens)       # e.g. 1,700 total tokens

The three pillars of production LLM observability:

  • 1. Cost Accounting: Multiply `prompt_tokens` and `completion_tokens` by model pricing rates and record the dollar cost directly to the user's account database row.
  • 2. Latency Tracing: Record Time-to-First-Token and total generation duration using OpenTelemetry (e.g. Langfuse, Arize Phoenix, OpenInference).
  • 3. Rate Limiting by Token Quota: Enforce monthly token budgets per subscription tier (e.g. Free Tier = 100k tokens/month).

Observability Rule: Never log sensitive customer Personally Identifiable Information (PII) in plaintext in your tracing databases! Anonymize or redact prompts before shipping them to third-party dashboards.
