Lesson 05 · Branching & merging

Branching

A branch sounds like a copy of your project. It is not. It is a movable label, and that one fact makes branching cheap and safe.

Time ~12 min Win Create, switch, and delete branches without fear Mission link Branches are the foundation of every team workflow

1A branch is a pointer

In most tools, "branch" means "copy the whole project and work on the copy". Git does something far lighter. A branch is just a pointer to a commit — a sticky note with a name on it, stuck to one snapshot.

When you commit, the pointer moves forward to the new commit. That is the entire mechanism. Because a branch is only a name, creating one is instantaneous and costs almost nothing, no matter how large your project is.

Key idea A branch is a movable pointer to a commit. Creating one does not copy any files.

2Creating and switching

You create a branch and switch to it in one step: 

git switch -c experiment

Now HEAD points at experiment, and new commits move that pointer. Your original branch is untouched — it still points at the commit you left from. This is why branching is safe: you can try something, and if it fails, the old branch never moved.

git branch lists your branches and marks the current one. git switch main takes you back. Deleting a branch with git branch -d only removes the label — the commits stay in history as long as something still points at them.

3Watching a pointer move

Follow the pointer as you commit on a branch. Notice that the original branch never moves while you are away — that is the whole point.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can create a branch, commit on it, switch back, and explain why the original branch did not change.

5Do this next

  1. Create a branch with git switch -c and make one commit on it.
  2. Switch back to your original branch and confirm the commit is not there.
  3. Predict what git branch -d would do to the commits you made.
