Lesson 03 · History & commits

The three trees

Git keeps three copies of your project at once. Once you can name them, every confusing Git command suddenly makes sense.

Time ~12 min Win Say which of the three trees any change lives in Mission link This model explains add, commit, diff, and restore

1Three places, one project

In the last lesson you met the staging area. It is one of three places your project exists inside a repository:

  • Working tree — the actual files you edit in your editor.
  • Staging area (also called the index) — the changes you have chosen for the next commit.
  • Repository — the committed history, stored inside .git.

People call these "the three trees". A change moves through them in one direction: you edit the working tree, you stage into the index, you commit into the repository.

Key idea Almost every Git command is really a question about which tree you are moving data between.

2Reading the three trees

The command git status is your map. It tells you which files differ between the working tree and the index, and which staged changes are waiting to be committed. Run it constantly; it is cheap and it always tells you where you are.

git diff compares the working tree against the index — what you have changed but not yet staged. git diff --staged compares the index against the last commit — what you are about to record. Two different questions, two different answers.

3Following one change

Watch a single edit travel through all three trees. This is the mental model to hold onto: at each step, the change exists in a different tree, and a different command moves it forward.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can name the three trees and say which one any change currently lives in.

5Do this next

  1. Edit a file and run git status. Note which tree the change is in.
  2. Run git add on it, then git status again. What moved?
  3. Run git diff and git diff --staged and compare the two outputs.
