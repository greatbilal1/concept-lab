Lesson 07 · Recovery

Undoing things

The reason to learn Git is not to avoid mistakes — it is to make them safely. This lesson is the undo toolkit.

Time ~14 min Win Choose the right undo command for any situation Mission link Recovery is what makes branching and merging safe

1Undo depends on where you are

There is no single "undo" in Git, because there is no single place a mistake can live. The right command depends on which tree the mistake is in — the model from Lesson 3.

  • Working tree — you edited a file and want it back: git restore file.
  • Staging area — you staged something by mistake: git restore --staged file.
  • Repository — you committed something you regret: git revert or git reset.
Key idea Ask "which tree is the mistake in?" and the correct undo command follows almost automatically.

2Revert versus reset

These two are the ones people confuse. They do opposite things to history:

git revert creates a new commit that undoes an earlier one. History is preserved — you can see both the mistake and the fix. This is the safe choice on shared branches.

git reset moves the branch pointer backwards, as if the later commits never happened. It rewrites history. That is fine on a branch only you have, and dangerous on a branch others have pulled.

3The safety net: reflog

Even if you reset away commits, they are not gone immediately. Git keeps a log of everywhere HEAD has been: 

git reflog

This is your safety net. If you reset too far, find the commit in the reflog and reset back to it. Almost nothing you do in Git is truly unrecoverable within a few days — which is exactly why it is safe to experiment.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can pick the right undo command for a working-tree, staged, or committed mistake — and recover from a bad reset with the reflog.

5Do this next

  1. Edit a file, then run git restore on it and confirm the change is gone.
  2. Stage a file by mistake, then unstage it with git restore --staged.
  3. Make a commit, revert it, then run git reflog and read the trail.
