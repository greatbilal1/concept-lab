Lesson 02 · The basics

Your first commit

A snapshot is only useful if you can take one on purpose. This lesson is the two-command loop that records your first commit.

Time ~12 min Win Stage and commit a change, and say what each step did Mission link This is the loop you will repeat hundreds of times

1Git needs a repository

Git does not watch every folder on your computer. It only tracks folders you have explicitly told it about. Such a folder is called a repository, and you create one with a single command run inside the folder: 

git init

That command creates a hidden .git directory. Everything Git knows — every snapshot, every message, every branch — lives inside it. If you delete .git, you delete the history and are left with plain files. That is worth remembering: the history is a folder, and it is yours.

Key idea A repository is just a folder with a .git directory inside it. Git tracks nothing until you run git init.

2Two steps, not one

Here is the part that surprises everyone. Recording a change takes two commands, not one. First you stage the files you want in the snapshot, then you commit them: 

git add essay.txt
git commit -m "rewrite intro"

Why two steps? Because you rarely want to snapshot everything you have touched. You might have fixed a bug and also started an unrelated experiment. Staging lets you choose exactly which changes belong in this commit. The staging area is a holding pen between your files and the history.

3What the commit message is for

The -m flag supplies the message. It is tempting to write "stuff" or "fixes". Resist that. The message is the only part of the commit a future reader — often you — will understand at a glance. Write what changed and why, in the imperative mood: "rewrite intro", not "rewrote intro".

After committing, Git prints a short summary: the branch, the new commit's id, and how many files changed. That id is the handle you will use to refer to this snapshot later.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can run git init, stage a file with git add, and record it with git commit -m — and explain what each step did.

5Do this next

  1. Create a scratch folder, run git init, and look inside the new .git directory.
  2. Add one file, commit it, then change the file and commit again with a clear message.
  3. Predict what happens if you edit a file but never run git add before committing.
