Lesson 01 · The basics

What version control is for

You have almost certainly saved a file as report-final-v2-ACTUAL.docx. Version control is what replaces that habit with something you can trust.

Time ~10 min Win Explain what a commit is and why it beats saved copies Mission link Every later lesson builds on the snapshot idea

1The problem with copies

Imagine you are writing a short essay. You save it, then you rewrite the opening paragraph. You are nervous about losing the old version, so you save a copy: essay-old.txt. Then you try a different ending and save essay-old-2.txt. A week later you have six files and no idea which one is which.

The copies are not the real problem. The real problem is that you cannot answer questions about them. Which file has the paragraph you liked? What exactly changed between Tuesday and Friday? Who wrote the sentence that broke the argument? A pile of files has no memory.

Key idea Version control is not "backup". It is a record of changes — a history you can read, compare, and travel back through.

2A snapshot, not a diff

Git, the version control system this course uses, thinks in snapshots. Every time you record a change, Git takes a picture of what all your files look like at that moment and stores it. That picture is called a commit.

This is different from how you might expect it to work. You might assume Git stores a list of "what changed" — a diff. It does not, at least not as its primary model. It stores whole snapshots, and it is clever enough to reuse unchanged files so the storage stays small. The practical consequence is simple: any commit is a complete, restorable version of your project.

3What a commit carries

A commit is more than a snapshot of files. It also carries metadata: who made it, when, and — most importantly — a message explaining why. That message is the part humans read. A good history is a story told in commit messages.

Each commit also gets a unique identifier, a long hexadecimal string like a3f9c21. That identifier is derived from the contents of the commit, which means the same content always produces the same id. You will use these ids constantly when reading history and undoing mistakes.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can explain why a commit is a snapshot with a message, and why that beats a folder of saved copies.
