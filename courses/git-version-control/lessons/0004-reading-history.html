Lesson 04 · History & commits

Reading history

A history you cannot read is just storage. This lesson is how to ask Git what happened, and how to read the answer.

Time ~12 min Win Read a log, inspect a commit, and compare two points Mission link Reading history is the skill behind every recovery

1The log is a list of commits

git log prints the commit history, newest first. By default it is verbose — full ids, authors, dates, and messages. The first thing to learn is how to make it readable: 

git log --oneline

That gives one line per commit: a short id and the message. This is the view you will use most often. It answers "what happened, in order?" at a glance.

Key idea git log --oneline is the default way to read history. Learn it first and reach for the verbose form only when you need detail.

2Inspecting one commit

When a line in the log catches your eye, ask Git to expand it: 

git show a3f9c21

git show prints the commit's metadata and the exact changes it introduced. This is how you answer "what did that commit actually do?" — the question a saved-copies folder could never answer.

3Comparing two points

History is not only a list; it is a set of comparable states. git diff can compare any two commits, not just the working tree: 

git diff a3f9c21 b7e2d10

That shows everything that changed between those two snapshots. You can also use names like HEAD (the current commit) and HEAD~1 (its parent). These relative names are how you will refer to "the previous version" without copying long ids.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can read a one-line log, expand a single commit, and diff any two points in history.

5Do this next

  1. Run git log --oneline in a repository and read the messages top to bottom.
  2. Pick a commit and run git show on it. Identify what changed.
  3. Run git diff HEAD~1 HEAD and describe the change in one sentence.
