Lesson 08 · Putting it together

A workflow that works

You now know every piece. This lesson assembles them into the loop that real teams run every day.

Time ~14 min Win Run a full feature-branch workflow end to end Mission link This is the payoff — all seven lessons in one loop

1The feature branch loop

The standard workflow is a loop with five steps. You have already met every command in it:

  1. Branch — git switch -c feature/login off the main line.
  2. Commit — make small, well-messaged commits as you work.
  3. Push — git push -u origin feature/login to share the branch.
  4. Review — open a pull request so others can read the diff.
  5. Merge — once approved, merge into the main branch and delete the feature branch.

The point of the loop is that the main branch stays working. Nobody commits half-finished work directly to it. Every change arrives through a branch that was reviewed first.

Key idea Branch, commit, push, review, merge. The main branch is always the version you would be happy to ship.

2Remotes and pull requests

A remote is a copy of the repository hosted somewhere else — GitHub, GitLab, or a server your team runs. git push sends your commits there; git pull brings theirs down. The remote is not special: it is the same repository, just reachable by others.

A pull request (or merge request) is a request to merge one branch into another, wrapped in a place to discuss it. It is where review happens. The diff you learned to read in Lesson 4 is exactly what reviewers read.

3The loop in motion

Follow one feature from branch to merged. Notice that every step is a command you already know — the workflow is just the order they go in.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can describe and run the full feature-branch workflow, from branching to merging a reviewed change.

5Do this next

  1. Create a feature branch, make two commits, and push it to a remote.
  2. Open a pull request and read your own diff as a reviewer would.
  3. Merge it, delete the branch, and confirm the main branch still works.
