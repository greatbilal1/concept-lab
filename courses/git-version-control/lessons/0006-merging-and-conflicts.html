Lesson 06 · Branching & merging

Merging and conflicts

Branches are only useful if you can bring them back together. Merging is how, and conflicts are not errors — they are Git asking you a question.

Time ~14 min Win Merge a branch and resolve a conflict calmly Mission link Every team workflow ends in a merge

1Two kinds of merge

You merge by switching to the branch you want to keep and pulling the other one in: 

git switch main
git merge experiment

If main has not moved since you branched, Git can simply slide the pointer forward. That is a fast-forward merge — no new commit, no work. If both branches have new commits, Git must combine them, and it creates a merge commit with two parents.

Key idea A fast-forward just moves a pointer. A real merge creates a commit that joins two lines of history.

2When Git cannot decide

Git merges automatically when the two branches changed different parts of a file. But if both changed the same lines, Git cannot know which version you want. It stops and marks the file as conflicted.

Inside the file you will see markers: 

<<<<<<< HEAD
your version
=======
their version
>>>>>>> experiment

A conflict is not a failure. It is Git saying "I need a human decision here". You edit the file to the version you want, delete the markers, then git add the file and git commit to finish the merge.

3Resolving step by step

Follow a conflict from the moment it appears to the finished merge. The important part is that git status always tells you what is left to do.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can merge a branch, recognise a conflict, and resolve it without panic.

5Do this next

  1. Create two branches that edit different files, then merge one into the other.
  2. Create a deliberate conflict by editing the same line on both branches.
  3. Resolve it, then run git status at each step to see what Git wants.
