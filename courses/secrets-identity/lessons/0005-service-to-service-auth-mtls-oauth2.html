1Core principles of Service-to-Service Authentication (mTLS, OAuth2 Client Credentials)

Human users authenticate with passwords and MFA. But how does Microservice A authenticate when calling Microservice B inside your cloud cluster? Hardcoding a shared API secret key in both services is fragile: if the secret leaks, all service-to-service trust collapses.

Key idea Machine-to-machine trust: mutual TLS (mTLS), SPIFFE/SPIRE identity standards, OAuth2 Client Credentials grant, and service meshes.

2mTLS vs OAuth2 Client Credentials

The Two Standard Machine-to-Machine (M2M) Authentication Models:

3Service Mesh Automation

  • 1. Mutual TLS (mTLS) & Service Meshes (Istio / Linkerd): Every microservice pod is issued an ephemeral X.509 certificate. When Service A connects to Service B over TCP, both present certificates signed by an internal Certificate Authority (CA). The connection is bidirectionally authenticated and encrypted at the network layer!
  • 2. SPIFFE / SPIRE: An open standard providing cryptographically verifiable identity documents (SVIDs) to workloads in dynamic container environments.
  • 3. OAuth2 Client Credentials Grant: For HTTP API microservices: Service A authenticates against an internal Identity Provider (Keycloak / Auth0) using client credentials, receives a short-lived signed JWT, and includes it as `Authorization: Bearer `. Service B verifies the signature!
# OAuth2 Client Credentials Flow (Service-to-Service):
# 1. Billing Service requests token from Auth Server:
POST https://auth.company.com/oauth/token
Payload: { "grant_type": "client_credentials", "client_id": "billing_svc", "client_secret": "..." }

# 2. Auth Server returns signed, short-lived JWT valid for 15 minutes:
Response: { "access_token": "eyJhbGci...", "expires_in": 900, "scope": "invoices:read" }

# 3. Billing Service calls Invoice Service with verifiable token:
GET https://invoices.company.com/api/v1/invoices
Headers: { "Authorization": "Bearer eyJhbGci..." }

The Zero Shared Secret Principle: Never use a static shared password between microservices. Use mTLS certificates or short-lived signed OAuth2 JWT tokens.
