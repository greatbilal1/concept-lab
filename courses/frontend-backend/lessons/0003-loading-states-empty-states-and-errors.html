Lesson 03 · UI State & Optimistic Updates

Loading states, empty states, and errors

An API call is not just data: it is a journey through time. Master the 4-state asynchronous UI state machine: idle, loading, success, and error.

Time ~10 min Win Design comprehensive asynchronous UI states that handle loading, errors, and empty results Mission link Prevents UI flickering and broken component states during network operations

1The four essential UI states

Many junior developers model asynchronous UI with multiple independent booleans: const [loading, setLoading] = useState(false); const [error, setError] = useState(null);. This leads to impossible states: what if both loading and error are true at the same time?

A resilient frontend models asynchronous communication as a strict State Machine with four mutually exclusive states: 1. Idle (not started), 2. Loading (awaiting network), 3. Success (data received), and 4. Error (network or server failure).

Key idea Model asynchronous UI as mutually exclusive states: idle, loading, success, or error.
