Lesson 04 · UI State & Optimistic Updates

Optimistic updates and rollback patterns

Why wait for the server before showing a 'like' or checkmark? Master optimistic UI updates: rendering success immediately and rolling back gracefully if the network fails.

Time ~10 min Win Implement optimistic UI updates with automatic state rollback on network rejection Mission link Creates snappy, instantaneous user experiences over high-latency networks

1Perceived performance through optimism

On mobile networks, an API request can take 300 to 800 milliseconds. If a user clicks 'Like' on a post and waits nearly a second for a spinner before the heart turns red, the app feels sluggish and unresponsive.

With an Optimistic Update, you update the UI state immediately upon user action, assuming the server will succeed. In the background, you dispatch the network request. If the server confirms, you update IDs; if the server fails, you rollback the UI to its previous snapshot and notify the user.

Key idea Update the UI immediately for instant feedback, but retain a snapshot to rollback if the network fails.
