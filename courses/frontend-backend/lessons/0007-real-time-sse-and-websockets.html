Real-time communication: SSE and WebSockets

When HTTP polling is too slow: compare Short Polling, Long Polling, Server-Sent Events (SSE), and WebSockets for live chat, notifications, and streaming.

Time ~10 min Win Select between Polling, Server-Sent Events, and WebSockets based on communication requirements Mission link Guides protocol selection for live, streaming, and collaborative web applications

1Moving beyond request-response

Traditional HTTP requires the client to ask before the server can speak. For live features like chat, stock tickers, or AI token streaming, repeated polling (setInterval(fetch, 1000)) wastes massive bandwidth on empty responses.

For unidirectional server-to-client streaming (like AI text tokens or live sports scores), Server-Sent Events (SSE) is lightweight, runs over standard HTTP, and has automatic reconnection. For bidirectional, low-latency communication (like multiplayer games or collaborative editing), WebSockets establishes a full-duplex TCP channel.

Key idea Use SSE for unidirectional server-to-client streaming; use WebSockets for bidirectional full-duplex communication.
