Lesson 06 · Security & Error Handling

Error handling and response models

Never leak password hashes in API responses. Master FastAPI's response_model filtering, custom exception handlers, and HTTPException.

Time ~10 min Win Filter sensitive response data using response_model and customize error formats Mission link Prevents accidental data leakage and standardizes API error responses

1Filtering output with response_model

A common security vulnerability: a database user model contains password_hash. A developer writes return user, inadvertently exposing the hashed password in public JSON responses!

FastAPI solves this with response_model. When you declare @app.get('/users/{id}', response_model=UserOut), FastAPI filters the output data strictly to the fields declared in UserOut. Even if your database model contains password hashes or internal keys, FastAPI strips them out before serializing.

Key idea response_model guarantees that only intended, safe fields are serialized in the HTTP response.
