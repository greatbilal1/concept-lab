async def versus def in FastAPI

Should your path operation be 'async def' or normal 'def'? Discover the thread pool magic of FastAPI: when async accelerates I/O, and when normal def prevents blocking.

Time ~10 min Win Choose appropriately between 'async def' and 'def' path operations to avoid thread starvation Mission link Prevents catastrophic thread pool blocking in asynchronous Python backends

1The two execution lanes of FastAPI

FastAPI supports both async def and traditional synchronous def endpoints. But how does it run both on the same server?

When you declare async def, FastAPI executes the function directly on the Main Event Loop. If you write slow, blocking code (like time.sleep() or synchronous database queries) inside an async def, you freeze the entire server! When you declare normal def, FastAPI runs the function inside an external Threadpool, preventing blocking.

Key idea Use async def for non-blocking awaitable I/O; use normal def for blocking synchronous libraries.
