Lesson 07 · Designing failure

Designing failure

An exception is useful only if the program responds well to it. Choose between checking first and handling a failed operation, write messages that help someone act, and preserve diagnostics instead of silently discarding them.

Time ~10 min Win Design a failure path that helps recovery Mission link Make failures diagnosable, not invisible

1Give the person a next step

Compare "Invalid input" with "Age must be a whole number from 0 to 130; you entered 'old'.". The second message identifies the expectation and the value that failed it. Do not include secrets, and avoid showing a traceback as if it were a user-facing explanation.

Key idea A useful error tells the reader what failed, what was expected, and what they can do next, without exposing sensitive data.

2Second idea

2Check first or try the operation?

LBYL ("look before you leap") checks a condition first, such as testing whether a key exists. EAFP ("easier to ask forgiveness than permission") tries the operation and handles the specific exception if it fails. Choose the clearer expression of the rule. EAFP is especially useful when the operation itself is the reliable test; a separate check can become stale before the operation happens.

3Third idea

3Keep diagnostics, not silence

If you can recover, handle the known failure. If you cannot, let it propagate or log it with its traceback at a boundary. An empty except block or pass turns a visible problem into wrong output that is much harder to find. Use assert for programmer assumptions during development, not for validating user input: Python may remove assertions when optimization is enabled.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today You can choose an explicit recovery style, write actionable messages, and preserve unexpected failures for diagnosis instead of hiding them.

5Do this next

  1. Rewrite one vague error message to include the failed value and the expected form.
  2. Implement a dictionary lookup once with LBYL and once with EAFP; choose the clearer version for the situation.
  3. Replace a silent except: pass with a specific handler or a logged re-raise.
