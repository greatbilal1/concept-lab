What an error actually is

An error is not a punishment. It is Python telling you, precisely, that a promise it made could not be kept. This lesson is about what that message is made of — and why the two kinds of failure you will meet behave completely differently.

Time ~10 min Win Tell a syntax error from a runtime error Mission link The vocabulary every later lesson builds on

1Two ways a program can fail

You have already seen both of these. Run a file with a missing bracket and Python refuses to start. Run a file that divides by zero and Python starts fine, then stops halfway through. Those feel similar when you are staring at a red wall of text, but they are completely different events.

The first is a syntax error. Python reads your whole file before it runs a single line, translating it into instructions. If the grammar is broken, that translation fails and nothing executes at all. Not the first line, not the imports, nothing.

The second is a runtime error. The file was valid, so Python began running it. Somewhere in the middle, an operation could not be completed — and Python stopped at that line, with everything before it already done.

Key idea A syntax error means "I cannot understand this file." A runtime error means "I understood it, I ran it, and this specific step was impossible."

2An exception is an object

Here is the idea that makes the rest of this course click. When a runtime error happens, Python does not just print a message and quit. It creates an object — an instance of an exception class — and then starts moving it up through your program.

That object has a type (ZeroDivisionError), a message ("division by zero"), and a record of where it happened. Because it is an object, you can catch it, inspect it, store it, and raise it again. That is the entire mechanism behind try/except.

The exception classes form a tree. ZeroDivisionError is a kind of ArithmeticError, which is a kind of Exception, which is a kind of BaseException. When you catch a type, you catch everything beneath it — which is powerful, and also the source of the most common mistake in this whole subject.

3Watch it travel

Trace this program. The exception is created deep inside average, but nothing there handles it — so it travels up to report, and then up to the top level, where Python finally prints it and stops.

Notice that the program did not "crash randomly". It stopped at exactly the line that could not complete, and the exception walked up the call stack looking for someone willing to handle it. Nobody was, so it reached the top.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today

You can now look at a failure and say which of the two kinds it is — and you know that a runtime error is a real object travelling up your call stack, not just text on a screen. That object is what every remaining lesson in this course is about.

5Do this next

  1. Write a file with a deliberate syntax error (delete a closing bracket) and run it. Confirm that no print before the error appears.
  2. Now write a file that prints three lines and then divides by zero. Confirm that the first three lines do appear before the error.
  3. In a Python shell, run help(ZeroDivisionError) and then ZeroDivisionError.__mro__. Read the chain of parents — that is the hierarchy you will catch against in Lesson 03.
