Lesson 03 · Catching

Catching what you expect

You can now read a traceback. The next step is to stop the program from dying when a failure is predictable. try and except let you say "I know this can fail, and here is what to do instead" — but only if you name the exception you actually expect.

Time ~10 min Win Handle a specific exception without hiding others Mission link Control over failure, not fear of it

1From crash to choice

Suppose you ask the user for a number and convert it with int(). If they type "hello", Python raises ValueError and your program stops. But this failure is expected — users type the wrong thing all the time. You want to respond, not crash. 

try:
    age = int(input("Age: "))
except ValueError:
    print("That was not a number.")
    age = 0

The try block holds the risky line. The except ValueError block runs only if a ValueError is raised inside it. If the conversion succeeds, the handler is skipped entirely.

Key idea except names the exception you expect. Anything else keeps propagating, exactly as it did in Lesson 01.

2Only the first match runs

You can list several handlers, and Python checks them top to bottom. The first one whose type matches runs; the rest are ignored. This matters because exception types form the tree you met in Lesson 01 — a handler for a parent also matches every child.

So order matters. Put specific types first and general ones last, or a broad handler will swallow the cases you meant to treat separately.

3Watch the handler fire

Step through this program. The try block raises, Python looks for a matching except, finds it, and continues after the whole statement.

Notice that the line after the try/except still runs. Catching does not end the program — it redirects it.

4Practice

Recall the key facts from memory before the quiz.

✓ Your win for today

You can wrap a risky operation in try, name the exact exception you expect in except, and know that every other exception still travels up the stack untouched.
