Lesson 03 · Interfaces & Type Aliases

Interfaces & Object Shapes

In TypeScript, types are structural ('duck typed'): if an object has the required properties, it satisfies the interface.

Time ~10 min Win Define object contracts with interfaces, optional properties, and readonly fields Mission link Guarantee consistent data shapes across components and microservices

1Structural typing vs nominal typing

Languages like Java or C# use nominal typing: an object only satisfies an interface if its class explicitly declares implements InterfaceName.

TypeScript uses structural typing (often called "duck typing"). If an object matches the shape defined by an interface—meaning it has the required properties with matching types—TypeScript accepts it, regardless of how it was created.

Key idea TypeScript cares about the shape of data, not the class label on the object.

2Interface features: optional and readonly

Interfaces provide modifiers to fine-tune property behavior:

  • readonly id: string: Prevents mutation of the property after creation.
  • email?: string: Marks the property as optional (it can be string or undefined).
  • extends OtherInterface: Inherits properties from one or more base interfaces.
