Lesson 01 · Basic Types & Type Inference

Why TypeScript & Type Annotations

JavaScript is dynamically typed; TypeScript adds a compile-time static type system that verifies code correctness before execution.

Time ~10 min Win Write explicit type annotations for variables, functions, and arrays and understand type erasure Mission link Eliminate silent runtime type errors across complex applications

1Static typing on top of dynamic JavaScript

In standard JavaScript, variables can hold any value, and functions receive whatever arguments are passed at runtime. If you pass an unexpected shape, JavaScript fails at runtime with errors like TypeError: user.toUpperCase is not a function.

TypeScript introduces a compile-time type checker. You write TypeScript (.ts files), the compiler (tsc) verifies all types, and then produces clean JavaScript (.js) by completely stripping out (erasing) the type annotations.

Key idea TypeScript catches bugs during compilation; at runtime, only standard JavaScript executes with zero performance overhead.

2Basic type annotations

You annotate variables and function parameters using a colon (: type). The primary primitive types match JavaScript's primitives: number, string, boolean, null, and undefined.

3Tracing function type verification

Observe how the TypeScript compiler detects a type mismatch when passing arguments to an annotated function.

4Practice

Test your understanding of type annotations and compiler behavior.

✓ Your win for today

You can explain the purpose of TypeScript, annotate primitive variables and functions, and understand the compile-to-JS cycle.

5Do this next

  2. Deliberately pass an invalid type to an annotated function and inspect the compiler error.
  3. Verify that emitted .js files contain no TypeScript type keywords.
