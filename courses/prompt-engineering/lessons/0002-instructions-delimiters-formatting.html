1Core principles of Clear Instructions, Delimiters, and Markdown Formatting

When you dump a customer email, a database schema, and an instruction into a single flat text blob, the model struggles to parse the boundaries: where do the instructions end, and where does the customer data begin? 3Prompt Injection Defense via Delimiters

  • XML Tags (Anthropic Standard): Wrapping different sections in explicit semantic tags: `<context> ... </context>`, `<rules> ... </rules>`, `<document> ... </document>`. Highly effective for frontier models!
  • Markdown Headers: Using `## Rules`, `### Input Data`, `### Expected Output` to establish hierarchical structure.
  • Triple Quotes / Backticks: Enclosing multiline text or code blocks (`"""` or ```` ``` ````).
# Prompt Structuring with XML Delimiters:
Analyze the customer support email provided in the <email> tags below.
Extract the customer's sentiment and order ID according to the <rules>.

<rules>
1. Sentiment must be one of: [POSITIVE, NEUTRAL, NEGATIVE].
2. Order ID follows the format 'ORD-' followed by 6 digits.
</rules>

<email>
Hello, I am furious! My order ORD-849201 has not arrived yet. Please refund me.
</email>

Boundary Clarity: Delimiters make it impossible for customer text to be misinterpreted as system instructions, neutralizing basic prompt injection attacks.
