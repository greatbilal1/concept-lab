The 3-Layer Architecture Ports & Adapters (Hexagonal) Repository Pattern Configuration & Boundaries

1The 3-Layer Architecture

Classic layered responsibilities
1. Presentation Layer (Controllers / Routers)
   - HTTP, validation, status codes, JSON serialization
2. Business Logic Layer (Services / Domain)
   - Core business rules, calculations, workflows
3. Persistence Layer (Repositories / Database)
   - SQL queries, ORM sessions, external API clients

See Lesson 01 — The layered architecture pattern.

2Ports & Adapters (Hexagonal)

Dependency Inversion in practice
// Domain defines the Port (Interface):
interface PaymentGateway {
  charge(amount: number, token: string): Promise<PaymentReceipt>;
}

// Infrastructure provides the Adapter:
class StripePaymentAdapter implements PaymentGateway {
  async charge(amount: number, token: string) {
    return await stripe.charges.create(...);
  }
}

See Lesson 03 — Hexagonal architecture: ports and adapters.

3Repository Pattern

Collection-like persistence abstraction
class UserRepository:
    def get_by_id(self, user_id: int) -> User: ...
    def save(self, user: User) -> None: ...
    def find_by_email(self, email: str) -> Optional[User]: ...

# Service consumes Repository without knowing if it is SQL, Redis, or Mock!

See Lesson 05 — The repository pattern.

4Configuration & Boundaries

Twelve-Factor settings and logging
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    database_url: str
    jwt_secret: str
    environment: str = "development"

settings = Settings() # loads from environment variables with validation
