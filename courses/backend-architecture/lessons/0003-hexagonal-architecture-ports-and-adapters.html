Lesson 03 · Hexagonal Architecture & Ports

Hexagonal architecture: ports and adapters

Treat your application as an isolated hexagon. Discover Alistair Cockburn's Ports and Adapters architecture: how to plug in databases, HTTP APIs, and CLI tools with zero coupling.

Time ~10 min Win Implement Ports and Adapters to decouple core application logic from external technologies Mission link The practical implementation pattern for Hexagonal and Clean Architecture

1The application in the center

Alistair Cockburn created Hexagonal Architecture (Ports and Adapters) with a clear vision: an application should be equally driven by users, automated tests, or batch scripts, and developed and tested in isolation from its runtime devices and databases.

The application core sits inside a hexagon. To talk to the outside world, the core defines Ports (interfaces). External technologies connect through Adapters that translate between external drivers (HTTP, SQL, Stripe) and the core ports.

Key idea The core defines Ports (interfaces); external technologies plug in via Adapters.

2Driving versus Driven ports

Understand the two sides of the hexagon: Primary (Driving) and Secondary (Driven).
