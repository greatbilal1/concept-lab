Lesson 01 · Layers & Architectural Boundaries

The layered architecture pattern

Controllers should not write SQL, and database models should not format HTML. Master the classic 3-tier layered architecture: Presentation, Business, and Persistence.

Time ~10 min Win Organize backend codebases into distinct Presentation, Service, and Persistence layers Mission link The foundational architectural pattern used by the vast majority of enterprise backends

1The classic three-layer pattern

The most widely adopted backend architecture divides software into three horizontal tiers: 1. Presentation Layer (HTTP routing, JSON parsing, status codes), 2. Business Logic Layer (pure domain rules, calculations, workflows), and 3. Persistence Layer (database access, SQL queries, cache clients).

The golden rule of layered architecture: Dependencies flow strictly downward. The Presentation layer calls the Business layer; the Business layer calls the Persistence layer. The Business layer never knows about HTTP, and the Persistence layer never knows about web controllers.

Key idea Dependencies flow downward: Presentation calls Business Services; Business Services call Persistence.
