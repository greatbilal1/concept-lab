Naming a step

A procedure is a step with a name. This lesson is about writing one well: a clear name, a body that does what the name says, and a one-line note that tells the next reader what it is for.

Time ~10 min Win Write a procedure whose name says what it does Mission link Give each piece a name

1The anatomy of a procedure

Every procedure has the same four parts: the def keyword, a name, parentheses, and an indented body. The name is the important part — it is how the rest of the program refers to this step. 

def print_banner():
    print("=" * 20)
    print("  REPORT  ")
    print("=" * 20)

print_banner()

The name print_banner says exactly what the step does. A reader never has to open the body to know what calling it will do. That is the whole goal of naming a step.

2Name it after the job

A good procedure name is a verb phrase: print_banner, load_scores, send_email. It describes the job, not the mechanism. If you cannot name it in a few words, the step is probably doing more than one thing — a problem Lesson 05 solves. 

# good — the name is the job
def calculate_total(prices):
    ...

# bad — the name is the mechanism
def loop_over_prices_and_add_them_up(prices):
    ...

Python's style guide, PEP 8, says function names should be lowercase with words separated by underscores. That is why it is print_banner and not PrintBanner.

Key idea A procedure name is a promise. The body should do exactly what the name says — no more, and no less.

3Say what it does, in one line

A docstring is a string on the first line of the body. It is not decoration — it is the one sentence that tells the next reader what the step is for, without them reading the code. 

def print_banner():
    """Print a boxed title above a report."""
    print("=" * 20)
    print("  REPORT  ")
    print("=" * 20)

One line is usually enough. If you need three paragraphs to describe a procedure, that is a signal it is doing too much.
