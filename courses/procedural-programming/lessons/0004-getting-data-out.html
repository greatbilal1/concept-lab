Lesson 04 · Data

Getting data out

A procedure that only prints is a dead end — its result cannot be used by the next step. return is how a step hands a value back, so the sequence can keep going.

Time ~10 min Win Write a procedure that returns a value Mission link Get a result back from a procedure

1return hands a value back

return does two things at once: it ends the procedure immediately, and it sends a value back to whoever called it. That value can be stored, printed, or passed to the next step. 

def add(a, b):
    return a + b

total = add(2, 3)
print(total)        # 5
print(add(10, 20))  # 30

Compare this to a version that prints instead of returning. The printing version can only show the answer; the returning version lets the rest of the program use it. That difference is what makes a step composable.

2No return means None

If a procedure has no return, it still returns something: None, Python's value for "nothing". This is why a procedure that only prints cannot be used in an expression. 

def show(a, b):
    print(a + b)

result = show(2, 3)   # prints 5
print(result)         # None

None is not an error — it is the honest answer to "what did this step produce?" when the step produced nothing. But if you meant to hand a value back, a missing return is the bug.

Watch out A procedure that prints and a procedure that returns look almost identical, but only one of them can feed the next step. If your result is None, check for a missing return.

3Return ends the step

return is not just a value — it is an exit. Any statements after it in the same block never run. This makes it the natural way to handle a failure case early. 

def safe_divide(a, b):
    if b == 0:
        return None      # leave early
    return a / b

print(safe_divide(10, 2))   # 5.0
print(safe_divide(10, 0))   # None

The early return keeps the main path flat: the happy case is the last line, not buried inside an else. This is the same early-exit idea from Control Flow, now applied to a step.
