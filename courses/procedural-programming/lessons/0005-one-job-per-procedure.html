Lesson 05 · Structure

One job per procedure

This is the hinge of the course. Everything before it was about a single step; everything after it is about a program of steps. The rule that makes that possible is simple: each procedure does one job.

Time ~10 min Win Split a do-everything procedure into named steps Mission link Split a script into named procedures

1The do-everything procedure

Here is a procedure that does three jobs at once: it reads the data, it computes a total, and it prints a report. It works — but you cannot reuse any part of it, and you cannot test any part of it. 

def process():
    prices = [4, 8, 15]
    total = 0
    for p in prices:
        total = total + p
    print("Total:", total)

process()

The name process is a confession: it does not describe a job, because there is no single job. That is the signal to split it.

2Extract the steps

Splitting a procedure into smaller ones is called extracting. Each new procedure gets a name that describes its one job, and the original becomes a short sequence of calls. 

def load_prices():
    return [4, 8, 15]

def total(prices):
    result = 0
    for p in prices:
        result = result + p
    return result

def print_report(total):
    print("Total:", total)

print_report(total(load_prices()))

The last line reads like a sentence: print the report of the total of the loaded prices. Each step can now be reused, tested, and understood on its own.

Key idea A procedure should do one job, so its name can describe it completely. If the name needs an "and", it is two procedures.

3Cohesion: does it belong together?

Cohesion is how closely the statements inside a procedure belong together. High cohesion means every line serves the one job. Low cohesion means the procedure is a grab-bag. 

# high cohesion — every line serves one job
def total(prices):
    result = 0
    for p in prices:
        result = result + p
    return result

# low cohesion — three unrelated jobs
def setup():
    connect()
    load_config()
    print_banner()

The test is the name. If you can name the procedure in a few words and every line serves that name, cohesion is high. If you cannot, split it.

✓ Your win for today

You can take a do-everything procedure and split it into named steps, each doing one job. This is the single most important habit in procedural programming — and it is the rule that the rest of the course builds on. The next lesson is about the data those steps share.
