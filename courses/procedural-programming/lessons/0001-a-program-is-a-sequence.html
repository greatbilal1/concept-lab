Lesson 01 · Steps

A program is a sequence

Before you can organise a program, you have to see it for what it is: a list of steps that run in order, top to bottom. This lesson is about that shape — and about the first tool for naming a step.

Time ~10 min Win Read a script and name its steps Mission link A program as a sequence of steps

1Top to bottom

A Python file is a list of statements. Python runs them in the order they appear, one after another, from the first line to the last. That is the whole model — everything else in this course is built on top of it. 

name = "Ada"
greeting = "Hello, " + name
print(greeting)
print("Done")

Four statements, four steps. The output is Hello, Ada then Done. Nothing here is surprising — and that is the point. A procedural program is exactly this: a sequence of steps that operate on data as they go.

2Naming a step

A long sequence is hard to read, because every step looks the same. The fix is to give a group of steps a name. In Python that name is a procedure, written with def. 

def greet(name):
    greeting = "Hello, " + name
    print(greeting)

greet("Ada")
greet("Grace")
print("Done")

The def line defines the step; it does not run it. The two greet(...) lines call it, and each call runs the body once. Now the top-level sequence reads as three steps: greet Ada, greet Grace, print Done.

Key idea Defining a procedure does not run it. The body runs only when the procedure is called, and it runs once per call.

3Why this is the default style

Most code you will read — scripts, data pipelines, small tools — is procedural. It is the style you reach for first because it matches how you describe a task out loud: do this, then this, then this. The rest of this course is about doing it well.
