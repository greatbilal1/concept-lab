Lesson 01 · Cluster Architecture & Core Primitives

Control Plane, etcd & Worker Architecture

Kubernetes splits responsibilities cleanly between the brains of the cluster (Control Plane) and the muscle (Worker Nodes).

Time ~10 min Win Explain the responsibilities of every control plane and worker component and their interaction via the API server Mission link Diagnose cluster outages and master the control-plane reconciliation loop

1Brain vs Muscle: The two tiers

A Kubernetes cluster consists of two distinct tiers:

  • Control Plane (The Brains): Manages the cluster. It contains the kube-apiserver (the only component communicating directly with etcd), the kube-scheduler (decides which node hosts each pod), and the kube-controller-manager (runs reconciliation loops).
  • Worker Nodes (The Muscle): The physical or virtual machines that actually run user containers. Each worker runs a kubelet (the local node manager), kube-proxy (handles network packet routing), and a container runtime (such as containerd).
Key idea No component talks directly to etcd except the kube-apiserver; all other components interact via the REST API.

2The continuous reconciliation loop

Kubernetes operates on a simple principle: Observed State vs. Desired State. Controllers continuously query the API server: "The user asked for 3 replicas, but only 2 are running. Therefore, I will create 1 new pod."
