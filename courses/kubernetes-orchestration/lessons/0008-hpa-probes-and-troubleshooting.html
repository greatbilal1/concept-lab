Health Probes, Autoscaling (HPA) & Debugging

Ensure production resilience: configure automated health checks, scale pod replicas based on traffic, and troubleshoot failures.

Time ~10 min Win Configure Liveness/Readiness probes, set up the Horizontal Pod Autoscaler, and debug production outages Mission link Automate recovery from service deadlocks and scale capacity seamlessly during traffic spikes

1The three health probes

Kubernetes cannot know if your application is actually working just because its process is running. A node application might be stuck in an infinite loop or locked waiting for a database socket.

The kubelet uses three distinct probes to manage container health:

  • Startup Probe: Determines if a slow-starting application has initialized. While running, it disables liveness and readiness checks to prevent premature restarts.
  • Liveness Probe: Detects deadlocks and fatal states. If it fails, the kubelet kills the container and restarts it according to its restartPolicy.
  • Readiness Probe: Determines if the container is ready to accept user traffic. If it fails, the pod is removed from Service endpoints; it is not killed.
Key idea Liveness probe failures trigger container restarts; readiness probe failures temporarily remove the pod from service traffic.

2Horizontal Pod Autoscaler (HPA)

The Horizontal Pod Autoscaler (HPA) automatically adjusts the number of replica pods in a Deployment based on observed metrics (like average CPU utilization, memory pressure, or custom Prometheus metrics).

For example, if average CPU exceeds 70%, the HPA controller calculates desiredReplicas = ceil[currentReplicas * (currentMetric / targetMetric)] and scales up the Deployment.
