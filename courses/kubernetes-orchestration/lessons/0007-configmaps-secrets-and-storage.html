Lesson 07 · Storage, Config & Production Operations

ConfigMaps, Secrets, PVs & PVCs

Never hardcode configuration or passwords in container images. Separate configuration and persistent storage from code.

Time ~10 min Win Inject configuration and secrets into pods and provision persistent storage with PVCs Mission link Keep sensitive credentials secure and preserve critical data across container restarts

1Separating configuration from container images

The Twelve-Factor App methodology mandates strict separation of config from code. Building separate container images for development, staging, and production is an anti-pattern.

Kubernetes provides two core configuration primitives:

  • ConfigMap: Stores non-sensitive key-value pairs (URLs, feature flags, configuration files).
  • Secret: Stores sensitive data (database passwords, API tokens, TLS private keys).

Both can be injected into containers as environment variables or mounted as configuration files inside a volume.

Key idea Use ConfigMaps for general configuration and Secrets for sensitive credentials; inject them via environment variables or volumes.

2Persistent storage: PV, PVC, and StorageClass

Container filesystems are ephemeral: when a container restarts, modifications are wiped clean. For durable storage, Kubernetes decouples storage consumers from storage providers:

  • StorageClass: Defines the storage provisioner (e.g. AWS EBS gp3, GCP Persistent Disk, local NVMe).
  • PersistentVolume (PV): A physical piece of storage in the cluster provisioned by an administrator or dynamically by a StorageClass.
  • PersistentVolumeClaim (PVC): A request for storage by a user (e.g. "Give me 50GB with ReadWriteOnce access") that binds to a matching PV.
