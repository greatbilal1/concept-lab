Lesson 04 · Workloads & Controllers

StatefulSets, DaemonSets & Batch Jobs

Not every application is a stateless web server. Learn how to run databases (StatefulSets), node agents (DaemonSets), and one-off tasks (Jobs).

Time ~10 min Win Choose the correct workload controller (StatefulSet, DaemonSet, Job, CronJob) for specialized workloads Mission link Run databases and cluster-wide infrastructure agents predictably and safely

1Stateful workloads with StatefulSets

Stateless pods are interchangeable cattle: if web-7f89d-abc dies, it is replaced by web-7f89d-xyz with a new random IP and ephemeral storage.

Databases (PostgreSQL, Kafka, Cassandra) require stable identities. A StatefulSet guarantees:

  • Stable network IDs: Pods have predictable sequential names: db-0, db-1, db-2.
  • Dedicated storage: Each pod receives its own dedicated PersistentVolume that reattaches to that exact pod index even after a crash or reschedule.
  • Ordered deployment and scaling: Pods start and terminate strictly in sequential order (0, then 1, then 2).
Key idea StatefulSets provide stable sequential hostnames and dedicated persistent volume bindings for databases.

2DaemonSets, Jobs, and CronJobs

Different operational patterns require specialized controllers:

  • DaemonSet: Ensures that every node runs an exact replica of a Pod. Perfect for monitoring agents (Datadog, Prometheus node-exporter) and log collectors (Fluentbit).
  • Job: Runs a pod until completion (exit code 0). Ideal for database migrations or batch data processing.
  • CronJob: Schedules Jobs to run periodically at fixed intervals using standard cron syntax (e.g. 0 2 * * * for nightly backups).
