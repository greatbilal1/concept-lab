Lesson 06 · LSP & Legitimate Inheritance

The Liskov Substitution Principle (LSP)

If it looks like a duck and quacks like a duck but needs batteries, you have the wrong abstraction. Discover the Liskov Substitution Principle and the famous Square-Rectangle trap.

Time ~10 min Win Evaluate inheritance hierarchies against the Liskov Substitution Principle (LSP) Mission link The behavioral contract that governs when class inheritance is genuinely safe

1Subtypes must be substitutable

Barbara Liskov formulated the Liskov Substitution Principle (LSP), the 'L' in SOLID: Subtypes must be substitutable for their base types without altering the correctness of the program.

If a function accepts a Rectangle, passing a Square should not break it. But in mathematics, a Square is a Rectangle; in object-oriented code, Square violates LSP! A Rectangle promises that setting width does not alter height. If Square overrides setWidth(w) to also set height, it breaks the caller's contract!

Key idea Subtypes must honor all behavioral promises made by their superclass without surprise mutations.
