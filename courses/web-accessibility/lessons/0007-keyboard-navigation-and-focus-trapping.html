Keyboard Navigation, Tabindex & Focus Trapping

If you cannot use your website with just a keyboard, it is broken. Master focus indicators, tabindex rules, and modal dialog focus traps.

Time ~10 min Win Manage keyboard focus, remove outlines responsibly, and implement bulletproof focus traps for modal dialogs Mission link Guarantee full accessibility for users with motor impairments who cannot use a mouse

1The Golden Rule of Keyboard Navigation

Millions of people navigate computers exclusively with keyboards, switch devices, or head wands due to motor disabilities (paralysis, tremors, arthritis). The fundamental rule of web engineering is: Any action that can be performed with a mouse must be fully operable with a keyboard alone.

Key navigation expectations:

  • Tab / Shift+Tab: Move forward and backward between interactive controls.
  • Enter / Space: Activate buttons, links, and checkboxes.
  • Arrow Keys: Navigate within complex composite widgets (radios, menus, select dropdowns).
  • Never remove focus outlines: Removing outline: none without an accessible alternative makes keyboard navigation impossible.
Key idea Every interactive control must have a visible focus indicator and be fully operable via standard keyboard keys.

2Tabindex rules & Modal focus trapping

The tabindex attribute controls keyboard focusability:

  • tabindex="0": Inserts a non-interactive element into the natural sequential keyboard tab order.
  • tabindex="-1": Makes an element focusable via JavaScript (element.focus()), but skips it during keyboard tabbing.
  • Positive tabindex (tabindex="1+"): An anti-pattern! Never use positive tabindex because it overrides natural DOM order.

When an accessible modal dialog opens, you must trap focus: tabbing past the last element in the modal wraps focus back to the first element, preventing focus from escaping into the inert background page. Pressing Escape must close the modal and return focus to the trigger button.
