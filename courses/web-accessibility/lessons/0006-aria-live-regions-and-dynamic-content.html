Lesson 06 · ARIA Roles, States & Live Regions

ARIA Live Regions & Dynamic Content

When content updates via AJAX or WebSockets, sighted users see it. Learn how aria-live announces updates to screen readers without moving focus.

Time ~10 min Win Announce asynchronous updates politely or assertively using aria-live regions and role='alert' Mission link Keep assistive technology users informed of dynamic Single Page App (SPA) updates

1The problem of silent dynamic updates

In modern web applications, content changes constantly without full page reloads: a toast notification appears saying "Payment Successful", a timer counts down, or search results filter live.

Sighted users notice these changes through peripheral vision. Screen reader users only hear what is currently focused. Without intervention, dynamic updates happen completely silently. ARIA Live Regions solve this by announcing DOM updates automatically without shifting user focus.

Key idea ARIA live regions announce asynchronous content changes to screen readers without moving user focus.

2Configuring live regions: polite, assertive, and atomic

Configuring a live region requires careful tuning:

  • aria-live="polite": Use for 95% of updates (e.g. cart item counts, search result totals). Waits for conversational pauses.
  • aria-live="assertive" (or role="alert"): Reserved for critical, time-sensitive emergencies (e.g. "Server disconnected", session timeout warnings). Interrupts speech immediately.
  • aria-atomic="true": Instructs the screen reader to read the entire container rather than just the mutated text node (critical for timestamps or sentences).

Crucial Rule: The live region container must be present in the DOM before the content is injected. Injecting both the container and content simultaneously often fails to trigger announcements.
