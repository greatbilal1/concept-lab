Accessible Forms, Labels & Error Announcements

Forms are the primary point of failure on the web. Learn how to programmatically associate labels, hints, and error alerts.

Time ~10 min Win Build accessible forms with programmatic label wiring, aria-describedby hints, and aria-invalid errors Mission link Ensure users with disabilities can independently complete purchases, logins, and registrations

1The fatal flaw: Missing form labels

A visually sighted user sees a text box next to the word "Phone Number". But a screen reader does not infer relationships by visual proximity: unless programmatically linked, it focuses the input and announces: "edit text, blank".

You must programmatically connect inputs and labels:

  • Explicit association: <label for="user-phone">Phone</label><input id="user-phone" ... />.
  • Implicit wrapping: <label>Phone <input ... /></label>.

Never rely on placeholder="..." as a label: placeholders disappear when typing begins, lack sufficient contrast, and are ignored by many assistive devices.

Key idea Every form control must have a programmatically associated label via the for/id relationship.

2Wiring hints and errors with aria-describedby

An input often needs auxiliary text: password requirements or validation error messages. The aria-describedby attribute takes one or more element IDs and speaks their text after the label is read.

When validation fails, add aria-invalid="true" to the input and point aria-describedby to the error message container (which should also have role="alert").
