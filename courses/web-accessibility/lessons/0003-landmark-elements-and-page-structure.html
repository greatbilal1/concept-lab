Lesson 03 · Semantic HTML, Landmarks & The AOM

Document Landmarks & Page Structure

Screen reader users do not read entire pages line-by-line; they jump between landmarks and headings. Learn to architect page hierarchy.

Time ~10 min Win Structure accessible document layouts using HTML5 landmark elements and strict heading hierarchies Mission link Enable efficient non-visual page scanning for screen reader users

1How screen reader users scan pages

A sighted user opening a web page glances across the screen in 2 seconds, visually identifying the navigation bar, the hero banner, and the footer. Blind users cannot glance visually. Instead, they press hotkeys on their screen reader:

  • 'H' key: Jumps to the next heading (<h1> through <h6>).
  • 'D' key (Landmarks): Jumps directly between major structural landmark regions (e.g. Main, Navigation, Header, Footer).

If your page is constructed purely of generic <div> tags, the user has zero landmarks to jump to.

Key idea Screen reader users navigate through headings and landmarks; proper document structure is their navigation map.

2HTML5 semantic landmarks and skip links

HTML5 provides dedicated landmark elements that map directly to accessibility roles:

  • <header> (role="banner"): Top branding and site header.
  • <nav> (role="navigation"): Major navigation blocks.
  • <main> (role="main"): The unique central content of the document. Only one per page!
  • <aside> (role="complementary"): Sidebar content related to main.
  • <footer> (role="contentinfo"): Copyright, legal links.

Always include a Skip Link: a visually hidden link at the very top of the page that becomes visible on focus, allowing keyboard users to jump straight to <main id="main"> without tabbing through 30 header links.
