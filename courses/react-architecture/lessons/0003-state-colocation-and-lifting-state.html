Lesson 03 · State & The Render Cycle

State co-location and lifting state

Where should state live? Master Kent C. Dodds' state co-location principle: keep state as close as possible to where it is used, and lift state only when shared.

Time ~10 min Win Co-locate state at the lowest common ancestor in the component tree Mission link Prevents unnecessary top-level re-renders and bloated global state stores

1The global state mistake

A common beginner mistake is putting all state into a global store (Redux, Context, or top-level App). When a user types a single character into a search input, the entire App and its 50 child components re-render!

The golden rule of state architecture is State Co-location: Keep state as close as possible to the component that actually renders or consumes it. If only a modal dialog cares whether it is open, that state belongs inside the modal, not in global state. If two siblings need to share data, lift state up only to their lowest common ancestor.

Key idea Keep state as local as possible; lift state only to the lowest common ancestor that shares it.
