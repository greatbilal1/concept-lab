Lesson 06 · Memory

References, not copies

A name does not hold a value. It holds a reference — a pointer to where the value lives. Once you see names as arrows rather than boxes, every sharing surprise in the previous lessons becomes predictable instead of mysterious.

Time ~11 min Win Draw the arrows for any assignment Mission link Why two names can share one value

1A name is an arrow

When you write a = [1, 2, 3], the list is created somewhere in memory and the name a is bound to a reference to it. The name does not contain the list; it points at it. 

a = [1, 2, 3]   # a ──→ [1, 2, 3]
b = a           # b ──→ [1, 2, 3]   (same list!)
c = [1, 2, 3]   # c ──→ [1, 2, 3]   (a different list)

Two names can point at the same value, and two values can look identical while being separate. The arrows are the truth; the printed contents are not.

2Aliasing: two names, one value

When two names refer to the same value, we say they are aliases. Aliasing is not an error — it is often exactly what you want. But it means a change made through one name is a change to the shared value, visible through the other. 

a = [1, 2, 3]
b = a
b[0] = 99
print(a)     # [99, 2, 3] — a sees the change
Key idea Assignment copies the reference, not the value. After b = a there is still only one list — two arrows pointing at it.

3Rebinding moves one arrow

Rebinding a name does not affect the value or the other names pointing at it. It simply moves that one arrow somewhere else. 

a = [1, 2, 3]
b = a
a = [9, 9, 9]    # a now points at a NEW list
print(b)         # [1, 2, 3] — b still points at the old one

Compare this with the previous section. Mutating the shared value was visible through both names; rebinding one name was visible through neither. Mutation changes the value; rebinding changes the arrow.

4Why this matters

Almost every "why did my other variable change?" bug is aliasing. A function receives a list, appends to it, and the caller's list changes too — because the function received a reference to the same list, not a copy of it. Knowing the arrow model lets you predict this before it happens.
