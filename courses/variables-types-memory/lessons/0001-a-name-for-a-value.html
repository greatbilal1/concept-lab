Lesson 01 · Names & values

A name for a value

You have written x = 5 a hundred times. This lesson is about what that line actually does — and the answer is not "put 5 into x". It is subtler, and getting it right now saves you from a whole family of bugs later.

Time ~10 min Win Explain what a variable is not Mission link The idea every later lesson builds on

1A box, or a label?

Most introductions say a variable is "a box that holds a value". It is a friendly picture, and it is wrong in a way that will bite you. A box implies the value lives inside the name, and that copying the name copies the value. Neither is true.

A better picture: a variable is a label — a sticky note with a name on it, stuck onto a value that lives somewhere in memory. The name and the value are two separate things. The name just points.

Key idea A variable is a name that refers to a value. The value is the data; the name is how you reach it. Keep those two ideas apart and everything else in this course falls into place.

2Names are for humans

The computer does not need your names. It works with memory addresses — raw numbers. Names exist so that you can write total_price instead of 0x7ffd4a2b, and so the next person reading your code can tell what you meant.

That is the whole point of a name: it is a human-readable handle on a machine location. When you choose a name, you are writing a tiny piece of documentation.

3One name, one value at a time

A name refers to exactly one value at any moment. But the value it refers to can change — that is what makes it a variable rather than a constant. When you write a new assignment, the label moves to a new value. 

score = 10      # the label "score" points at 10
score = 25      # the label now points at 25
print(score)    # 25

Notice what did not happen: the number 10 was not changed into 25. The label simply stopped pointing at 10 and started pointing at 25. The old value is still sitting there, unchanged, until nothing refers to it any more.

4What a variable is not

Three things people assume, all false:

  • It is not the value. score is not 25; it refers to 25.
  • It is not a box. Nothing is stored "inside" the name.
  • It is not permanent. The name can point somewhere else at any time.
Common mistake Saying "the variable contains the value". It is a small slip of language that quietly installs the box model — and the box model is exactly what makes the next lesson's surprises feel like magic instead of logic.

✓ Your win for today

You can now say precisely what a variable is — a name that refers to a value — and name the three things it is not. That distinction is the foundation for everything that follows: assignment, types, mutability and memory all make sense only once the name and the value are separate in your head.

6Do this next

  1. Write down, in one sentence, the difference between a name and a value. If your sentence uses the word "contains", rewrite it.
  2. In a Python shell, run a = 5, then b = a, then a = 9. Print both. Explain why b is still 5.
  3. Find one variable name in code you have written that does not describe its value. Rename it to something a stranger could read.
