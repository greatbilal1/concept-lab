Lesson 05 · Types

Mutable and immutable

Some values can be changed in place; others cannot. This single distinction explains why lists surprise beginners and numbers never do — and it is the hinge on which the whole memory half of this course turns.

Time ~10 min Win Predict when a change is shared Mission link Why one list edit affects two names

1Two kinds of value

A value is immutable if it can never be changed after it is created — numbers, strings, and booleans are all immutable. A value is mutable if it can be changed in place — lists, dictionaries, and sets are mutable. 

n = 5
n = n + 1        # rebinds n to a new value; the 5 is untouched

items = [1, 2, 3]
items.append(4)  # changes the list itself, in place
print(items)     # [1, 2, 3, 4]

Notice the difference in wording. n = n + 1 rebinds the name to a new value. items.append(4) mutates the existing value. Those are two genuinely different operations.

2Mutation is visible through every name

Here is the payoff of the label model. If two names refer to the same mutable value, changing it through one name is visible through the other — because there is only one value. 

a = [1, 2, 3]
b = a            # b refers to the SAME list
b.append(4)
print(a)         # [1, 2, 3, 4] — a changed too!

This is not a bug and not a copy failure. b = a bound b to the same list, so there was never a second list to keep separate. The next lesson makes this mechanism precise.

3Why immutability is a gift

Immutable values are safe to share. If a number or string is passed around, no one can change it out from under anyone else, so you never have to worry about who else holds a reference. That is why strings are immutable: it makes them safe to use as dictionary keys and to share freely.

4Identity: is it the same value?

When you need to know whether two names refer to the same value rather than merely equal ones, you use is. It compares identity, not content. == asks "do these look the same?"; is asks "are these the very same thing?". 

a = [1, 2]
b = [1, 2]
a == b     # True  — same contents
a is b     # False — two different lists

c = a
a is c     # True  — the same list, two names
Key idea == compares values; is compares identity. For mutable values the two questions give different answers, and the difference is exactly what causes shared-change surprises.
