Lesson 02 · Names & values

Assignment is a binding

The equals sign is the most misread symbol in programming. It does not mean "is equal to" — it means "make this name refer to this value". Once you read it that way, a lot of confusing code becomes obvious.

1The equals sign is a verb

In maths, = is a statement of fact: x = 5 means "x is equal to 5". In programming it is an action: "bind the name x to the value 5". It is a command, not a claim.

That is why x = x + 1 is perfectly sensible in code and nonsense in maths. Read as a command it says: "take the value x currently refers to, add one, and bind x to the result."

Key idea name = value is an instruction to bind. The right-hand side is worked out first, then the name is pointed at the result.

2Right side first, always

Assignment has an order. The expression on the right is fully evaluated before anything happens to the name on the left. So in total = price * qty, the multiplication happens first, producing a value, and only then is total bound to it. 

price = 4
qty = 3
total = price * qty   # 12 is computed, then bound to total
print(total)          # 12

3Binding is not copying

Here is where the label model pays off. When you write b = a, you are not copying the value out of a into b. You are binding b to the same value that a refers to. Two names, one value. 

a = 5
b = a        # b now refers to the same 5
a = 9        # a moves to 9; b is untouched
print(a, b)  # 9 5

For numbers this looks like copying, because numbers cannot be changed. But the mechanism is binding, and for values that can change, the difference is dramatic — that is Lesson 06.

4The classic swap

A famous beginner puzzle: swap two variables. The naive attempt fails, and the reason is binding. 

a = 1
b = 2
a = b     # a now refers to 2 — the 1 is lost
b = a     # b refers to 2 as well
print(a, b)   # 2 2  — not swapped!

The first line overwrites a's binding before its old value is saved anywhere. The fix is to hold the old value in a third name first — or, in Python, to use the tuple trick a, b = b, a, which evaluates the whole right side before rebinding either name.
