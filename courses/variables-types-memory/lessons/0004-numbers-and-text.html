Lesson 04 · Types

Numbers and text

Two types carry almost all the data you will ever handle: numbers and text. Each has a quirk that will surprise you — integers are exact, floats are not, and strings cannot be changed at all. Knowing the quirks is most of the battle.

Time ~10 min Win Explain why 0.1 + 0.2 is not 0.3 Mission link The two types you use every day

1Integers are exact

An integer is a whole number — no fractional part. Integers are stored exactly, so arithmetic on them is exact. 2 + 3 is 5, always, with no rounding anywhere. 

7 + 3        # 10
10 // 3      # 3   — integer division, discards the remainder
10 % 3       # 1   — the remainder
2 ** 10      # 1024

Python integers can also grow as large as memory allows, so there is no "overflow" to worry about at this level. Exactness is the defining property.

2Floats are approximate

A float is a number with a fractional part. It is stored in binary, in a fixed number of bits, which means most decimal fractions cannot be represented exactly. The famous consequence: 

0.1 + 0.2        # 0.30000000000000004
0.1 + 0.2 == 0.3 # False

This is not a Python bug. It is the same in every language, because 0.1 in binary is a repeating fraction — like 1/3 in decimal — and it has to be cut off somewhere. The tiny error is called rounding error.

Common mistake Comparing floats with ==. Because of rounding error, two floats that "should" be equal often are not. Compare with a tolerance instead, or keep money in integers (cents) rather than floats.

3Strings are immutable

A string is a sequence of characters — text. Its defining property is that it is immutable: once created, it can never be changed. Every "change" actually builds a brand-new string. 

s = "hello"
s.upper()        # "HELLO" — a new string
print(s)         # "hello" — the original is untouched
s[0] = "H"       # TypeError — strings cannot be changed in place

This matters because it means strings are safe to share. If two names refer to the same string, neither can change it out from under the other. That safety is the whole reason immutability exists — and it is the subject of the next lesson.

4Booleans: the third small type

A boolean is a value that is either True or False. You rarely write one directly; you get one from a comparison. Booleans are what conditions are made of, so they matter even in a lesson about numbers and text. 

5 > 3          # True
"a" == "b"     # False
bool(0)        # False — zero is falsy
bool("hi")     # True  — non-empty text is truthy

✓ Your win for today

You can now explain why integers are exact and floats are not, why 0.1 + 0.2 is not 0.3, and why strings can never be changed in place. Those three facts cover the vast majority of real-world type surprises — and the immutability of strings sets up the memory lessons that follow.

  2. Try to change a string in place, such as s[0] = "H". Read the error and explain what it tells you about strings.
  3. Store a price of 19.99 as cents (1999) instead of a float, and add it three times. Compare the exactness with the float version.
