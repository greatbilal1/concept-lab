Naming for humans

Names are for people, not for the computer. The machine only needs a reference; you need a story. This final lesson turns everything you have learned about names and values into a habit you can use in every program you write.

Time ~10 min Win Name things so code reads itself Mission link Why good names prevent bugs

1Names carry meaning

A name is a label you attach to a value so that you can remember what the value is for. total_price tells a story; x does not. The computer is indifferent — but the next person reading the code is not, and that person is usually future you. 

# hard to read
a = 19.99
b = 3
c = a * b

# reads itself
unit_price = 19.99
quantity = 3
total_price = unit_price * quantity

2Conventions you should follow

Python has a widely followed naming convention, described in PEP 8. Names use lowercase words joined by underscores, constants use all capitals, and names that start with an underscore signal "internal". Following the convention means your code looks like everyone else's. 

user_name = "Ada"        # variable — lowercase_with_underscores
MAX_RETRIES = 3          # constant — ALL_CAPS
_internal_cache = {}     # leading underscore — internal use

3Constants and shadowing

A constant is a name you promise not to rebind — written in capitals to signal that promise. Shadowing is when a name in an inner scope hides a name in an outer one. Both are about names, and both can cause confusion if used carelessly. 

MAX = 100

def check(MAX):        # this MAX shadows the outer one
    return MAX < 50

check(10)              # True — the inner MAX is used
Common mistake Shadowing a built-in name, such as list or sum. It works, but it hides the built-in for the rest of the scope and confuses readers. Choose a different name.

4Names are the cheapest documentation

Every good name is a comment you did not have to write. Because a name is bound to a value, a well-chosen name tells the reader what the value means without them having to trace where it came from. This is why naming is the first skill to practise and the last to master.

✓ Your win for today

You can now name values so that code reads itself, follow Python's naming conventions, and recognise constants and shadowing. More importantly, you can explain the whole course in one sentence: a name is a label bound to a value, and everything else follows from that.

6Do this next

  1. Take a short program you wrote earlier and rename every single-letter name to something meaningful. Notice how much easier it is to read.
  2. Write a constant in capitals and use it in two places. Explain why the capitals are a promise rather than a rule.
  3. Write a function that shadows an outer name, then rename it to avoid the shadowing. Explain what confusion the rename removed.
