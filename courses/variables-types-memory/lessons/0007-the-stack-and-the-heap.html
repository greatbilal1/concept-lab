Lesson 07 · Memory

The stack and the heap

Memory is not one undifferentiated pool. It is organised into two regions with very different rules: the stack, which is fast and automatic, and the heap, which is flexible and managed. Knowing which is which explains lifetimes.

Time ~11 min Win Say where a value lives Mission link Why local names vanish

1Two regions of memory

The stack is a region of memory organised like a stack of plates: things are pushed on and popped off in order. It holds the frames of function calls — the local names and the references they hold. It is fast and its lifetime is automatic.

The heap is a large, unordered region where objects live. When you create a list or a string, the object itself is placed on the heap, and a reference to it is stored in a stack frame. The heap is flexible but needs managing.

2A frame is a call's workspace

Every time a function is called, a new frame is pushed onto the stack. The frame holds that call's local names. When the function returns, its frame is popped, and its local names disappear with it. 

def double(n):
    result = n * 2    # n and result live in this frame
    return result

double(5)             # frame pushed, then popped
print(result)         # NameError — result is gone

This is why local names cannot be seen from outside. They were never global; they lived in a frame that no longer exists.

3References bridge the two

The stack and the heap are connected by references. A frame on the stack holds names; each name holds a reference to an object on the heap. The object outlives the frame if something else still refers to it. 

def make():
    items = [1, 2, 3]   # list lives on the heap
    return items        # reference escapes the frame

data = make()           # data now refers to the list
print(data)             # [1, 2, 3] — the list survived
Key idea The stack holds frames and references; the heap holds the objects themselves. A value survives a function call if a reference to it escapes.

4Why the split exists

The split is a trade-off. Stack memory is fast to allocate and free because it is just a pointer that moves up and down, but it is limited in size and its lifetime is tied to the call. Heap memory is flexible — objects can be any size and live as long as needed — but allocating and reclaiming it costs more.

You can now say where any value lives — a frame on the stack or an object on the heap — and explain why local names vanish when a function returns. That sets up the final memory lesson, where we ask what happens to heap objects nobody refers to any more.
