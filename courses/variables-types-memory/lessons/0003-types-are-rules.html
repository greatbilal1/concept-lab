Lesson 03 · Types

Types are rules

A type is not a label the computer sticks on a value for its own convenience. It is a set of rules about what you are allowed to do. Understanding types as rules explains every "unsupported operand" error you will ever see.

Time ~10 min Win Predict which operations are legal Mission link Why "2" + 2 fails

1A type is a set of allowed moves

Every value has a type, and the type decides which operations make sense. You can add two numbers. You can join two pieces of text. You cannot add a number to a piece of text — not because the computer is being difficult, but because "add" has no agreed meaning across those two kinds of thing. 

2 + 3          # 5      — numbers add
"ab" + "cd"    # "abcd" — strings join
2 + "3"        # TypeError — no shared meaning
Key idea A type is a contract: it lists the operations that are valid for a value. A type error means you asked for an operation the contract does not include.

2Types travel with values, not names

This is the part that surprises people coming from typed languages. In Python, the value has a type; the name does not. A name can refer to a number now and a string a moment later, and nothing complains. 

x = 5        # x refers to an int
x = "five"   # now x refers to a str — perfectly legal
print(type(x))   # <class 'str'>

The name is just a label. The type belongs to whatever the label currently points at. This is called dynamic typing, and it is why the same name can hold different kinds of value at different times.

3Asking a value its type

You are never guessing. type(value) tells you what kind of thing you are holding, and isinstance(value, T) asks whether it is a particular kind. Both are how you check before you act. 

type(5)              # <class 'int'>
type("hi")           # <class 'str'>
isinstance(5, int)   # True
isinstance("hi", int)  # False

4Converting between types

When you need an operation that the current type does not allow, you convert. int("3") turns the text "3" into the number 3, and then addition works. Conversion is explicit on purpose: the language makes you say what you mean rather than guessing. 

int("3") + 2      # 5
str(3) + "2"      # "32"
int("three")      # ValueError — not a number at all
Common mistake Assuming int("3") and str(3) are the same kind of conversion. They are opposites: one parses text into a number, the other formats a number as text. Mixing up the direction is a frequent bug.

✓ Your win for today

You can now explain a type as a set of rules rather than a label, predict which operations are legal, and convert deliberately when they are not. You also know that types belong to values, not names — which is exactly why the next lesson can talk about numbers and text as different kinds of thing.
