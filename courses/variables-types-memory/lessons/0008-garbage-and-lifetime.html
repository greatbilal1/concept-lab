Lesson 08 · Memory

Garbage and lifetime

Heap objects do not live forever. When nothing refers to an object any more, it becomes garbage and is reclaimed. Understanding this explains both why Python feels effortless and how memory leaks still happen.

Time ~11 min Win Predict when an object dies Mission link Why you never free memory

1An object lives while it is reachable

An object on the heap stays alive as long as at least one reference points at it. The moment the last reference goes away, the object is unreachable — no name, no container, nothing can reach it. It is now garbage. 

a = [1, 2, 3]   # one reference
a = None        # the list is now unreachable
                # nothing can reach it — it is garbage

Notice that the list was not "deleted". It simply became unreachable, and the runtime is free to reclaim its memory.

2Reference counting

Python's main strategy is reference counting. Every object keeps a count of how many references point at it. When that count drops to zero, the object is reclaimed immediately. 

import sys
a = [1, 2, 3]
sys.getrefcount(a)   # more than 1 (the call itself adds one)
b = a                # count goes up
del b                # count goes down
Key idea An object is alive while its reference count is above zero. When the last reference disappears, the count hits zero and the memory is reclaimed.

3Garbage collection for cycles

Reference counting has one blind spot: cycles. If two objects refer to each other, each keeps the other's count above zero even when nothing outside can reach them. Python handles this with a garbage collector that periodically looks for unreachable cycles and reclaims them. 

a = {}
b = {}
a["other"] = b
b["other"] = a   # a cycle — counts never reach zero
del a, b         # the cycle is unreachable, but counts stay high
                 # the garbage collector finds and frees it

4Memory leaks in a managed language

If Python frees everything automatically, how do leaks happen? A leak is not lost memory — it is memory that is still reachable but no longer useful. A global list that you keep appending to, or a cache that never expires, holds references forever, so the objects can never be reclaimed.

Common mistake Believing "Python has a garbage collector, so I cannot leak memory". You can — by keeping references alive in globals, caches, or long-lived containers. The collector only frees what is unreachable.
