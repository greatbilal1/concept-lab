Executing the Tool and Formatting the Tool Result

Executing the requested function, capturing outputs, and feeding results back using the 'tool' message role.

1Core principles of Executing the Tool and Formatting the Tool Result

Once you parse the tool name and arguments, your application executes the real code. But how do you return the result to the model so it can formulate its final answer?

Key idea Executing the requested function, capturing outputs, and feeding results back using the 'tool' message role.

2The Tool Result Message Sequence

You append two sequential messages to the conversation array:

3String Serialization Requirement

  • 1. The Assistant's Tool Call Request: You must append the model's message (containing the `tool_calls` array) to the conversation history.
  • 2. The Tool Result Message: You append a message with role: "tool", the matching tool_call_id, and the serialized JSON content representing the function's output.
# Executing and Formatting Tool Results:
# Step 1: Execute real Python function:
result_data = execute_database_query(args["sku"])

# Step 2: Append Assistant request to history:
messages.append(message) # The model's own response object!

# Step 3: Append Tool result message to history:
messages.append({
    "role": "tool",
    "tool_call_id": tool_call.id, # MUST MATCH THE REQUEST ID!
    "content": json.dumps(result_data) # Serialized result payload
})

# Step 4: Call model again to synthesize final answer!
final_response = client.chat.completions.create(model="gpt-4o", messages=messages)

The Pairing Invariant: Every `tool` message in history must correspond to a preceding `tool_call_id` in an assistant message. If IDs are missing or mismatched, the API rejects the request.
