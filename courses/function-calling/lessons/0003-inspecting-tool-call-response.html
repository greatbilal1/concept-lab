Inspecting the Tool Call Response from the Model

Parsing tool call responses: finish_reason='tool_calls', extracting tool_call_id, and parsing JSON arguments.

Time ~10 min Win You know how to inspect and parse tool call responses from language models. Mission link Mastering inspecting the tool call response from the model across modern software engineering

1Core principles of Inspecting the Tool Call Response from the Model

When you pass tools to an API call, you must inspect the response object to determine what the model decided to do. Did it finish talking, or is it asking you to execute a tool?

Key idea Parsing tool call responses: finish_reason='tool_calls', extracting tool_call_id, and parsing JSON arguments.

2Tool Call Response Anatomy

When a model requests a tool, two things happen:

3Branching Execution Flow

  • 1. `finish_reason == 'tool_calls'`: This status indicates that generation paused because a tool call was requested.
  • 2. `message.tool_calls`: A list of tool call objects containing the unique id, function name, and serialized JSON arguments.
# Inspecting a Tool Call Response in Python:
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
    tools=tools
)
message = response.choices[0].message

if response.choices[0].finish_reason == "tool_calls":
    for tool_call in message.tool_calls:
        print(f"Tool ID:   {tool_call.id}")           # e.g. 'call_91823ab'
        print(f"Function:  {tool_call.function.name}") # e.g. 'get_product_inventory'
        # Parse the JSON arguments string:
        args = json.loads(tool_call.function.arguments)
        print(f"Arguments: {args}")                   # e.g. {'sku': 'PROD-8492'}

The Tool Call ID: Note the unique `tool_call_id`! You must save this ID because you will need to attach it to the tool execution result when sending it back to the model.
