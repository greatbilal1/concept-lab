Lesson 01 · The Request-Response Cycle

The request-response cycle

At the heart of the web is a simple, repeating conversation: the client asks a question, and the server gives an answer. Explore the stateless protocol loop.

Time ~10 min Win Articulate the client-initiated, stateless request-response lifecycle Mission link The fundamental interaction pattern of all web architecture

1A conversation over TCP

Every time you load a website or call a REST API, your computer acts as an HTTP client. It opens a TCP connection to the server, sends an explicit HTTP request message, waits for the server to reply with an HTTP response message, and then closes or reuses the connection.

HTTP is fundamentally stateless: the server does not remember who you are from the previous request unless you explicitly attach an identification token or cookie to the message.

Key idea HTTP is a stateless conversation: every request is evaluated independently as an isolated transaction.
