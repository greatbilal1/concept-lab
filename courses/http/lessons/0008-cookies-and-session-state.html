Lesson 08 · State, Cookies & Caching

Cookies and session state

How does a stateless protocol support login sessions and shopping carts? Learn how Set-Cookie, HttpOnly, and SameSite manage state and defend against attacks.

Time ~10 min Win Configure secure session cookies with HttpOnly, Secure, and SameSite attributes Mission link Prevents critical web vulnerabilities like XSS credential theft and CSRF attacks

1Simulating state over a stateless protocol

Because HTTP preserves no memory between requests, the web simulates continuity using Cookies. When you log in, the server generates a random session token and returns it in a Set-Cookie response header.

The browser automatically stores this cookie and attaches it as a Cookie header to every subsequent request sent to that domain. The server inspects the incoming token to identify the authenticated user.

Key idea Cookies are client-stored tokens sent automatically on every request to simulate continuous sessions.
