Lesson 04 · Sorting

Selection and insertion sort

Last lesson you learned that binary search only works on a sorted list. That raised an obvious question: where does the sorted list come from? Today you write the two simplest answers — selection sort and insertion sort — and see that sorting is really precomputation you do once so that every later search is cheap.

Time ~12 min Win Hand-trace both sorts on a short list and say which one wins on nearly-sorted data Mission link Sorting is the setup step that turns a slow search into a fast one

1Why sort at all

Sorting is not the goal — it is the preparation. A sorted list is a list you have paid for once and can then search, merge, and compare cheaply forever after. This is the first real trade-off in the course: spend time up front, save time on every question you ask later.

Both sorts today follow the same shape. They keep a growing sorted region at the front of the list and shrink an unsorted region at the back. They differ only in how they move the next item into place.

Key idea Sorting is precomputation. You sort once so that searching, merging, and comparing become fast for every question that follows.

2Selection sort: pick the smallest, swap it forward

Selection sort scans the whole unsorted region, finds the smallest item, and swaps it into the next slot of the sorted region. Then it repeats on what is left. After k passes, the first k items are final and never move again.

The cost is easy to see: the first pass looks at n items, the next at n−1, then n−2, and so on. That is roughly n²/2 comparisons no matter what the input looks like — even a list that is already sorted gets the full treatment.

3Insertion sort: slide the next card into place

Insertion sort works the way most people sort a hand of playing cards. You take the next card and slide it left past every card that is bigger than it, stopping the moment it fits. The sorted region grows by one each time.

Here is the payoff. If the list is already nearly sorted, each card barely moves, so the work per item is tiny. Insertion sort is adaptive: its cost depends on how disordered the input already is. Selection sort is not — it always pays the full price.

4Two properties worth naming

Both sorts are in-place: they rearrange the list using only a constant amount of extra memory, so they never need a second copy of the data. That matters when the list is large or memory is tight.

Insertion sort is also stable: items that compare equal keep their original relative order, because it only slides an item past strictly larger ones. Selection sort is not stable, because a long-distance swap can jump an equal item over its twin. Stability matters whenever you sort records by one field after already sorting them by another.

✓ Your win for today You can hand-trace selection sort and insertion sort on a short list, and you can explain why insertion sort is the better choice when the data is already nearly sorted.

5Do this next

  1. Sort [5, 2, 9, 1, 7] by hand with selection sort. Write down the list after each pass.
  2. Sort the same list with insertion sort. Count how many times an item actually moves.
  3. Predict which sort wins on [1, 2, 3, 5, 4], then check your reasoning against the trace above.
