Lesson 02 · Searching

Linear search

The simplest search there is: look at every item, one at a time, until you find what you want. It is slow, it is boring, and it is the baseline every other search in this course is measured against.

Time ~10 min Win Count exactly how many comparisons a search costs Mission link The baseline that makes fast search meaningful

1Look at everything, in order

You have a list and a target. You do not know where the target is — or whether it is there at all. The only tool you have is "look at one item and compare it". So you start at the beginning and work forward.

That is linear search. It is the algorithm you already use when you scan a shelf for a particular book, or read a list of names looking for your own. It needs no assumptions about the data: the list can be sorted, unsorted, or complete nonsense. It just has to be a list.

Key idea Linear search is correct on any list. That is its whole selling point — and the reason it is the fallback when you cannot sort or cannot afford to.

2The loop and the two ways out

The algorithm has exactly two ways to finish, and forgetting either one is the classic bug:

If you only handle "found it", your program runs off the end of the list and crashes. If you only handle "ran out", you never report success. Both exits are part of the algorithm, not an afterthought.

3Count the comparisons

Here is the habit that matters more than the code: count the work. Trace a search for 9 in the list [4, 8, 15, 16, 23, 42] and watch the comparison count climb.

Six items, six comparisons, and the target was not even there. On a list of $n$ items, the worst case is $n$ comparisons — and the average case is about $n/2$. That is what "linear" means: the cost grows in step with the list.

Watch out Linear search is fine for ten items and painful for ten million. The lesson is not "never use it" — it is "know what it costs before you use it".

5Do this next

  1. Write linear search in pseudocode. Return the index of the target, or -1 if it is not there. Handle the empty list.
  2. Trace it on [7, 7, 7] looking for 7. Which index does it return? Now decide: should it return the first match or the last?
  3. Count the comparisons for a search that succeeds on the first item, and for one that fails on a list of 100. Write both numbers down.
Primary source Read _Introduction to Algorithms_ by Cormen, Leiserson, Rivest & Stein, Chapter 2, Section 2.1 ("Insertion sort") for the loop-invariant style of reasoning, then Section 2.2 for how the book counts the work an algorithm does.
