Recursion in disguise: the call stack

Last lesson you traced factorial(4) and noticed something odd: the calls piled up before any multiplication happened. Something has to remember all those paused calls and their half-finished work. That something is the call stack, and once you see it, recursion stops feeling like magic.

Time ~12 min Win Explain what the call stack holds and why deep recursion can overflow it Mission link The call stack is the machine's bookkeeping for every recursive algorithm

1Where do the paused calls live?

When factorial(4) calls factorial(3), the outer call is not finished — it is waiting for a result to multiply. The machine cannot throw that work away, so it parks it somewhere and comes back later.

That somewhere is the call stack. Every time a function is called, a new record is pushed on top. Every time a function returns, its record is popped off. The stack is last-in, first-out: the most recent call is always the one that finishes first.

Key idea The call stack is the machine's memory of unfinished work. Each call pushes a frame; each return pops one. Recursion is just the stack doing its normal job.

2Stack frames

Each record on the stack is called a stack frame. A frame holds the function's local variables, the arguments it was called with, and the place to resume once it returns. For factorial(3), the frame remembers that n is 3 and that it still owes a multiplication by 3.

This is why recursion costs memory. Ten nested calls mean ten frames alive at once. A loop doing the same work keeps only one frame, because it never needs to remember a paused call.

3Watch the stack grow and unwind

Follow the stack depth as factorial(4) runs. It grows to four frames on the way down, then unwinds one frame at a time on the way back up.

4Stack overflow and tail recursion

The stack has a fixed size. If recursion goes too deep — say a million nested calls — the frames run out of room and the program crashes with a stack overflow. This is exactly what happens when a base case is missing, and it is also why recursion depth matters even when the base case is correct.

One special case avoids the growth. If the recursive call is the very last thing the function does, with no work left to combine afterwards, the frame is no longer needed and can be replaced instead of pushed. That pattern is called tail recursion, and some languages optimise it into a loop.

✓ Your win for today You can describe what a stack frame holds, trace the stack growing and unwinding, and explain why deep recursion can overflow it.

5Do this next

  1. Draw the call stack for factorial(3) at its deepest point, labelling each frame.
  2. Explain why a loop that sums a list uses less memory than a recursive sum.
  3. Rewrite a recursive countdown so the recursive call is the last step, making it tail recursive.
