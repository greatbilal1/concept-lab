1Habits

What an algorithm is
An algorithm is a finite, unambiguous sequence of steps
that turns an input into an output.

Good algorithms are:
  - correct on every valid input
  - finite (they always stop)
  - precise enough for a machine to follow

Pseudocode: plain-language steps, no syntax rules.
Decomposition: break a problem into smaller problems.
Invariant: a fact that stays true at every step.
Trace: run the steps by hand on a small input.
Edge case: the smallest, largest, or empty input.

See Lesson 01 — What an algorithm really is.

2Searching

Linear search — O(n)
for each item in the list:
    if item == target: return its index
return not found

Works on any list, sorted or not.
Worst case: scan every item.
A sentinel is a value placed at the end so the
loop needs no separate bounds check.

See Lesson 02 — Linear search.

Binary search — O(log n)
low = 0, high = n - 1
while low <= high:
    mid = (low + high) / 2
    if list[mid] == target: return mid
    if list[mid] < target: low = mid + 1
    else:                  high = mid - 1
return not found

Precondition: the list MUST be sorted.
Each step halves the search space.
1,000,000 items -> about 20 steps.
On an unsorted list it returns a wrong answer.

See Lesson 03 — Binary search.

3Sorting

Selection sort — O(n²)
for i from 0 to n - 1:
    find the smallest item in list[i..n-1]
    swap it into position i

Always scans the whole unsorted region.
Cost is the same even if the list is sorted.
In-place, but NOT stable.
Insertion sort — O(n²), fast when nearly sorted
for i from 1 to n - 1:
    take list[i]
    slide it left past every larger item
    drop it where it fits

Adaptive: nearly sorted input is almost free.
In-place AND stable.

See Lesson 04 — Selection and insertion sort.

Merge sort — O(n log n)
mergeSort(list):
    if list has 0 or 1 item: return list   # base case
    split list into left and right halves
    left  = mergeSort(left)
    right = mergeSort(right)
    return merge(left, right)

merge(a, b):
    while both lists have items:
        take the smaller front item
    append whatever remains

Divide and conquer: divide, conquer, combine.
Merging is linear, so each level costs n.
log n levels x n work = n log n.
Needs extra memory, so NOT in-place.
Stable if ties take from the left list first.

See Lesson 05 — Divide and conquer: merge sort.

4Recursion

The two required parts
def factorial(n):
    if n <= 1: return 1        # base case
    return n * factorial(n-1)  # recursive case

Base case: smallest input, answered directly.
Recursive case: call on a smaller input.
The recursive case must move toward the base case.
No base case -> infinite calls -> crash.

See Lesson 06 — Recursion: a function that calls itself.

The call stack
Each active call pushes a stack frame holding:
  - its arguments
  - its local variables
  - where to resume on return

Returning pops the top frame.
Order is last-in, first-out.
Too many nested frames -> stack overflow.
Tail recursion: the call is the last action,
so the frame can be replaced, not pushed.

See Lesson 07 — Recursion in disguise: the call stack.

5Putting it together

Complexity and trade-offs
Complexity: how work grows as input grows.
Big-O: the growth rate, ignoring constants.

  linear search   O(n)
  binary search   O(log n)
  selection sort  O(n²)
  insertion sort  O(n²), fast when nearly sorted
  merge sort      O(n log n)

Trade-off: sort once (n log n), then every
search costs log n instead of n.
Precomputation: pay up front to save later.

Recipe for a hard problem:
  1. decompose it into known pieces
  2. match each piece to a tool
  3. name the trade-off before coding
