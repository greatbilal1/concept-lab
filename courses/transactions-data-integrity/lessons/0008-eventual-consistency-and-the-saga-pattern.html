Eventual consistency and the Saga pattern

How do giants like Uber, Netflix, and Amazon handle distributed transactions without 2PC? Master eventual consistency, Sagas, and compensating transactions.

Time ~10 min Win Architect distributed workflows using the Saga pattern and compensating transactions Mission link The industry standard pattern for distributed business workflows across microservices

1Trading ACID for BASE

Because distributed locks (2PC) kill throughput, large distributed systems embrace Eventual Consistency (BASE: Basically Available, Soft state, Eventual consistency). Instead of locking all databases simultaneously, services commit their changes locally and immediately.

Distributed transactions are coordinated using the Saga Pattern: a sequence of independent local transactions. If step 3 fails (e.g. payment rejected), the saga executes Compensating Transactions backwards (releasing inventory, canceling shipping) to restore consistency.

Key idea A Saga coordinates distributed workflows using local transactions and compensating rollbacks.
