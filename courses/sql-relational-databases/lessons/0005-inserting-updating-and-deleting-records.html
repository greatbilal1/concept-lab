Lesson 05 · Data Manipulation & Constraints

Inserting, updating, and deleting records

Mutating data safely is a craft. Master INSERT, the disaster of UPDATE without WHERE, soft deletes versus hard deletes, and the RETURNING clause.

Time ~10 min Win Execute data mutations safely using parameterized DML statements and RETURNING clauses Mission link The core statements for modifying persistent data in relational databases

1The three mutation verbs: INSERT, UPDATE, DELETE

Data Manipulation Language (DML) provides three verbs to alter rows: INSERT INTO adds new rows, UPDATE ... SET modifies existing rows, and DELETE FROM removes rows.

A terrifying danger: If you run UPDATE or DELETE without a WHERE clause, you update or delete EVERY SINGLE ROW in the entire table! Always test your WHERE clause with a SELECT query first before executing destructive mutations.

Key idea An UPDATE or DELETE statement without a WHERE clause mutates every row in the entire table.

2The RETURNING clause superpower

Modern databases (PostgreSQL, SQLite) let you return the newly generated ID or mutated values in one round-trip.

3Tracing an atomic transaction mutation

Trace how wrapping an UPDATE inside a transaction protects against accidental data loss.

4Practice

Test your memory of DML mutation statements.

✓ Your win for today

You can perform data mutations safely with parameterized SQL and verify outcomes using RETURNING clauses.

5Do this next

  1. Insert a row and retrieve its generated primary key using INSERT ... RETURNING id.
  2. Perform a multi-row INSERT with a single SQL statement.
  3. Implement a soft-delete column (deleted_at TIMESTAMP) instead of destructive DELETE.
