Lesson 02 · The Relational Model & Tables

Tables, data types, and constraints

Garbage in, garbage out. Learn how strict column datatypes and database constraints (PRIMARY KEY, NOT NULL, UNIQUE, CHECK) protect data integrity at the lowest level.

Time ~10 min Win Design robust relational tables using appropriate data types and column constraints Mission link Prevents corrupted, inconsistent data from entering database storage

1Guarding data at the gate

Application validation code can have bugs, but database constraints never lie. Constraints are rules enforced by the database engine on every single write operation: NOT NULL forbids missing values, UNIQUE prevents duplicates, and CHECK enforces domain limits (e.g. price >= 0).

Every table should have a Primary Key: a non-null, unique column (such as an auto-incrementing integer or UUID) that permanently identifies each row for references.

Key idea Database constraints enforce business rules at the storage engine level, making bad data impossible to store.
