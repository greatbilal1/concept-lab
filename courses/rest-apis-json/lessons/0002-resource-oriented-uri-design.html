Lesson 02 · REST Architecture & Resources

Resource-oriented URI design

URIs are nouns; verbs are methods. Learn how to structure clean, predictable REST endpoints for collections, individual items, and nested sub-resources.

Time ~10 min Win Design clean, noun-based RESTful URI hierarchies for complex domain models Mission link Eliminates messy URL endpoints and establishes intuitive API conventions

1Nouns, pluralization, and identifiers

A well-designed REST API reads like an organized library catalogue. Endpoints identify resources (nouns), never operations (verbs). By industry convention, collection URIs use lowercase plural nouns: /users, /orders, /articles.

Individual items are accessed by appending their unique identifier: /users/42. Nested sub-resources express ownership: /users/42/orders clearly identifies the orders belonging to user 42.

Key idea Use plural nouns for collections, identifiers for items, and nest only when strict ownership exists.

2The standard resource matrix

Combine plural noun endpoints with the five standard HTTP verbs to cover full CRUD operations.

3Tracing nested sub-resource limits

Avoid nesting deeper than two levels; flatten deep relationships to keep URIs maintainable.

4Practice

Test your memory of URI design conventions.

✓ Your win for today

You can design intuitive, scalable URI hierarchies that require minimal documentation for developers to understand.

5Do this next

  1. Take a messy RPC-style API and refactor it into clean noun-based REST endpoints.
  2. Flatten a URI nested deeper than two levels into a top-level resource endpoint.
  3. Verify that your collection endpoints use plural nouns consistently.
