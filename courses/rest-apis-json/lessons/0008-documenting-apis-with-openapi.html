Documenting APIs with OpenAPI

If it isn't documented, it doesn't exist. Learn how to write machine-readable OpenAPI 3 specifications and generate interactive Swagger documentation.

Time ~10 min Win Author OpenAPI 3 specifications that generate documentation, client SDKs, and mock servers Mission link The industry standard for API contracts and developer experience

1API contracts as single source of truth

Word documents and wiki pages are terrible places to document APIs: they get out of date the day after they are written. The industry standard is OpenAPI Specification (OAS) (formerly Swagger).

An OpenAPI document is a structured YAML or JSON file defining every path, operation, parameter, request body, and response schema. From this single source of truth, tools automatically generate interactive documentation, client SDKs, and mock test servers.

Key idea OpenAPI specifications serve as executable contracts for documentation, testing, and SDK generation.
