Lesson 05 · API Design Patterns & Errors

Error handling and Problem Details

Stop inventing custom error JSON shapes. Master RFC 7807 / 9457 Problem Details for HTTP APIs to deliver consistent, machine-readable error responses.

Time ~10 min Win Implement standardized RFC 9457 Problem Details error responses across APIs Mission link Provides predictable error contracts that automated clients can parse reliably

1The problem with ad-hoc error formats

In most poorly designed APIs, error responses are chaotic: one endpoint returns {"error": "bad"}, another returns {"message": "failed"}, and another returns plain HTML error pages.

To fix this, the IETF standardized RFC 7807 (updated by RFC 9457): Problem Details for HTTP APIs. It specifies the application/problem+json media type with standard fields: type, title, status, detail, and instance.

Key idea Standardize API errors using RFC 9457 Problem Details so clients parse errors uniformly.
