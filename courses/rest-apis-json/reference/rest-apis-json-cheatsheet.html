1Resource URI Patterns

Standard collection & item endpoints
GET    /api/v1/articles          # List articles (filterable)
POST   /api/v1/articles          # Create new article
GET    /api/v1/articles/42       # Retrieve single article
PATCH  /api/v1/articles/42       # Partial update article
DELETE /api/v1/articles/42       # Remove article
GET    /api/v1/articles/42/comments # Sub-resource collection

See Lesson 02 — Resource-oriented URI design.

2Standard JSON Error Envelope

Consistent error responses
HTTP/1.1 422 Unprocessable Entity
Content-Type: application/problem+json

{
  "type": "https://api.example.com/errors/validation",
  "title": "Invalid Input Data",
  "status": 422,
  "detail": "Email address is already registered.",
  "instance": "/users/signup"
}

See Lesson 05 — Error handling and Problem Details.

3Pagination Patterns

Offset versus cursor query parameters
// Offset pagination
GET /items?offset=20&limit=10

// Cursor-based pagination (scale-friendly)
GET /items?cursor=eyJpZCI6NDJ9&limit=10

Response Envelope:
{
  "data": [...],
  "pagination": { "next_cursor": "eyJpZCI6NTJ9", "has_more": true }
}

See Lesson 06 — Pagination, filtering, and sorting.

4API Versioning

Evolution strategies
// 1. URI path versioning (most popular)
https://api.example.com/v1/users

// 2. Custom header versioning
X-API-Version: 2026-05-01

// 3. Accept header content negotiation
Accept: application/vnd.example.v2+json

See Lesson 07 — API versioning strategies.
