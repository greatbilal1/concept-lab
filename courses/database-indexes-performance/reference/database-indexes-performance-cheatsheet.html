1Index Creation Syntax

B-Tree, Unique, and Partial
-- Standard B-Tree index
CREATE INDEX idx_users_email ON users(email);

-- Composite index (Order Matters!)
CREATE INDEX idx_orders_user_status ON orders(user_id, status);

-- Partial index (saves disk & memory)
CREATE INDEX idx_unpaid_invoices ON invoices(user_id) 
WHERE status = 'unpaid';

See Lesson 02 — Anatomy of a B-tree index.

2Reading EXPLAIN ANALYZE

Diagnostic execution plan
EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM users WHERE email = 'ada@example.com';

-- Key Plan Nodes:
-- Seq Scan: Reading every page from disk (SLOW on large tables)
-- Index Scan: Traverses B-tree + fetches heap tuple (FAST)
-- Index Only Scan: All data in B-tree; zero heap fetches (FASTEST)

See Lesson 04 — Reading query plans with EXPLAIN ANALYZE.

3Leftmost Prefix Rule

Composite index matching
-- Index on: (A, B, C)
-- CAN use index:
WHERE A = 1
WHERE A = 1 AND B = 2
WHERE A = 1 AND B = 2 AND C = 3

-- CANNOT use index:
WHERE B = 2               # skips A
WHERE C = 3               # skips A and B

See Lesson 05 — Composite indexes and the leftmost prefix rule.

4Unused Index Audit

Finding index write overhead
SELECT indexrelname, idx_scan, idx_tup_read, idx_tup_fetch
FROM pg_stat_user_indexes
WHERE idx_scan = 0;  -- 0 scans = unused write penalty!

See Lesson 08 — The write penalty and index maintenance.
