Lesson 05 · Composite Indexes & Sizing

Composite indexes and the leftmost prefix rule

Index column order matters. Master multi-column composite indexes and the Leftmost Prefix Rule to serve multiple queries with a single index.

Time ~10 min Win Design composite multi-column indexes respecting the Leftmost Prefix rule Mission link Prevents creating redundant single-column indexes and optimizes multi-clause queries

1The phonebook analogy: column order is king

A telephone directory is an index sorted by (Last Name, First Name). You can quickly find everyone named 'Smith'. You can quickly find 'Smith, John'. But can you quickly find everyone whose first name is 'John' regardless of last name?

No! You would have to read every single page. A Composite Index on (A, B) is sorted by A first, and by B only within matching A values. This is the Leftmost Prefix Rule: an index on (A, B, C) can accelerate queries on (A), (A, B), and (A, B, C), but is completely useless for queries on (B) or (C) alone.

Key idea Composite indexes are sorted left-to-right; queries must filter on leading columns to use the index.
