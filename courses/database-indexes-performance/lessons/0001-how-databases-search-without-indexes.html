Lesson 01 · B-Trees & Scan Types

How databases search without indexes

Imagine finding a name in an unalphabetized phone book: you must read every page from cover to cover. Discover the Sequential Scan and why O(n) lookups collapse at scale.

Time ~10 min Win Explain why sequential scans cause query latency to scale linearly with table size Mission link The fundamental baseline that motivates index creation

1The Sequential Scan (Table Scan)

When a table has no index on a column, the database has only one way to answer WHERE email = 'ada@example.com': it must read every single disk page and evaluate every single row from the first to the last. This is a Sequential Scan (Seq Scan).

A sequential scan has a time complexity of O(n). On 1,000 rows, it takes 0.5 milliseconds. On 10,000,000 rows, the database must pull gigabytes of data from disk into RAM, taking 15 seconds and consuming 100% of a CPU core.

Key idea Without an index, the database must read every row in the table (Sequential Scan) in O(n) time.
